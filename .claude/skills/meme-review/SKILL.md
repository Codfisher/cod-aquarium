# 迷因審查（Meme Review）

`npm run task:process-meme` 會用 Gemini 產生**初稿**。初稿不算完成，
必須逐張比對圖片核對過，資料才會標上 `reviewed`。

## 兩道關卡各自的角色

- **Gemini 負責初稿**：涵蓋率高、成本低、可無人值守，但動作方向與出處常出錯
- **你負責核對**：拿著初稿去挑錯，比從零描述準得多

實測 56 張初稿抓到的錯誤：

- 「趕豬」實際是拿木棍反覆敲暈
- 「撫摸柴犬的臉」實際是搧巴掌
- 「撞上玻璃門」實際是叼出飯碗摔在地上
- 「向後翻滾跌落沙發」實際是整隻貓被拖走
- 出處被畫風誤導（《搞笑漫畫日和》標成《米飛兔》）
- 「旁邊的怪獸拉著尾巴」實際上牠全程沒動 —— 而「站著什麼都不做」正是笑點

**核對重點是驗證初稿，不是重寫。** 初稿正確就用 `ok` 蓋章，不要為了改而改。

## 你看不到動作，要靠九宮格

直接讀動態 WebP／GIF 只會拿到**第一格**。務必先產生九宮格拼圖再判讀，
它把時間軸攤平成空間，動作變化才看得出來。

## 流程

```bash
# 1. 看有哪些待核對（最新的排前面）
npm run task:review-meme -- list

# 2. 印出初稿內容，等下逐張比對
npm run task:review-meme -- draft 10

# 3. 產生九宮格（輸出到 .meme-review/）
npm run task:review-meme -- sheet --pending 10

# 4. 用 Read 工具逐張看 .meme-review/<id>.webp，與初稿比對

# 5a. 初稿正確 → 蓋章
npm run task:review-meme -- ok <id> <id> ...

# 5b. 有錯 → 只寫要改的欄位，會自動標記已核對
npm run task:review-meme -- write <id> "describe=…" "emotion=…"

# 看不清楚時放大指定影格（會標上格號）
npm run task:review-meme -- zoom <id> 8 19
```

`write` 只接受 `describe` / `ocr` / `keyword` / `emotion`，其餘欄位由管線產生。
情緒標籤會被驗證，不在清單內或超過上限會直接拒絕寫入。

修正既有資料也用同一個 `write`，不必先 `list`。

## 核對清單

逐張看九宮格時，依序確認初稿的這幾件事：

1. **動作方向對不對** —— 退回門內 vs 走出門外、被拖走 vs 自己跌倒。看首尾兩格的位置差
2. **結果有沒有寫到** —— 最後一格常是笑點（畫面變空、變白、爆炸）
3. **有沒有虛構細節** —— 初稿常補上沒發生的動作。「靜止不動」往往才是梗
4. **出處可不可信** —— 畫風相似不代表同一部作品，沒把握就拿掉，別跟著初稿錯
5. **OCR 有沒有漏或錯字** —— 動圖各格文字可能不同；浮水印不該進 OCR
6. **情緒是不是「拿來表達」的** —— 不是圖中人物的心情

## 撰寫規則

### describe

正體中文 1–2 句，只寫**主體特徵、表情、動作變化與結果、出處作品名**。

- 動圖要寫出動作**變化與結果**，結果往往就是笑點（「只剩空蕩的沙發」「畫面一片白」）
- 禁止：「此為網路迷因」「背景模糊」「無文字」「無人物」「來源不明」「整體呈現…情緒」
- 禁止開頭贅詞：「圖片顯示」「畫面中央是」
- 禁止描述背景細節、服裝細節、氛圍總結
- 圖上文字不寫進 describe，放 ocr
- 諧音雙關格式：「X」為「Y」諧音
- **出處沒把握就不要寫**。具體角色名、怪獸名認不出來就用外觀描述帶過，寫錯比不寫更糟

### ocr

圖上所有可見文字，原樣抄錄，多段以空格分隔，無文字則留空字串。

- **忽略浮水印與頻道標記**（ViralHog、LAD BIBLE、MakeAGIF.com、reddit 等）
- 動圖各格文字可能不同，依播放順序全部抄錄，重複的只抄一次

### keyword

搜尋用關鍵字與同義詞，逗號分隔。想的是「使用者會用什麼線索找這張圖」：

- 動作與結果（摔碗、敲暈、拖走、掀桌）
- 實際使用情境（催飯、掛名組員、被叫去上班、豬隊友）
- 作品別稱（超人力霸王／鹹蛋超人／奧特曼／Ultraman）
- 諧音雙關要加上「諧音」

初稿的出處判斷錯誤時，原本那個錯誤名稱若確實是常見的聯想線索（例如米飛兔畫風），
可以留在 keyword，但 describe 必須寫正確的出處。

### emotion

這張圖「**拿來表達**」的情緒，判斷依據是**使用時機，不是圖中人物的心情**。
只能從下列清單挑，逗號分隔，最多 **2** 個，挑不出來就留空字串：

無奈、生氣、疑惑、開心、悲傷、驚訝、嘲諷、得意、尷尬、疲憊、可愛、恐怖、讚許、拒絕、敷衍

初稿常見誤標：

- 貓擺臭臉被拖走 → 是「拒絕」不是「驚訝」
- 被打巴掌仍禮貌微笑 → 是「敷衍、尷尬」
- 賊笑關門 → 是「得意、嘲諷」不是「拒絕、尷尬」
- 自己被電、隊友沒貢獻 → 「無奈、嘲諷」

## 判讀時容易踩的坑

- **九宮格取樣太疏**：長動圖只抽 9 格，中間的關鍵動作（叼起某物、放下某物）會漏掉。
  覺得動作接不起來就用 `zoom` 補看，不要憑九宮格硬猜
- **別急著推翻初稿**：曾經把「狗反覆用前爪把手撥開」誤判成「狗被拉起來」，
  放大後才發現初稿是對的。看不出來就 `zoom`，不是改掉

## 收尾

改完後確認整份資料仍可解析：

```bash
npm run task:check-meme-index
```
