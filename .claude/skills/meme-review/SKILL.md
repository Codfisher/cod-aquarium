# 迷因審查（Meme Review）

`npm run task:process-meme` 會用 Gemini 產生**初稿**。初稿不算完成，
必須逐張比對圖片核對過，資料才會標上 `reviewed`。

## 兩道關卡各自的角色

- **Gemini 負責初稿**：涵蓋率高、成本低、可無人值守，但動作方向與出處常出錯
- **你負責核對**：拿著初稿去挑錯，比從零描述準得多

實測 56 張初稿抓到的錯誤：

- 「趕豬」實際是拿木棍反覆敲暈
- 「撫摸柴犬的臉」實際是搧巴掌
- 「撞上玻璃門」實際是叼出飯碗摔在地上
- 「向後翻滾跌落沙發」實際是整隻貓被拖走
- 出處被畫風誤導（《搞笑漫畫日和》標成《米飛兔》）
- 「旁邊的怪獸拉著尾巴」實際上牠全程沒動 —— 而「站著什麼都不做」正是笑點

全庫 960 張靜態圖核對完的結果：初稿通過率 **7.6%**，最常見的三種錯依序是
**OCR 擅自轉簡繁或翻譯**（把「代驾」改成「代價」，諧音梗直接消失）、
**出處憑畫風硬猜**（約 50 張）、**多語系圖只抄中文那一行**。

**核對重點是驗證初稿，不是重寫。** 初稿正確就用 `ok` 蓋章，不要為了改而改。

## 你看不到動作，要靠九宮格

直接讀動態 WebP／GIF 只會拿到**第一格**。務必先產生九宮格拼圖再判讀，
它把時間軸攤平成空間，動作變化才看得出來。

## 靜態圖也看不清楚，要靠 crop

迷因圖多半是低解析度轉存。爪子、手勢、小字這類細節在原圖根本糊成一團，
而**動作方向常常就卡在這種細節上**。要推翻初稿的動作描述前，先 `crop` 放大該部位。

## 流程

```bash
# 1. 看有哪些待核對（最新的排前面）
npm run task:review-meme -- list

# 2. 印出初稿內容，等下逐張比對
npm run task:review-meme -- draft 10

# 3. 產生九宮格（輸出到 .meme-review/）
npm run task:review-meme -- sheet --pending 10

# 4. 用 Read 工具逐張看 .meme-review/<id>.webp，與初稿比對

# 5a. 初稿正確 → 蓋章
npm run task:review-meme -- ok <id> <id> ...

# 5b. 有錯 → 只寫要改的欄位，會自動標記已核對
npm run task:review-meme -- write <id> "describe=…" "emotion=…"

# 看不清楚時放大指定影格（會標上格號）
npm run task:review-meme -- zoom <id> 8 19

# 靜態圖看不清楚時放大九宮格區塊（加強對比，區塊：左上 上 右上 左 中 右 左下 下 右下）
npm run task:review-meme -- crop <id> 左下
```

`write` 只接受 `describe` / `ocr` / `keyword` / `emotion`，其餘欄位由管線產生。
情緒標籤會被驗證，不在清單內或超過上限會直接拒絕寫入。

修正既有資料也用同一個 `write`，不必先 `list`。

## 核對清單

逐張看九宮格時，依序確認初稿的這幾件事：

1. **動作方向對不對** —— 退回門內 vs 走出門外、被拖走 vs 自己跌倒。看首尾兩格的位置差
2. **結果有沒有寫到** —— 最後一格常是笑點（畫面變空、變白、爆炸）
3. **有沒有虛構細節** —— 初稿常補上沒發生的動作。「靜止不動」往往才是梗
4. **出處可不可信** —— 畫風相似不代表同一部作品，沒把握就拿掉，別跟著初稿錯
5. **OCR 有沒有漏或錯字** —— 動圖各格文字可能不同；浮水印不該進 OCR
6. **情緒是不是「拿來表達」的** —— 不是圖中人物的心情

## 撰寫規則

### describe

正體中文 1–2 句，只寫**主體特徵、表情、動作變化與結果、出處作品名**。

- 動圖要寫出動作**變化與結果**，結果往往就是笑點（「只剩空蕩的沙發」「畫面一片白」）
- 禁止：「此為網路迷因」「背景模糊」「無文字」「無人物」「來源不明」「整體呈現…情緒」
- 禁止開頭贅詞：「圖片顯示」「畫面中央是」
- 禁止描述背景細節、服裝細節、氛圍總結
- 圖上文字不寫進 describe，放 ocr
- 諧音雙關格式：「X」為「Y」諧音
- **出處沒把握就不要寫**。具體角色名、怪獸名認不出來就用外觀描述帶過，寫錯比不寫更糟

### ocr

圖上所有可見文字，原樣抄錄，多段以空格分隔，無文字則留空字串。

- **原樣抄錄是字面意思**：原圖簡體就抄簡體、日文就抄日文、韓文就抄韓文。
  **連錯字與不合文法的地方都照抄** —— 曾經圖上印著「돈이 어딨이」，
  初稿與核對者都自動修成文法正確的「어딨어」。模型會自動糾正外語，要刻意抵抗
- **諧音梗常靠單一個字成立，改字等於把梗弄丟**：「代驾」被轉成「代價」、
  「瞧不吉你」被抄成「瞧不起你」、「哩洗咧靠喔」被抄成「靠哇」，梗全沒了
- **忽略浮水印與頻道標記**（ViralHog、LAD BIBLE、MakeAGIF.com、reddit、Bilibili
  頻道名、電視台台標、新聞人物字幕條與跑馬燈、譯者署名）
- **但商品包裝、招牌、衣物、書封上的文字要保留**，那是畫面主體不是浮水印。
  牙膏盒特寫就該收品牌與品名，吉祥物腰帶上的 DAIKIN 也一樣
- **同一張圖的取捨要一致**，別收了一半漏一半
- **多語系圖不要只抄中文那一行**，日／韓／英各段都要收
- 動圖各格文字可能不同，依播放順序全部抄錄，重複的只抄一次

### keyword

搜尋用關鍵字與同義詞，逗號分隔。想的是「使用者會用什麼線索找這張圖」：

- 動作與結果（摔碗、敲暈、拖走、掀桌）
- 實際使用情境（催飯、掛名組員、被叫去上班、豬隊友）
- 作品別稱（超人力霸王／鹹蛋超人／奧特曼／Ultraman）
- 諧音雙關要加上「諧音」

初稿的出處判斷錯誤時，原本那個錯誤名稱若確實是常見的聯想線索（例如米飛兔畫風），
可以留在 keyword，但 describe 必須寫正確的出處。

**但被圖片證據推翻的名字要清掉**。這兩件事不一樣：畫風聯想留著有用，
「圖上根本不是這個人」的名字留著只會誤導。實測最大宗的失誤就是這個 ——
describe 把「威廉亞當」改成「傑克開膛手」，keyword 卻原封留著威廉亞當。

### emotion

這張圖「**拿來表達**」的情緒，判斷依據是**使用時機，不是圖中人物的心情**。
只能從下列清單挑，逗號分隔，最多 **2** 個，挑不出來就留空字串：

無奈、生氣、疑惑、開心、悲傷、驚訝、嘲諷、得意、尷尬、疲憊、可愛、恐怖、讚許、拒絕、敷衍

初稿常見誤標：

- 貓擺臭臉被拖走 → 是「拒絕」不是「驚訝」
- 被打巴掌仍禮貌微笑 → 是「敷衍、尷尬」
- 賊笑關門 → 是「得意、嘲諷」不是「拒絕、尷尬」
- 自己被電、隊友沒貢獻 → 「無奈、嘲諷」

## 判讀時容易踩的坑

- **九宮格取樣太疏**：長動圖只抽 9 格，中間的關鍵動作（叼起某物、放下某物）會漏掉。
  覺得動作接不起來就用 `zoom` 補看，不要憑九宮格硬猜
- **別急著推翻初稿**：曾經把「狗反覆用前爪把手撥開」誤判成「狗被拉起來」，
  放大後才發現初稿是對的。看不出來就 `zoom` 或 `crop`，不是改掉
- **反向驗證比正面辨認可靠**：判斷「前肢在身前還是身後」時，糊掉的爪子怎麼看都看不準，
  但去看**身前那一側的輪廓有沒有東西**就一翻兩瞪眼 —— 胸線直接貼著窗戶，
  就證明前肢不在身前。分不出 A 或 B 時，改去找「若是 A 就一定會出現的東西」
- **先驗證再改，包括使用者說你錯的時候**：使用者指出錯誤時同樣要先放大核對再動手。
  跳過核對就改，等於把「別急著推翻初稿」換個對象再犯一次

## 核對者自己會犯的七種錯

960 張全部核對完、再逐張複驗一遍後，核對者的錯誤率是 **10.1%**。
以下七種按實測歸納，**共通根源是「想把描述寫得更完整」**——
而補完整正是引入錯誤的時機。

1. **具體換具體**：初稿寫了一個具體動作，你換成另一個同樣具體的，但誰都沒去看圖。
   柴犬「前肢置於身後」→「垂在身前」、恐怖漫畫「面具落在一旁」（實際仍扣在臉上）、
   海綿寶寶「刷眼睛」→「刷牙」（泡沫下方看得到嘴與門牙）。
   **沒把握就保留初稿，或把該細節整個拿掉，不要換一個等強度的新斷言**
2. **籠統換具體**（最常重複）：初稿講得含糊，你「補完整」，補出圖上沒有的東西。
   吉娃娃「瞇眼」（實際圓睜）、五條悟「抱胸」（實際雙手在身前交握）、
   「牽著狗」（手臂空著，狗身上只有項圈）、「閉眼微笑」（小人根本沒畫嘴巴）
3. **憑印象填數量**：初稿沒提數量，你自己填一個。
   「三顆餃子」（手只捏一顆）、雙槍貓漏數第三把槍、宮女「五位」（實際三抬一）
4. **歸屬判錯／合併斷言**：把不同來源的東西講成同一個，或算到錯的人身上。
   布偶自己伸出的手→「旁邊伸出一隻手」（放大袖口才看出穿自同一隻布偶）、
   「同一張笑臉」（比對衣領與嘴型是不同素材）、「三格連續比手勢」（末格手不在畫面裡）
5. **刪套語時誤刪實物**：規則要你刪掉「幽默帶威脅感」這種總結，
   你連旁邊的客觀特徵一起砍。兔耳玩偶手上的斧頭、漫畫裡的望遠鏡、平頭男嘴角的菸。
   **刪的是評價與氛圍，不是物件**
6. **動刀沒收尾**（最大宗）：describe / ocr / keyword **三欄要彼此對得起來**。
   改了出處卻沒同步 keyword、台標改對了卻沒清掉 OCR 裡的新聞字幕條、
   圖上字幕印著人名而 OCR 也抄了、describe 卻把人名刪光
7. **硬安諧音**：為了滿足「諧音要標本體詞」而硬湊。
   「敷眼／熬夜」讀音毫無關聯、把「谋财害命」拗成「莫再掛科」。
   **不是諧音就別標**

判不出來時一律**保留現狀**，別為了交出成果而找碴 —— 無憑據地推翻，
只是把同一個錯誤換個方向再犯一次。

## 收尾

改完每一筆之前，先回頭對一次三欄（第 6 種錯就是漏了這一步）：

- describe 動過出處或主體 → keyword 裡被推翻的名字清掉了嗎？
- OCR 排除了台標或字幕條 → 同一張圖的其他台標、跑馬燈也一起排除了嗎？
- describe 標了諧音 → keyword 有「諧音」與本體詞嗎？兩詞讀音真的相近嗎？

改完後確認整份資料仍可解析：

```bash
npm run task:check-meme-index
```
