# Minespace - EP17：打散色階

大家好，我是鱈魚。

上一章把抗鋸齒從 FXAA 換成多重取樣，畫面上的貼圖總算不再被抹糊。

換完之後抬頭看天，一整片漸層上浮出了一圈一圈的等高線。%(⊙ o ⊙)%

鱈魚：「顯卡壞了？」
路人：「你自己把幫你遮住的東西拆了啊。」

## 色階環是什麼

畫面最後要寫進一份八位元的緩衝區，每個通道只有 0 到 255 這 256 個整數可以用。

著色器算出來的顏色是連續的浮點數，寫進去的那一刻得挑一個最近的整數。這一步叫量化，而量化的誤差本身很小，一個色階而已，人眼在一般的畫面上根本看不出來。

麻煩的是**平滑而漫長的漸層**。

想像一條從天頂的深藍走到天邊的白，走完整個畫面高度。這條路上只能踩 256 級台階，於是每一級都佔了好幾十列像素。同一級之內是完全相同的顏色，級與級之間是一次乾淨俐落的跳躍。

那就是一條看得見的界線。

<demo-banding-origin />

漸層越長，每一階佔的螢幕就越寬，界線也就越明顯。%(´･_･`)%

而人眼對這種轉折特別敏感，這現象叫馬赫帶效應（Mach bands）。就算兩側只差一個色階，只要那條界線是筆直而連續的，眼睛就會自己把它強調出來。

路人：「所以改成十位元的緩衝區就好了？」
鱈魚：「WebGL 給不了，而且顯示器多半也吃不到。」

## 加半個色階的雜訊

治法出乎意料地便宜。在量化之前，替每個像素加上一點隨機的偏移就好。

```glsl
float noise = fract(sin(dot(gl_FragCoord.xy, vec2(12.9898, 78.233))) * 43758.5453);
color += (noise - 0.5) / 255.0;
```

`fract(sin(...))` 是著色器裡最省的亂數。拿片元座標做一次高頻的正弦再取小數，出來的值在 0 到 1 之間，而且相鄰像素之間毫無關聯。

減 0.5 讓它變成正負半個色階，除以 255 換算成八位元的一階。

<demo-dither-noise />

### 為什麼這樣就看不出來了

關鍵在於**界線消失了，誤差還在**。

想像漸層走到某一段，理想值剛好落在第 100 階與第 101 階之間，偏第 100 階那側三成。

沒有雜訊的時候，這一整段的每個像素都會乖乖地選 100，直到理想值越過中點才整排一起跳到 101。那個「一起跳」畫出來就是一條線。

加了雜訊之後，每個像素拿到的偏移都不一樣。理想值偏 100 那側三成的地方，大約七成的像素選 100、三成選 101，而且是隨機散布的。再往前走一點，選 101 的比例慢慢升到四成、五成。

於是**這一整片的平均亮度是連續的**，眼睛看到的是平滑的過渡。原本集中在界線上的誤差被攤成滿版的細顆粒，而顆粒的振幅只有一個色階，肉眼看不見。%( •̀ ω •́ )✧%

雜訊的幅度給到一個色階寬就夠。再往上加只是把畫面弄髒，界線早就散掉了。

## 每一道後製都是一次重排

事情還沒完。

畫面畫進緩衝區之後，還要經過色調映射、對比、色調曲線，最後才寫進螢幕。而每一道處理都在重新排列色階。

ACES 這條曲線在亮部壓縮得很兇、在暗部拉開得很兇。壓縮的那一段，好幾個輸入階會被擠成同一個輸出階；拉開的那一段剛好相反，原本相鄰的兩階被推得老遠，中間空出一段沒有東西的區間。

再量化一次，那段空隙就成了更寬的一條帶。

<demo-tonemap-band />

所以打散色階要做兩次，一次在畫面出去之前，一次在來源那一層。

## 第一步：管線這一道

Babylon 的影像處理本身就有這個開關。

```ts
pipeline.imageProcessing.ditheringEnabled = true
```

它會在色調映射與色調曲線之後、寫進畫面之前加上一份雜訊，預設強度剛好是 1/255。

成本是每個像素一次亂數，換來的是肉眼看不見的顆粒取代看得見的圈。這筆帳怎麼算都划算。%(´,,•ω•,,)%

順帶一提，這也是為什麼專案裡最後拿掉了色彩分級的查找表。

查找表的取樣走三線性內插，等於把一條平滑的曲線換成幾十段折線，而每個節點上斜率會跳一下。天空的漸層加上光暈那層放射狀的亮度都是極平滑的東西，兩者相加之後，某一圈等亮度線壓在節點上就會浮出一道看得見的輪廓。

實測那張查找表最大只改變 8/255，多數落在 1 到 5 之間。一個看不太出來的效果，換一個看得很清楚的瑕疵。%(›´ω`‹ )%

## 第二步：天空那一層自己再加一次

管線那一道處理的是最後那次量化。而天空是自己算出顏色、自己寫進緩衝區的，它那一層的量化在更早之前就發生了。

天空又剛好是全場漸層最長的東西。從天頂到天邊、從太陽那一側到背光那一側，兩條路都鋪滿整個畫面。

所以 `sky-gradient` 的片元著色器在最後一行自己加了一次。

```glsl
/**
 * 打散色階
 *
 * 整片天是一條很長的漸層，八位元的色階在上面會顯出一圈圈的等高線。
 * 加上半個色階的雜訊就看不出來了，代價是肉眼看不見的顆粒
 */
float noise = fract(sin(dot(gl_FragCoord.xy, vec2(12.9898, 78.233))) * 43758.5453);
color += (noise - 0.5) / 255.0;

gl_FragColor = vec4(color, 1.0);
```

就這兩行，接在混完霞光之後。

<demo-sky-dither />

把著色器內的雜訊關掉，天邊那一圈暖光的外緣會清清楚楚地畫出好幾道弧。那正是它們最容易出現的位置，因為那裡的漸層走得最慢。

路人：「兩層都加，雜訊會不會疊起來？」
鱈魚：「會，變成大約一點四個色階。還是遠低於看得見的門檻。」

## 為什麼抗鋸齒換掉之後才要處理

回到開頭那個問題。

FXAA 的判斷依據是亮度落差。而色階的界線本身就是一道落差，正好落在它的守備範圍裡，於是它在抹平幾何邊緣的同時，順手也把那些等高線抹開了。

那是免費的，也是不受控的。它決定要抹哪裡的依據跟色階完全無關，而且會連貼圖的硬邊一起帶走（上一章那件事）。

多重取樣不碰這件事。它只對真正的幾何邊緣多取幾個樣本，色階的界線在它眼裡什麼都不是。

所以換過去之後，這一項得由自己正面處理。%( ˘•ω•˘ )%

## 完整實作

整理一次。

1. 管線開 `ditheringEnabled`，收拾色調映射與色調曲線重排之後的那次量化
2. 天空著色器在寫出顏色前自己加一次，收拾它自己那一層的量化
3. 雜訊幅度都是正負半個色階，也就是 `1/255`
4. 亂數用 `fract(sin(dot(gl_FragCoord.xy, ...)))`，一次乘法一次正弦

判斷「這裡該不該加」的標準只有一條，**這一層有沒有長而平滑的漸層**。

天空有，光暈有，霧的過渡有。方塊的表面沒有，那上面滿滿都是貼圖的硬邊，本來就不存在連續的漸層。

## 總結 🐟

以上程式碼可以[在此取得](https://github.com/Codfisher/cod-aquarium/tree/main/content/aquarium/minespace)

- 色階環來自八位元只有 256 階，而長漸層讓每一階佔了好幾十列像素
- 加上正負半個色階的雜訊，界線會散成看不見的顆粒，平均亮度反而變連續
- 雜訊要加在量化之前，加在之後只是灑顆粒
- 色調映射與分級會重排色階，重新量化之後色階環更明顯，所以管線那一道要開
- 天空自己也加一次，因為它那一層的漸層最長、而且它自己就會量化一次
