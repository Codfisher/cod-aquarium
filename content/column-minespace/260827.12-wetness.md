# Minespace - EP12：雨後濕潤

大家好，我是鱈魚。

雨本身只是幾千條掉下來的線，落地就沒了。真正讓人相信剛下過雨的，是雨停之後那段地還是濕的時間。

少了它，走出聽雨亭的那一步，整個世界會在一瞬間乾透。%(´･_･`)%

## 濕的表面在物理上發生了什麼

這件事有兩個方向相反的效果，而且必須同時發生。

**第一件是變暗。**

石頭、木頭、泥土這類表面都有孔隙。下雨之後水填進那些孔隙，光射進去以後在裡面來回反射好幾次才出得來，每一次反射都被吸收掉一點。走出來的光就少了，於是我們看到的是一片更深、更飽和的顏色。

濕掉的沙灘顏色比乾沙深好幾階，就是這個原因。

**第二件是變亮。**

乾的表面很粗糙，法線東倒西歪，照進來的光散到各個方向。水在上面鋪成一層平滑的膜之後，那些散開的反射全部聚回同一個方向，高光因此暴增。

雨後的柏油路在斜射的陽光下會亮到刺眼，那道亮本來就該在那裡。

<figure-wet-specular />

鱈魚：「所以濕就是把顏色調暗嘛，一行搞定。」
路人：「那看起來只是髒而已。」
鱈魚：「⋯⋯好啦，還要把高光一起拉起來。」

<demo-wet-basic />

範例裡把兩個開關分開試一次就很清楚。只壓暗是髒，只加高光是上了一層蠟，兩個一起才是濕的。%( •̀ ω •́ )✧%

## 第一步：先把原色記下來

實作之前有一件事要先做對。

濕度會連續變化，每一幀都可能重算，所以絕對不能在材質的現值上再乘一次。那樣調個幾次就會越調越黑，再也回不來。

```ts
const backupList = materialList.map((material) => ({
  material,
  diffuse: [material.diffuseColor.r, material.diffuseColor.g, material.diffuseColor.b],
  specular: [material.specularColor.r, material.specularColor.g, material.specularColor.b],
  specularPower: material.specularPower,
}))
```

之後每次都拿這份原色去算。

## 第二步：漫射壓暗

```ts
const WET_DIFFUSE_RATIO = 0.68

const diffuseRatio = lerp(1, WET_DIFFUSE_RATIO, wet)

material.diffuseColor.set(
  diffuse[0] * diffuseRatio,
  diffuse[1] * diffuseRatio,
  diffuse[2] * diffuseRatio,
)
```

業界對柏油這類多孔材質會壓到剩下一兩成，方塊世界不必那麼極端。這裡的木頭與石頭本來就是低飽和的手繪色，壓太多會整片發黑，留六成八剛好。

## 第三步：高光提亮並散開

高光要往同一個目標值收。

```ts
const WET_SPECULAR = 0.42

material.specularColor.set(
  lerp(specular[0], WET_SPECULAR, wet),
  lerp(specular[1], WET_SPECULAR, wet),
  lerp(specular[2], WET_SPECULAR, wet),
)
```

照原值放大的話會有一個很難發現的漏洞。原本的高光是每種方塊各自調過的，有的很低、有的乾脆是零，而零乘上任何倍率都還是零，那幾種方塊永遠濕不起來。

水膜是蓋在表面上的一層，底下是什麼材質並不影響它有多亮。%( ˘•ω•˘ )%

範圍也要一起放寬。

```ts
const WET_SPECULAR_POWER = 20

material.specularPower = lerp(backup.specularPower, WET_SPECULAR_POWER, wet)
```

指數越低、高光的範圍越寬。乾的方塊用預設的六十四，那是幾乎看不見的小亮點；濕的地面該是一整片順著光的方向鋪開的亮，收到二十才是水膜該有的樣子。

順帶一提，高光這一項在 `StandardMaterial` 裡加在漫射的 clamp 外面，也就是全場唯一能真的超過純白的通道。雨後那道刺眼的反光正是從那裡來的。

<demo-wet-target />

六成八、零點四二、二十，這三個數字都是可以調的目標值。拉一拉滑桿，看看它們各自決定了什麼。

## 第四步：讓地面反射天色

到這裡已經很像了，還缺最後一樣東西。

真正的濕地面會反射天空。斜看出去的那一段路面會泛起一層天色，那是雨後最容易辨認的畫面。

正統的做法是螢幕空間反射，把場景多畫一次去找每個像素該反射什麼。而那個成本，跟這片禪庭濕地能佔到的畫面完全不成比例。%(´థ‸థ)%

所以走另一條路，反射一張等距柱狀投影的貼圖。

```ts
const texture = new DynamicTexture(
  'wet-sky-reflection',
  { width: 4, height: 64 },
  scene,
  false,
)
texture.coordinatesMode = Texture.FIXED_EQUIRECTANGULAR_MODE
texture.level = 0
```

寬度只給四像素，因為等距柱狀投影的顏色只跟視線的垂直角度有關，水平朝哪看都一樣。高度給六十四，漸層夠細看不出色階。

`FIXED` 那個變體是固定在世界座標上的，不隨鏡頭旋轉重新取樣。反光的是天空本身的顏色，鏡頭朝哪看都該一樣。

貼圖的內容跟著天色重畫。

```ts
const gradient = context.createLinearGradient(0, 0, 0, half)
gradient.addColorStop(0, colorToCss(atmosphere.skyZenithColor))
gradient.addColorStop(0.6, colorToCss(atmosphere.skyMidColor))
gradient.addColorStop(1, colorToCss(atmosphere.baseFogColor))
```

上半段是抬頭方向，天頂到地平線的漸層，中間插一階中空色，晨昏那種丁香紫與洋紅才有地方待。下半段是低頭方向，沒有真的地面資料，填地平線色至少不會顯得突兀。

天色變化很慢，半秒重畫一次就夠了。

<demo-sky-reflection />

這張圖不負責「反光的到底是不是眼前那棵樹」，它只負責「濕地在斜視角會泛起一層天光」。%(´,,•ω•,,)%

## 第五步：Fresnel 把反光趕到掠射角

只掛上反射貼圖的話，整片草地會泛白。

原因很直接，雨天的天空是一片亮灰，以那個強度反射到每一個像素上，等於在整個世界蓋一層灰白。濕潤該有的那道壓暗，被自己的反光完全蓋過去了。

真實的反射有角度。越貼近掠射角，反射越強，正對著看則幾乎沒有。這叫 Fresnel。

```ts
const fresnelParameters = new FresnelParameters()
fresnelParameters.bias = 0.02
fresnelParameters.power = 4
```

`bias` 是「正對時還留多少」，`power` 是「往掠射角集中得多快」。

<figure-wet-fresnel />

<demo-wet-fresnel />

`bias` 給高一點，低頭看到的地面也會蒙上一層天色。收到近乎零、`power` 拉高，反光就縮回它該在的地方，也就是斜看出去的那一段遠景。

強度也要一起收。

```ts
const WET_REFLECTION_LEVEL = 0.22

reflectionTexture.level = lerp(0, WET_REFLECTION_LEVEL, wet)
```

兩成二配上收窄的 Fresnel，濕地才會顯得更深、更飽和，而只在掠射角泛起一道白。

貼圖只有一張、Fresnel 參數只有一份，所有濕的材質共用，所以調這一個 `level` 就等於整個世界的濕地反光一起淡入淡出。

## 第六步：乾的時候要把貼圖整個拆掉

這一步很容易做成「把強度調成零就好」，那樣行不通。

```ts
function setReflectionAttached(nextAttached: boolean): void {
  for (const backup of backupList) {
    backup.material.reflectionTexture = nextAttached ? reflectionTexture : null
    backup.material.reflectionFresnelParameters = fresnelParameters
  }
}
```

兩個理由。

**一是浪費。**九成九的時間地面是乾的，卻讓兩百多份材質都常駐帶著一張反射貼圖，每一次繪製都多綁一個取樣器。

**二是會出事。**`StandardMaterial` 的反射在著色器裡有 `samplerCube` 與 `sampler2D` 兩份宣告，靠條件編譯二選一。掛著一張 2D 的等距柱狀投影貼圖時，另一份宣告仍然存在卻永遠不會被綁，於是它退回材質單元零，而那一格綁的是別的 2D 貼圖。

WebGL 對這種情況會丟出這一行。

```text
GL_INVALID_OPERATION: Two textures of different types use the same sampler location
```

整個繪製呼叫作廢。%(・_・;)%

只在真的濕的時候掛上去，乾了就拆掉，兩個問題一起沒有。

順帶一提，Fresnel 參數留著就好，不必跟著拆。那組參數單獨存在時不做任何事，反射那一段整個掛在有沒有貼圖上。

## 第七步：雨停之後慢慢乾

最後把濕度接上天氣。

<demo-wet-dry />

淋濕要快、變乾要慢，兩者差好幾倍。一場雨幾秒就把地面打濕，而雨停之後那段慢慢乾的過程才是這個效果存在的理由。

寫進材質之前記得加一道門檻。

```ts
const APPLY_STEP = 0.01

setRatio(ratio: number) {
  const wet = Math.min(1, Math.max(0, ratio))
  if (Math.abs(wet - appliedRatio) < APPLY_STEP)
    return

  appliedRatio = wet
  // 兩百多份材質從這裡開始改
}
```

這是每一幀都會走的路徑，而濕度在一秒內的變化遠小於眼睛看得出來的差別。差得夠多才動手，多數幀就整個跳過。

## 完整實作

專案裡的濕潤是一件全域的事，因為材質本來就全世界共用，同一種石頭只有一份。

這件事在這個場景裡剛好說得過去。雨勢滿檔時能見度只有二十六格，看得到的就只有腳邊這一塊；而走出雨區之後那段慢慢乾的過程，本來就該跟著人一起離開。

低畫質則不給反射貼圖。`createWetness` 的第二個參數是選用的，沒給的話就只做原本的漫射壓暗與高光散開，那兩件事本來就不花錢。

```ts
export function createWetness(
  materialList: StandardMaterial[],
  reflectionTexture?: Texture,
): Wetness
```
