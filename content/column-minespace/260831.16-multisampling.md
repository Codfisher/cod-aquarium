# Minespace - EP16：多重取樣

大家好，我是鱈魚。

這一章講抗鋸齒。%( •̀ ω •́ )✧%

方塊世界的東西幾乎全是盒子，而盒子只要轉過一點角度，稜線上就會出現一排階梯。走路的時候那排階梯還會沿著邊緣爬，特別搶眼。

## 鋸齒是怎麼來的

畫面上的一個像素，其實是一小塊有面積的方格。而光柵化在決定這個方格該塗什麼顏色時，只問了一次，問的是方格正中心那一點落在誰身上。

三角形蓋住這一格的九成也好、一成也好，只要中心點在裡面，整格就是三角形的顏色；中心點在外面，整格就是背景色。中間那些「蓋了一半」的情況完全沒有地方可以表達。

<demo-aliasing-origin />

把像素放大之後就看得很清楚了。斜邊只能在整數格之間跳，於是排成一道階梯。%(´･_･`)%

鱈魚：「那把解析度開到無限大不就好了？」
路人：「你的顯卡會先跟你分手。」

## 兩條路

抹開那排階梯有兩種完全不同的做法。

**FXAA** 是一道後製。等整張畫面畫完之後，它掃過每一個像素，找出亮度落差大的地方，判斷那裡大概是一條邊，再沿著邊的方向把兩側的顏色混一混。它很便宜，只要一趟全螢幕的取樣。

**MSAA**（多重取樣）發生在光柵化的當下。同一個像素裡擺好幾個取樣點，逐點去問「這一點在三角形裡面嗎」，最後按照中了幾點決定這一格要混多少三角形的顏色。片元著色器仍然只跑一次，多出來的只有覆蓋率的判定。

兩者的差別在於**它們手上有多少資訊**。

## 為什麼這個專案選 MSAA

FXAA 看到的只有一張畫好的圖。它分不出眼前這條亮度落差是幾何的邊緣，還是貼圖上本來就該有的兩格不同顏色的像素。

而 Minespace 的貼圖是十六格見方的像素畫，滿滿都是後者。

<demo-fxaa-texture />

開著 FXAA 的時候，牆面上那些石縫與顆粒被輕輕糊掉一層。那正是這套美術最不該失去的東西。%(´,,•ω•,,)%

MSAA 拿到的是光柵化階段的覆蓋率，它知道哪裡才是真正的三角形邊界。方塊的稜線平順了，貼圖一個像素都沒被動到。

路人：「所以像素風遊戲一律不能用 FXAA？」
鱈魚：「硬邊的美術風格都得小心。它的判斷依據就是亮度落差，而硬邊本來就是落差。」

代價是 MSAA 要配置一份多重取樣的緩衝區，每一幀還要多一次解析。這是頻寬的成本，跑不動的機器就兩個都不開。

## 第一步：把管線建起來

Babylon 的 `DefaultRenderingPipeline` 會把場景畫進離屏貼圖，再一路做完色調映射、暗角這些後製。

```ts
const pipeline = new DefaultRenderingPipeline('minespace-pipeline', false, scene, [camera])

pipeline.imageProcessingEnabled = true
pipeline.imageProcessing.toneMappingEnabled = true
pipeline.imageProcessing.toneMappingType = ImageProcessingConfiguration.TONEMAPPING_ACES
```

抗鋸齒的兩個開關就掛在這個管線上。

```ts
/** 幾何邊緣交給多重取樣 */
pipeline.samples = 4
/** 後製的那一種關掉，它會連貼圖一起抹 */
pipeline.fxaaEnabled = false
```

`samples` 給 1 等於關閉。

## 第二步：canvas 的多重取樣要關掉

這一步很容易漏。

建立引擎時有個 `antialias` 選項，那開的是 canvas 預設緩衝區的多重取樣。

```ts
return new Engine(canvas, false, {
  antialias: false,
  alpha: false,
  stencil: false,
  preserveDrawingBuffer: false,
})
```

之所以要關掉，是因為場景根本不是畫在那份緩衝區上。

有了 `DefaultRenderingPipeline` 之後，整個世界會先畫進管線自己的離屏貼圖，後製跑完才把結果貼回 canvas。而貼回去的那一步只畫一片鋪滿螢幕的方塊，上面沒有任何幾何邊緣。

canvas 那份多重取樣緩衝區於是接到一片沒有邊的東西，抗鋸齒無從發揮，白配置一份記憶體與頻寬。真正在做事的是管線上的 `samples`。%( ˘•ω•˘ )%

## 第三步：取樣數給到幾

<demo-sample-count />

一到二那一階差最多，二到四還看得出來，四以上就只剩下帳單。

理由是覆蓋率的表達能力。一個像素四個樣本，邊緣能表達的是「四分之零到四分之四」共五階；八個樣本變成九階，而人眼在一條邊上分不出這兩者的差別。頻寬卻是線性成長。

所以專案裡最高的兩級都停在四倍。

```ts
export const QUALITY_PRESET_MAP = {
  high: {
    sampleCount: 4,
    // ...
  },
  ultra: {
    sampleCount: 4,
    // ...
  },
}
```

最省的那一級給 1，也就是整個不開。那一級本來就在跟頻寬計較。

## 第四步：解析度倍率

抗鋸齒還有第三條路，直接畫更多的像素。

<demo-resolution-scale />

倍率調到 0.5 的時候，實際畫布的邊長是螢幕的兩倍。縮回去顯示的那一步，每個螢幕像素等於收了四個樣本，邊緣自然就平了。這叫超取樣，效果最好，成本也最兇。

Babylon 這邊的旋鈕叫硬體縮放，它與倍率互為倒數。

```ts
export function getHardwareScalingLevel(preset: QualityPreset, devicePixelRatio: number): number {
  return 1 / Math.min(devicePixelRatio, preset.pixelRatioLimit)
}
```

`Math.min` 那一段是關鍵。在兩倍的螢幕上照著裝置像素比走，代表要畫四倍的像素。

而幀率一低，轉動視角就會一段一段跳。視角轉多少是由滑鼠位移決定的，與幀率無關；幀率低下來，同樣的角度就被切成更少、更大的步進。

所以每一級各有一個像素上限。

```ts
export const QUALITY_PRESET_MAP = {
  low: { pixelRatioLimit: 1 / 3 },
  medium: { pixelRatioLimit: 1 },
  high: { pixelRatioLimit: 1.5 },
  ultra: { pixelRatioLimit: 1.5 },
}
```

最奢的那一級原本給 2，後來收回一點五。那多出來的像素換到的是幾乎看不出的銳利度，卻讓最貴的三項（四層陰影、遮擋視差、光線行進）各自多付兩倍多的錢。

極致該奢在效果。%( •̀ ω •́ )✧%

## 第五步：接上畫質分級

兩個數字都放進設定表，切換畫質時一起套用。

```ts
watch(quality, () => {
  const devicePixelRatio = window?.devicePixelRatio ?? 1
  engine.value?.setHardwareScalingLevel(
    getHardwareScalingLevel(preset.value, devicePixelRatio),
  )

  if (pipeline.value) {
    pipeline.value.samples = preset.value.sampleCount
  }
})
```

這兩項都是設一個屬性就生效的，用 `watch` 接就好。陰影就沒這麼幸運，貼圖邊長是建構時決定的，換等級得整個重建。

除錯開關那邊也接一份，方便隨時把兩種抗鋸齒對著比。

```ts
pipeline.value.samples = devToggle.multiSample ? preset.value.sampleCount : 1
/** 關掉多重取樣時補回 FXAA，才比較得出兩者的差別 */
pipeline.value.fxaaEnabled = !devToggle.multiSample && preset.value.sampleCount > 1
```

## 完整實作

整理一次流程。

1. 建引擎時 `antialias: false`，場景不畫在 canvas 的緩衝區上
2. 建 `DefaultRenderingPipeline`，`fxaaEnabled = false`
3. `pipeline.samples` 由畫質設定表決定，最高給 4
4. `setHardwareScalingLevel` 由同一張表的像素上限算出來
5. 切換畫質時兩項一起更新

最後補一件事。抗鋸齒從 FXAA 換成多重取樣之後，會少掉一個原本沒人注意到的副作用。

FXAA 在抹平邊緣的同時，順手也把色階的邊界抹開了。那些一圈一圈的等高線落差雖小，在它眼裡照樣是落差。

換掉它之後，那件事得由別人正面處理。下一章講的就是這個。%(๑•̀ㅂ•́)و✧%
