# Minespace - EP09：岸線與漣漪

大家好，我是鱈魚。

一片水最容易露餡的地方在岸邊。

方塊世界的水面是一整片同樣的藍，湖心與腳邊的淺灘長得一模一樣。少了那圈白沫，那片水在畫面上只是一塊藍色的半透明蓋子。%(´･_･`)%

這一章做兩件事。一是岸線，水淺的地方浮出一圈白沫；二是漣漪，雨滴與腳步各打出一圈往外擴的環。

第一件事得先知道「水底下那塊沙地離我多遠」，所以從深度圖講起。

## 場景深度圖是什麼

深度圖是一張與畫面同樣大小的圖，每個像素存著「這個方向上最近的實體有多遠」。

<demo-depth-map />

近的白、遠的黑，一整片地形被壓成一張灰階圖。%(⊙ o ⊙)%

範例裡有個地方值得停一下。那片水完全不在圖上。

深度算繪預設只畫不透明與 alpha test 的網格，半透明的東西整批跳過。水面因此不在自己這張圖上，它問到的才會是水底下那塊沙地。

### 為什麼要自己再畫一趟

鱈魚：「畫面本來就有一份深度緩衝區，直接拿來讀不就好了？」
路人：「WebGL 拿不到那個東西。」
鱈魚：「…好吧，那就自己再畫一趟。」

這是這套機制最貴的地方。整個場景要多跑一次，雖然深度著色器只寫一個數字、幾乎不吃填充率，但繪製呼叫是實打實的一倍。

Babylon 這邊開一張圖只要一行。

```ts
const depthRenderer = scene.enableDepthRenderer(
  camera,
  false,
  false,
  Texture.NEAREST_SAMPLINGMODE,
  /** 直接存視空間的 Z */
  true,
)
```

最後那個參數要打開。另一條路存的是正規化過的深度，要用就得把近遠平面再乘回去，而那組數字散在相機上，日後有人動了 `maxZ`，這裡會靜靜地算錯。存原始的 Z 值，比對時一個字都不必換算。%( ˘•ω•˘ )%

取樣模式挑最近鄰也是有原因的。浮點深度圖的雙線性取樣不是每張顯卡都支援，而我們只要那一格的值。

### 沒有東西的地方要當成無限遠

開完之後還有一行不能漏。

```ts
depthRenderer.clearColor = new Color4(camera.maxZ, 0, 0, 1)
```

存視空間 Z 時的預設底色是零，零的意思是「實體就貼在鏡頭上」。天空那一片於是變成全世界最近的東西，望向湖心的水會整片判成貼著岸。改成遠平面之後，那一片回到乾淨的水。

## 深度差就是「這裡有多淺」

有了深度圖，岸線的原理短得像一句話。

拿水面這個片元自己的深度，減掉深度圖裡同一個位置的深度，差多少就是「光要穿過多少水才碰到底」。差得少的地方就是淺灘。

先在頂點那邊把自己的深度算出來。

```glsl
varying float vShoreViewZ;

// CUSTOM_VERTEX_MAIN_END
vShoreViewZ = (view * worldPos).z;
```

這一行與 Babylon 深度著色器裡的那一行完全相同，兩邊比的才會是同一個量。

片段那邊照著螢幕座標去查圖。

```glsl
float sceneZ = texture2D(shoreDepthSampler, gl_FragCoord.xy * shoreScreen.xy).r;
float gap = max(sceneZ - vShoreViewZ, 0.0);
```

`shoreScreen.xy` 是畫面寬高的倒數。深度圖與場景畫在同一個尺寸上，所以像素座標除以畫面大小就是取樣座標，每一幀重讀一次，換視窗大小時才不會錯開。

`max` 那一刀是給水面前方的東西用的。有東西站在鏡頭與水之間時，兩者相減會是負的，夾成零之後那一段就只是滿版的白沫。

接著把距離換成濃度。

```glsl
float line = 1.0 - smoothstep(0.0, SHORELINE_WIDTH, gap);
float halo = exp(-gap / SHORELINE_GLOW_WIDTH) * 0.55;
float foam = max(line, halo) * strength;
```

兩項相加是不行的，那會讓亮線的核心過曝。取最大值之後，`line` 負責岸邊那道實心的亮帶，`halo` 鋪出外面那圈慢慢化開的暈。暈的寬度給到亮線的一倍多，白沫才有散開的樣子。

<demo-shoreline-basic />

石頭與水的交界也自己浮出一圈。這是整套做法最好用的地方，睡蓮的莖、棧道的柱子、從水裡站起來的枯木，全部不必登記，深度差自己會算。%ヽ(●`∀´●)ﾉ%

### 白沫平視過去會拉長

把範例的鏡頭壓到接近水平，同一片淺灘的白沫會整片變寬。

這是對的。

深度差量的是「沿著視線」的距離，垂直的水深只是它在正上方看的特例。斜著看過去，同樣一格深的水，光要走的路變長了，白沫自然跟著攤開。

路人：「所以低頭看是一圈細線，平視是一整片？」
鱈魚：「對，光本來就是這樣穿過水的。」

## 白沫要量化

現在的白沫是一圈平滑的漸層。

這件事在別的專案裡很好，在這裡不行。整套美術是十六格見方的像素畫，貼圖用最近鄰、法線用最近鄰、連 FXAA 都刻意關掉，那圈漸層會是全場唯一沒有階梯的東西。

一行就收得回來。

```glsl
foam = floor(foam * STEP_COUNT) / STEP_COUNT;
```

<demo-shoreline-step />

階數給零是原本的漸層，切成三四階之後白沫是一階一階退開的，與貼圖上的像素同一個節奏。階數再往上加就慢慢退回漸層。%( ´ ▽ ` )ﾉ%

### 白沫疊在哪一層

顏色要疊在漫射色上，別等到最後的成品那一層。

```glsl
// CUSTOM_FRAGMENT_UPDATE_DIFFUSE
baseColor.rgb = mix(baseColor.rgb, FOAM_COLOR, foam);
```

這個位置的顏色還沒乘上光照，所以白沫會跟著天色走。夜裡的沫是暗的、黃昏是橘的、霧裡是灰的。疊在成品上的話，那圈白會在半夜的湖面上自己發亮。

順帶一提，那個 `FOAM_COLOR` 看起來超出範圍。

```ts
const FOAM_COLOR: [number, number, number] = [1.7, 1.25, 1.05]
```

紅與綠都拉高是刻意的。這個顏色會乘上光照，而水的材質色調把光照先染成了藍，給純白出來會是一圈淡藍色的沫。把紅與綠先乘回去，落到畫面上才是白的。著色器最後有 clamp，不會過曝。

最後補一刀透明度。

```glsl
// CUSTOM_FRAGMENT_BEFORE_FRAGCOLOR
color.a = min(1.0, color.a + foam * 0.4);
```

水本身是七成二的半透明，白沫跟著半透明的話，水底的沙石會從那圈沫裡透出來。那看起來就像一池漂白過的水。%(´,,•ω•,,)%

## 漣漪是幾個槽位

岸線是靜態的，水面還缺會動的東西。

漣漪的資料結構很單純，一組固定長度的槽位，每一圈四個數字。

```ts
const RIPPLE_SLOT_COUNT = 8

/** 每四個數字一圈：世界 X、世界 Z、已經過幾秒、濃度。濃度為零代表空槽 */
const rippleList = new Float32Array(RIPPLE_SLOT_COUNT * 4)
```

丟一圈進去的時候，先找空槽，全滿就擠掉最老的那一圈。

```ts
export function emitWaterRipple(x: number, z: number, strength: number): void {
  let slotIndex = 0
  let oldestAge = -1

  for (let index = 0; index < RIPPLE_SLOT_COUNT; index++) {
    const offset = index * 4
    if (rippleList[offset + 3] === 0) {
      slotIndex = offset
      break
    }

    const age = rippleList[offset + 2]!
    if (age > oldestAge) {
      oldestAge = age
      slotIndex = offset
    }
  }

  rippleList[slotIndex] = x
  rippleList[slotIndex + 1] = z
  rippleList[slotIndex + 2] = 0
  rippleList[slotIndex + 3] = strength
}
```

擠掉最老的那一圈很安全，它本來就快淡光了。

每一幀替所有槽位加上年齡，過了壽命就把位子讓出來。

```ts
const age = rippleList[offset + 2]! + deltaSecond
rippleList[offset + 2] = age
if (age > RIPPLE_LIFETIME) {
  rippleList[offset + 3] = 0
}
```

著色器那邊每個片元走一遍八個槽位。

```glsl
float ripple = 0.0;

for (int rippleIndex = 0; rippleIndex < 8; rippleIndex++) {
  vec4 rippleEvent = rippleList[rippleIndex];
  if (rippleEvent.w <= 0.0) continue;

  float rippleDistance = length(vPositionW.xz - rippleEvent.xy);
  float ringRadius = rippleEvent.z * RIPPLE_SPEED;
  float ring = 1.0 - smoothstep(0.0, RIPPLE_WIDTH, abs(rippleDistance - ringRadius));

  ripple = max(ripple, ring * rippleEvent.w * exp(-rippleEvent.z * RIPPLE_DECAY));
}
```

`abs(距離 - 半徑)` 是「離這一圈的環有多遠」，所以環是空心的，半徑則單純隨時間長大。

這裡同樣取最大值。兩圈相加會在交會處爆出一塊白，而水面上兩道波交會時本來就只是「比較亮的那一道」。

## 誰來打圈

有了 `emitWaterRipple`，剩下的是決定誰去呼叫它。

<demo-ripple />

**雨**每一幀會算出二十幾個落點，站在池邊時那些落點多半都在水上。照單全收的話，八個槽位每一幀被覆寫一遍，每一圈都停在剛出生的那個半徑上，畫面看到的是一池不會擴散的白點。

隔三分之一秒放一圈就好。配上兩秒多的壽命，水面上同時有六七圈大小不同的環。

```ts
if (waterState.time - lastRainRippleTime < RAIN_RIPPLE_INTERVAL)
  return false

const level = getWaterLevel(waterMap, x, z)
if (level === null || Math.abs(impactY - level) > SURFACE_TOLERANCE)
  return false
```

第二刀擋掉的是「水面上方有東西」。池上的屋頂、棧道與樹冠都會擋雨，那些地方的雨滴不該讓底下的水起波。

**腳步**看的則是距離，走多遠才濺一次。

```ts
const wadeDistance = Math.hypot(
  camera.position.x - lastWadeX,
  camera.position.z - lastWadeZ,
)
if (wadeDistance < WADE_RIPPLE_DISTANCE)
  return
```

站著不動的人不該在自己腳邊持續打出一圈一圈的水波。%(´,,•ω•,,)%

判斷條件也要看高度，而且看的是「腳踩在水面附近」。整個人沉下去之後水面在頭頂，那時該有的是頭頂的波紋。

```ts
const footY = camera.position.y - PLAYER_EYE_HEIGHT
const level = getWaterLevel(waterMap, camera.position.x, camera.position.z)
if (level === null || footY > level + 0.2 || footY < level - 1.4)
  return
```

## 完整實作

專案裡的 `water-surface.ts` 是一個 `MaterialPluginBase`，只掛在水面那一層的材質上。材質外掛的完整機制見 EP05，這裡只用它的四個切入點。

1. `getSamplers` 報上深度圖的取樣器名字
2. `getUniforms` 開一組 `vec4`，時間、強弱、螢幕大小與漣漪陣列都在裡面
3. `bindForSubMesh` 每一幀把 `waterState` 的內容寫進去
4. `getCustomCode` 注入頂點與片段那幾段

有一件事跟這篇的示範不一樣。專案裡的水面是一顆一顆的方塊，六個面都在，而岸線與漣漪都照世界的 XZ 座標算，畫到側面上會變成一條條垂直的抹痕。

法線幫不上忙，水是 flat shaded 的，六個面的法線都被改成朝上。所以改看頂點的區域座標。

```glsl
// 頂點
vWaterTopFace = step(TOP_FACE_THRESHOLD, position.y);

// 片段
if (vWaterTopFace > 0.9) {
  // 岸線與漣漪都在這裡面
}
```

門檻要算出來，別寫死。水面那一層的網格是一顆矮掉八分之一格的方塊，建好之後又往下烘了半個落差，而那個落差是與碰撞共用的常數。寫死的話，哪天有人調了它，這裡會靜靜地失效，失效的樣子是「岸線整片不見」，不會有任何錯誤訊息。%(›´ω`‹ )%

最後是畫質。低畫質整套收掉，強度歸零之後著色器裡那幾段全部跳過，等於這個外掛不存在。

```ts
const isEnabled = devToggle.waterShoreline && preset.value.waterShoreline
waterState.shorelineStrength = isEnabled ? SHORELINE_STRENGTH : 0
```

深度預繪那一趟在低畫質本來就沒開，沒有圖可以查，岸線自然也留不住。

## 總結 🐟

以上程式碼可以[在此取得](https://github.com/Codfisher/cod-aquarium/tree/main/content/aquarium/minespace)

- WebGL 讀不到主畫面的深度緩衝區，深度圖只能自己再畫一趟
- 深度算繪不畫半透明的東西，水面因此問得到自己背後那塊沙地
- 深度差是沿著視線量的，同一片淺灘平視過去會整片拉長
- 白沫要量化成幾階，才跟得上像素風的節奏
- 漣漪是幾個固定的槽位，滿了就擠掉最老的那一圈
