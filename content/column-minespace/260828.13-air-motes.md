# Minespace - EP13：空氣顆粒

大家好，我是鱈魚。

前幾章把天色、雲影、霧氣都做完了，畫面該有的東西看起來都有了。可是走進去晃一圈，總覺得哪裡怪怪的。%(´･_･`)%

怪在空氣。

## 為什麼空氣裡要有東西

這個世界的空氣一直是空的。霧是一層跟著距離算出來的數學，光束是一道後製的後處理，兩者之間什麼都沒有。

於是方塊與方塊之間那段距離，畫面上是完全透明的。人的眼睛拿不到任何線索，只好把它讀成真空。

現實裡的空氣從來不是這樣。花粉、灰塵、水氣一直懸在裡面，陽光斜進來的時候整條光路都看得見。人之所以「看得見陽光」，正是因為空氣裡有東西擋在光的路上。

<demo-motes-presence />

關掉顆粒的時候，柱子與柱子之間只有一片乾淨的透明。撒上一把之後，那段距離忽然量得出來了。%ヽ(●`∀´●)ﾉ%

鱈魚：「所以只要在空中隨便灑一堆白點就好了嘛。」
路人：「隨便灑會變成雜訊好嗎。%(´・ω・`)%」
鱈魚：「好啦，數量、大小與速度都有講究。」

## 第一步：一組最小的粒子系統

Babylon 的 `ParticleSystem` 是現成的，開一份出來就能跑。

```ts
const emitter = new Vector3(0, 2, 0)

const moteSystem = new ParticleSystem('air-mote', 240, scene)
moteSystem.emitter = emitter
moteSystem.start()
```

建構子的第二個參數是這組系統最多養幾顆。這個數字一開就吃掉一份頂點緩衝，之後改不了，所以它是上限而不是目標值。

`emitter` 可以給網格，也可以給一個座標。這裡給座標，因為浮塵不從任何東西上噴出來，它就是散在空中。

### 顆粒生在哪裡

`emitter` 只決定中心點，範圍要另外給。

```ts
moteSystem.minEmitBox = new Vector3(-11, -2.5, -11)
moteSystem.maxEmitBox = new Vector3(11, 4, 11)
```

這兩個角落是**相對於發射器**的偏移，夾出來的長方體就是顆粒出生的範圍。

上下不對稱是刻意的。發射器等一下要綁在鏡頭上，而鏡頭的高度是眼睛，往下兩格半是腳邊、往上四格是頭頂。蹲著看與站著看都要有東西飄。

<figure-emit-box />

### 一顆顆粒的一生

每顆顆粒出生時領到一份隨機的參數，之後就照著它自己走完。

```ts
moteSystem.minSize = 0.04
moteSystem.maxSize = 0.08
moteSystem.minLifeTime = 6
moteSystem.maxLifeTime = 13
moteSystem.minEmitPower = 0.04
moteSystem.maxEmitPower = 0.16
```

大小給到將近一個像素就好。再大一點就成了雪，這個尺寸在畫面上只佔幾個像素，看得見卻不搶戲。空氣感本來就該讓人察覺不到自己在看什麼。%( ˘•ω•˘ )%

壽命給六到十三秒是配著發射率算的。同時飄在空中的數量大約是「發射率乘上平均壽命」，一秒二十六顆配上十秒的壽命，畫面上長期維持在兩百多顆。

### 顏色的三個欄位

```ts
moteSystem.color1 = new Color4(1, 0.94, 0.72, 0.5)
moteSystem.color2 = new Color4(0.94, 0.9, 0.78, 0.28)
moteSystem.colorDead = new Color4(1, 0.94, 0.72, 0)
```

`color1` 與 `color2` 是出生時隨機挑的兩端，每顆在兩者之間取一個值，一群顆粒因此不會整齊得像同一批貨。

`colorDead` 是壽命走完時的顏色。透明度收到零，顆粒才會慢慢淡掉。少了這一行，十三秒一到就是一顆白點憑空消失，那一下非常醒目。

### 怎麼飄

```ts
moteSystem.gravity = new Vector3(0, 0.012, 0)
moteSystem.direction1 = new Vector3(-0.06, 0.02, -0.06)
moteSystem.direction2 = new Vector3(0.06, 0.09, 0.06)
```

重力給了一個往**上**的極小值。灰塵在靜止的空氣裡是懸著的，幾乎不會落下，讓它慢慢往上飄一點點，再配上左右的微幅擾動，「空氣本身在動」的感覺才出得來。

`direction1` 與 `direction2` 同樣是隨機的兩端，配上 `emitPower` 就是每顆的初速。

### 混合模式

```ts
moteSystem.blendMode = ParticleSystem.BLENDMODE_STANDARD
```

浮塵走標準的半透明混合。它自己不發光，看得見是因為有光照在上面，所以該有的行為是蓋在背景上而不是加上去。

<demo-motes-shape />

三個滑桿一起玩就看得出關係。範圍拉大而發射率不動，密度立刻稀掉；壽命拉長則是同一批顆粒撐得更久，畫面上的總數跟著上升。%(⊙ o ⊙)%

順帶一提，拉動滑桿之後畫面要過幾秒才整批換過來。發射盒與壽命只影響還沒生出來的那些，已經在空中的顆粒照著自己出生時那一份設定走完。

## 第二步：顆粒要跟著鏡頭走

現在有個很實際的狀況。

顆粒撒在世界原點周圍那一圈，人往前走十幾格就走出去了，身邊立刻乾乾淨淨。而整個世界撒滿顆粒是不可能的，遠處那些在畫面上小到看不見，卻照樣要進每一幀的更新與排序。

解法是把發射點綁在鏡頭上，只在身邊十來格內撒。

```ts
moteSystem.emitter = emitter

scene.onBeforeRenderObservable.add(() => {
  emitter.copyFrom(camera.position)
})
```

關鍵在於**只有發射點跟著走**。顆粒撒出去之後就留在世界座標上，人往前走，它們自然落在身後，幾秒之後壽命到了再從新的位置生出來。

於是走到哪裡身邊都有東西在飄，卻不會有「一團顆粒黏著鏡頭跑」那種假。

<figure-emitter-follow />

### 不必每一幀對齊

```ts
const RECENTER_INTERVAL = 0.25

recenterElapsed += deltaTime
if (recenterElapsed >= RECENTER_INTERVAL) {
  recenterElapsed = 0
  emitter.copyFrom(camera.position)
}
```

發射盒有二十二格見方，走路一秒也才五六格。四分之一秒對齊一次，畫面上完全看不出落差，省下來的是每一幀那幾次向量複製。

<demo-motes-follow />

鏡頭沿著那排柱子來回。發射點釘在原地時，走到底就只剩一片空曠；跟著鏡頭走則是整段路上都有東西在飄。%( •̀ ω •́ )✧%

路人：「顆粒不會在世界邊界那裡穿幫嗎？」
鱈魚：「會，所以另外給了一個能見度的參數，貼近邊界時發射率直接收到零。」

## 第三步：白天的灰塵與夜裡的螢火

同一組骨架換一套參數，就長成完全不同的兩種。

夜裡的空氣不該有浮塵。浮塵之所以看得見是因為有光照在它身上，天黑了那道光就沒了，一群還在發亮的顆粒只會像浮在畫面上的雜訊。

夜裡該有的是螢火。

```ts
const fireflySystem = new ParticleSystem('air-firefly', 64, scene)

fireflySystem.blendMode = ParticleSystem.BLENDMODE_ADD
fireflySystem.minEmitBox = new Vector3(-8.8, -2.5, -8.8)
fireflySystem.maxEmitBox = new Vector3(8.8, 1.2, 8.8)
```

差別有三個。

**混合模式改成相加**。螢火自己會發光，顏色要加到畫面上。它也就這樣繞開了材質那道亮度上限，加上去的顏色不吃任何 clamp，一點螢火在深夜的草間才真的會亮。

**範圍收窄、也不往高處去**。螢火貼著草叢飛，上界只給到一格二。

**亮度用漸層走完一生**。

```ts
fireflySystem.addColorGradient(0, FIREFLY_COLOR_DIM, FIREFLY_COLOR_DIM)
fireflySystem.addColorGradient(0.25, FIREFLY_COLOR, FIREFLY_COLOR)
fireflySystem.addColorGradient(0.6, FIREFLY_COLOR, FIREFLY_COLOR)
fireflySystem.addColorGradient(1, FIREFLY_COLOR_DIM, FIREFLY_COLOR_DIM)
```

`addColorGradient` 的第一個參數是壽命走到幾成，後兩個是那一刻的顏色範圍。四個停點畫出「亮起、撐住、熄掉」的曲線，一整條壽命剛好走完一次明滅。

一群螢火各自的壽命又不一樣，整片看過去就是此起彼落地閃。%(๑´ㅂ`๑)%

### 兩邊怎麼交班

發射率各自跟著白晝的程度走。

```ts
const FIREFLY_DAY_THRESHOLD = 0.35

moteSystem.emitRate = MOTE_EMIT_RATE * dayRatio

const nightRatio = Math.max(0, 1 - dayRatio / FIREFLY_DAY_THRESHOLD)
fireflySystem.emitRate = FIREFLY_EMIT_RATE * nightRatio
```

浮塵直接乘上白晝的程度，天亮就有、天黑就沒有。

螢火反過來拿 `1 - dayRatio` 推，而且除上一個門檻。天要暗到三成五以下牠們才開始現身，黃昏那段時間並不會一邊還有夕陽一邊已經滿天螢火。

<demo-motes-daynight />

把滑桿從右拉到左，浮塵先收乾淨，天再暗一點草間才亮起幾點綠光。

洞穴裡則是第三種空氣。那裡永遠是暗的，但有燈火，所以塵照樣看得見；顏色換成冷灰，一點暖都不留。

```ts
const litRatio = Math.max(dayRatio, caveRatio * 0.7)
moteSystem.emitRate = MOTE_EMIT_RATE * litRatio

Color4.LerpToRef(POLLEN_COLOR, CAVE_COLOR, caveRatio, moteSystem.color1)
```

顏色就地插值，不重建系統。連已經活著的顆粒都會跟著換色，走進洞口那幾步是連續的。

<demo-motes-cave />

洞穴程度拉到底，發射率也只到日間滿檔的七成。塵靠燈火撐場面，亮度本來就到不了太陽那個等級。%(・ω・)%

## 第四步：數量跟著畫質分級

粒子是逐顆更新的，數量直接乘在每一幀的成本上。

```ts
function scaleParticleCount(baseCount: number) {
  return Math.max(1, Math.round(baseCount * preset.value.particleRatio))
}

airMotes = createAirMotes({
  scene,
  moteCount: scaleParticleCount(220),
  fireflyCount: scaleParticleCount(48),
})
```

每一種粒子的基準值都照著「最高畫質該有多密」調，各級之間的差別只是密度，所以這裡統一乘上一個倍率。等級增減時這一段完全不必動。

低畫質給零點三六倍，兩百二十顆收成八十顆。空氣感淡了一點，畫面照樣成立。

還有一件事要記得。

```ts
moteSystem.applyFog = true
```

平常那個距離連最濃的霧都還沒開始作用，這一項確實換不到任何看得出來的差別。世界邊界那道白幕是例外，它半格外就起霧、六格外全白，顆粒整片都落在裡面。

不吃霧的話，四周白成一片時這些顆粒依然清清楚楚地浮在白幕前面，跨過邊界就整批換了一組。停止發射只管得到還沒生出來的那些，已經飄在空中的要等壽命走完，而那段時間人早就走到邊界了。%(›´ω`‹ )%

## 完整實作

專案裡 `air-motes.ts` 做的就是這幾件事。

1. 開兩組系統，浮塵走標準混合、螢火走相加混合
2. 發射點每四分之一秒對齊一次鏡頭
3. 依白晝程度與洞穴程度算出兩邊各自的發射率
4. 顏色隨洞穴程度插值，走進洞口是連續的

```ts
export function createAirMotes({ scene, moteCount, fireflyCount }: CreateAirMotesParams) {
  const moteEmitter = new Vector3()
  const fireflyEmitter = new Vector3()

  // ...兩組系統的設定

  return {
    update(camera, dayRatio, caveRatio, visibleRatio) {
      // 對齊發射點、更新顏色與發射率
    },
    dispose() {
      moteSystem.dispose()
      fireflySystem.dispose()
    },
  }
}
```

`visibleRatio` 自己一個參數，不折進 `dayRatio` 裡。螢火是拿 `1 - dayRatio` 反推的，把「此刻不該看見」折進白晝的程度，對浮塵是關掉、對螢火卻是開到最大。大白天走到世界邊界會召出一群螢火。%(๑•́ ₃ •̀๑)%

## 總結 🐟

以上程式碼可以[在此取得](https://github.com/Codfisher/cod-aquarium/tree/main/content/aquarium/minespace)

- 空氣裡沒有東西的時候，眼睛只能把那段距離讀成真空
- `emitBox` 是相對於發射器的偏移，上下不對稱是為了配合眼睛的高度
- 只讓發射點跟著鏡頭走，顆粒留在世界座標上，才不會有一團東西黏著人跑
- 浮塵走標準混合、螢火走相加混合，同一套骨架換參數就是兩種空氣
- 數量統一乘上畫質的倍率，等級增減時這段程式碼不必動
