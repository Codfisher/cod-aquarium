# Minespace - EP06：天空、日月與雲

大家好，我是鱈魚。

這一章來看抬頭看得到的所有東西。%੭ ˙ᗜ˙ )੭%

## 先說一個失敗

Babylon 內建的 `SkyMaterial` 走的是 Preetham 大氣散射模型，那是業界標準做法。

用起來卻很慘。%(´థ‸థ)%

那套模型以「視線穿過大氣多長」決定顏色。抬頭看天頂是 8400，視線放平看地平線卻暴衝到 300000。

三十六倍之後散射早已徹底飽和，地平線必然是一整片沒有層次的純白。

更糟的是那片白貼著色調映射的上限，壓曝光也壓不下來，只會讓天頂跟著變暗、反差更大。

天邊那道刺眼的白線就是這樣來的。%(›´ω`‹ )%

路人：「那怎麼辦？」
鱈魚：「不算了，用調的。%( ˘•ω˘ )%」

## 自己畫一片天

改成自己寫著色器之後，天色是調出來的而不是算出來的。

這是實際跑起來的樣子，兩個開關對應下面要講的兩個設計。

<demo-sky-gradient />

拉時刻走一輪，日出的丁香紫、正午的藍、日落的橘與背後那道反霞都在裡面。%(*´∀`)~♥%

天空罩是一個以原點為中心的方盒，又設了 `infiniteDistance` 跟著鏡頭走，所以頂點的區域座標本身就是「從眼睛看出去的方向」。

```glsl
attribute vec3 position;
uniform mat4 worldViewProjection;
varying vec3 vDirection;

void main() {
  vDirection = position;
  gl_Position = worldViewProjection * vec4(position, 1.0);
}
```

省下一次矩陣運算，很划算。%( •̀ ω •́ )✧%

### 三段顏色，兩條曲線

```glsl
float upward = clamp(direction.y, 0.0, 1.0);

float hazeBlend = 1.0 - pow(1.0 - upward, HAZE_FALLOFF);
float zenithBlend = 1.0 - pow(1.0 - upward, ZENITH_FALLOFF);
vec3 upperColor = mix(midColor, zenithColor, zenithBlend);
vec3 color = mix(horizonColor, upperColor, hazeBlend);
```

只有天邊與天頂兩個顏色時，天空是一條單調的漸層。

中間多一個顏色，日出的丁香紫與日落的洋紅才有地方待著。那是把橘色的天邊接到藍色的天頂之間的那一段，也是一片天之所以好看的原因。%(*´∀`)~♥%

兩條曲線各司其職。

```glsl
const float HAZE_FALLOFF = 6.0;
const float ZENITH_FALLOFF = 1.6;
```

霧色收得快，只留在地平線上方五度左右；中空色到天頂則慢慢爬，鋪滿整片天。

`HAZE_FALLOFF` 若給小了，那片白會從地平線一路淹上來十幾度，在藍天底下鋪成一條又寬又亮的白帶。對，就是 Preetham 那條白線又回來了。

### 太陽的暖光要用混色不能用相加

```glsl
float halo = pow(towardSun, 18.0) * 0.55 + pow(towardSun, 2.5) * 0.45 * lowSky;
color = mix(color, glowColor, clamp(halo * glowStrength, 0.0, 1.0));
```

兩層疊起來，緊的那層是太陽外圍那一圈亮，鬆的那層鋪滿太陽那半邊天。

鬆的那層還要隨高度收掉，霞光才會積在天邊而不是糊上天頂。

重點是最後那一行用 `mix` 而不是 `+`。

相加的話，天邊本來就接近純白的霧色再加上一團暖光就會衝破 1.0，太陽貼近地平線時整片天糊成一大團白，霞色反而不見了。

混色有天花板，再濃也只會濃到霞光本身的顏色。於是日落是「整片天燒成橘色」而不是「整片天燒成白色」。%ヽ(●`∀´●)ﾉ%

### 反霞

這是我最喜歡的一段。%(๑•̀ㅂ•́)و✧%

```glsl
float awayFromSun = max(-dot(direction, sunDirection), 0.0);
float counter = pow(awayFromSun, 3.0) * lowSky * COUNTER_RATIO;
color = mix(color, counterColor, clamp(counter * glowStrength, 0.0, 1.0));
```

日出與日落時，背對太陽的天邊會浮起一道玫瑰色的帶子。那是被地平線下的陽光染紅、又還沒被地球影子吃掉的那一層大氣。

真實的天空裡最美的一段往往不在太陽那一邊，而在身後。

濃度直接跟著霞光走，正午霞光收到剩一點點，這道帶子自然也就不見了。

### 打散色階

```glsl
float noise = fract(sin(dot(gl_FragCoord.xy, vec2(12.9898, 78.233))) * 43758.5453);
color += (noise - 0.5) / 255.0;
```

整片天是一條很長的漸層，八位元的色階在上面會顯出一圈圈的等高線。

加上半個色階的雜訊就看不出來了。

::: tip
EP01 提過後製管線也開了 dithering。兩者不衝突，這裡處理的是天空自己那一層，管線那邊處理的是色調映射之後重新量化的那一次。
:::

### 兩個必設的旗標

```ts
material.disableDepthWrite = true
material.fogEnabled = false
```

天空罩邊長只有 260，跟著鏡頭走，所以永遠在 130 格外。照常寫深度的話，比它遠的東西全部會被擋掉。

世界之外那片白沙鋪了一千多格，超過 130 格的部分會整片消失。%(⊙ o ⊙)%

不吃霧則是因為天空本來就不該按距離褪色。

## 方形的太陽與月亮

大氣散射算出來的太陽是一顆帶光暈的圓球，那太寫實了。

方塊世界的天上不該有圓的東西。%( ˘•ω•˘ )%

```ts
function createSunDisc(scene: Scene) {
  const size = 16
  const texture = new DynamicTexture(SUN_DISC_NAME, { width: size, height: size }, scene, false, Texture.NEAREST_SAMPLINGMODE)
  const context = texture.getContext() as CanvasRenderingContext2D
  context.fillStyle = 'rgba(255, 250, 230, 1)'
  context.fillRect(0, 0, size, size)
  texture.update()

  const material = createSkyBodyMaterial(`${SUN_DISC_NAME}-material`, texture, scene)
  material.emissiveColor = new Color3(1, 1, 1)

  const disc = MeshBuilder.CreatePlane(SUN_DISC_NAME, { size: 15 }, scene)
  disc.material = material
  disc.position = SUN_DIRECTION.scale(-110)
  disc.infiniteDistance = true
  disc.billboardMode = Mesh.BILLBOARDMODE_ALL

  return material
}
```

### 貼圖要掛在 diffuseTexture

這件事很重要，卡了我不少時間。%(›´ω`‹ )%

Babylon 的著色器裡自發光是「顏色加上貼圖」。

```text
emissiveColor = vEmissiveColor + texture * level
```

把貼圖掛在 `emissiveTexture` 的話，顏色調成黑色貼圖照樣全亮（白天星星掛在藍天上），調成白色則是整片加上一層白（夜裡整個天空被灌成一片灰）。

關掉光照之後，diffuse 那條路才是我們要的乘法。

```text
finalDiffuse = clamp(emissiveColor) * 貼圖
```

於是自發光的顏色就成了一個乾淨的乘數，淡入淡出與染色都靠它。%( •̀ ω •́ )✧%

<demo-sky-body />

把開關切到 `emissiveTexture` 那一路，兩個亮度滑桿立刻整個失效，太陽、月亮與星星全部釘在滿檔。大白天掛著滿天星星，就是這麼來的。%(・∀・(・∀・(・∀・*)%

```ts
function createSkyBodyMaterial(name: string, texture: DynamicTexture, scene: Scene): StandardMaterial {
  const material = new StandardMaterial(name, scene)
  material.diffuseTexture = texture
  material.diffuseColor = new Color3(0, 0, 0)
  material.specularColor = new Color3(0, 0, 0)
  material.disableLighting = true
  material.fogEnabled = false
  material.backFaceCulling = false
  material.alphaMode = Constants.ALPHA_ADD
  /** 相加混合要走半透明那條路才生效，alpha 得比 1 小一點點 */
  material.alpha = 0.999
  /** 天體是天空的一部分，不留下深度，雲才蓋得住它 */
  material.disableDepthWrite = true

  return material
}
```

`alpha = 0.999` 也是個小坑，相加混合要 Babylon 把它排進半透明佇列才生效。

### 月亮要看得出是月亮

太陽是一片沒有細節的白，月亮則要有表面。

```ts
/** 底色：偏冷的月白 */
context.fillStyle = 'rgb(226, 233, 250)'
context.fillRect(0, 0, size, size)

/** 月海：暗一階的幾塊斑 */
context.fillStyle = 'rgb(196, 206, 231)'
const seaList: [number, number, number, number][] = [
  [2, 3, 5, 4],
  [8, 2, 3, 3],
  [10, 7, 4, 5],
  [1, 9, 3, 3],
  [5, 11, 4, 3],
  [12, 1, 2, 2],
]
for (const [x, y, width, height] of seaList) {
  context.fillRect(x, y, width, height)
}
```

位置與大小刻意不規則，也刻意不對稱。排得整齊會變成一顆骰子，均勻散開又會變成雜訊。

幾塊大的湊在一邊、幾塊小的散在另一邊，那才像月面。%(*´∀`)~♥%

再暗一階的坑落在月海裡面，表面就有第三層深度；右下角壓暗一層，月亮才有一點球的錯覺，卻又沒有真的把它畫成圓。

## 星空

一張隨機點上星點的貼圖，貼在一個罩住鏡頭的盒子上，用相加混合疊在天空前面。

黑色的底加上去等於沒加，只有星點會亮。%( •̀ ω •́ )✧%

const random = createSeededRandom('minespace-star')
const starCount = 460
for (let index = 0; index < starCount; index++) {
  const x = Math.floor(random() * size)
  const y = Math.floor(random() * size)
  /** 大部分是暗的小星，偶爾幾顆亮而大的 */

## 雲

Minespace 的雲是實際的方塊，不是貼圖，所以看得到厚度與側面。

### 用細胞自動機長出雲

```ts
const patternCount = 18
let cellList = Array.from({ length: patternCount * patternCount }, () => random() < 0.34)

/** 平滑幾輪，讓零散的格子聚成一朵一朵的雲 */
for (let pass = 0; pass < 4; pass++) {
  const nextList = cellList.slice()
  for (let x = 0; x < patternCount; x++) {
    for (let z = 0; z < patternCount; z++) {
      let neighborCount = 0
      for (let offsetX = -1; offsetX <= 1; offsetX++) {
        for (let offsetZ = -1; offsetZ <= 1; offsetZ++) {
          if (offsetX === 0 && offsetZ === 0)
            continue
          if (readCell(cellList, x + offsetX, z + offsetZ))
            neighborCount++
        }
      }
      nextList[z * patternCount + x] = neighborCount > 4
        || (neighborCount === 4 && readCell(cellList, x, z))
    }
  }
  cellList = nextList
}
```

初始填充率是挑過的。平滑規則會把孤立的格子吃掉，起始值太低整片天最後只剩零星幾朵，一抬頭常常什麼都沒有。

填到接近一半，收斂後才是「多雲」該有的覆蓋率。

但平滑會讓相鄰的雲黏成一片，覆蓋率一高就連成一大塊蓋住半邊天。

所以再跑一輪，標記每一團的大小，只對超標的那幾團由外往內剝一圈。

```ts
for (let pass = 0; pass < 6; pass++) {
  const sizeList = labelComponentSizeList(cellList)
  if (sizeList.every((size) => size <= MAX_CLOUD_CELL_COUNT))
    break

  const nextList = cellList.slice()
  for (let x = 0; x < patternCount; x++) {
    for (let z = 0; z < patternCount; z++) {
      const index = z * patternCount + x
      if (sizeList[index]! <= MAX_CLOUD_CELL_COUNT)
        continue

      /** 只剝外圍那一圈 */
      const isEdge = [[1, 0], [-1, 0], [0, 1], [0, -1]]
        .some((step) => !readCell(cellList, x + step[0]!, z + step[1]!))
      if (isEdge) {
        nextList[index] = false
      }
    }
  }
  cellList = nextList
}
```

大塊會縮小，細長的一團也會自然斷成幾朵。%ヽ(●`∀´●)ﾉ%

### 圖樣的週期是硬性條件

```ts
const patternCount = 18
const CLOUD_CELL_SIZE = 14
```

18 × 14 = 252，剛好等於世界寬度。

這是循環世界的硬性條件。玩家跨過邊界時位置會平移一整個世界的距離，雲的圖樣若不是同一個週期，整片天會在那一瞬間換一副樣子。

而雲是全場唯一不吃霧氣、藏不住的東西。%( ˘•ω•˘ )%

### 整片雲是一個網格

原本每一格都是獨立的方塊，相鄰兩格之間那兩片牆照樣畫出來。

隔著半透明的雲面看過去就是一格一格的框線交錯在一起，看起來像用積木拼的而不是一朵雲。%(・∀・(・∀・(・∀・*)%

所以照方塊世界的面剔除做法，鄰居是空的才畫那一面。

```ts
if (!isFilled(x - 1, z)) {
  addQuad([
    [minX, halfThickness, minZ],
    [minX, -halfThickness, minZ],
    [minX, -halfThickness, maxZ],
    [minX, halfThickness, maxZ],
  ], [-1, 0, 0])
}
```

頂面與底面一定畫，四個側面看鄰居。

<demo-cloud-mesh />

平滑輪數拉到 0 就是一片沒有形狀的雜訊，拉到 4 才聚成一朵一朵；單朵上限放大則會黏成一大塊蓋住整片天。

面剔除關掉之後，那些框線就是文章說的「像用積木拼的」。%(・∀・(・∀・(・∀・*)%

### 遠處的雲要化進天色

雲層往四面各鋪一千一百格。從眼睛看出去，越遠的雲落在越低的仰角上，最遠那一圈只剩不到五度。

幾百朵雲全擠在地平線上方那一小條裡，疊成一道白得發亮的帶子。%(´థ‸థ)%

而雲又是全場唯一不吃霧氣的東西，那道帶子連淡都不會淡。

解法是讓雲自己隨距離化進天邊的顏色。

```glsl
varying float vDistance;

void main() {
  float haze = smoothstep(fadeStart, fadeEnd, vDistance);
  vec3 color = mix(cloudColor, hazeColor, haze);
  gl_FragColor = vec4(color, cloudAlpha);
}
```

視空間的原點就是眼睛，所以頂點著色器直接取長度就好。

```glsl
vDistance = length((worldView * vec4(position, 1.0)).xyz);
```

```ts
const CLOUD_FADE_START = 320
const CLOUD_FADE_END = 900
```

<demo-cloud-fade />

鏡頭壓在地平線附近，關掉淡出之後那道白得發亮的帶子就出現了。%(´థ‸థ)%

抬頭看得到的那一大片雲完全不受影響，只有貼著地平線那一條被收掉。

### 飄移

```ts
const driftPeriod = patternCount * CLOUD_CELL_SIZE
let elapsed = 0
scene.onBeforeRenderObservable.add(() => {
  elapsed += scene.getEngine().getDeltaTime() / 1000
  cloudMesh.position.x = (elapsed * CLOUD_DRIFT_SPEED) % driftPeriod
  /** 地上的雲影要跟著一起飄 */

```

圖樣每 `patternCount` 格重複一次，位移滿一個週期就回到完全相同的排列，所以直接取餘數歸零，看不出接縫。%( •̀ ω •́ )✧%

### 太陽怎麼繞

```ts
const angle = (time - 0.25) * Math.PI * 2
const alongRise = Math.cos(angle)
const alongNoon = Math.sin(angle)

sample.sunPosition.set(
  SUNRISE_AXIS.x * alongRise + NOON_AXIS.x * alongNoon,
  SUNRISE_AXIS.y * alongRise + NOON_AXIS.y * alongNoon,
  SUNRISE_AXIS.z * alongRise + NOON_AXIS.z * alongNoon,
)
```

兩個軸必須互相垂直，太陽才是沿著一個正圓在天球上走。不垂直的話軌跡會歪成橢圓，日出與日落的高度也對不起來。

所以正午軸是由日出方位轉九十度算出來的，垂直這件事是結構保證的。%( •̀ ω •́ )✧%

正午的仰角約五十八度，不是正頂上。一整片白沙被垂直的頂光照著會平得像一張紙，留一點斜度，方塊的三個面才拉得開亮度。

### 換邊的那一刻

平行光在日夜交替時要換邊，白天從太陽來、夜裡從月亮來，而兩者正好是相反的方向。

切換的瞬間所有影子會整個翻過去。%(⊙ o ⊙)%

```ts
const HORIZON_GATE_HEIGHT = 0.1

/** 貼著地平線的那一小段把平行光關掉 */
sample.lightIntensity *= smoothRange(Math.abs(sample.sunHeight), 0, HORIZON_GATE_HEIGHT)
```

讓平行光在太陽貼近地平線的那一小段淡到全暗，換邊就發生在沒有光的時候。

那幾秒的亮度由環境光撐著，本來就是日出前後天亮著卻沒有直射光的樣子。

### 夜裡的補光

這一段與 EP02、EP03 埋的伏筆連起來了。%(๑•̀ㅂ•́)و✧%

```ts
const NIGHT_FILL_COLOR: [number, number, number] = [0.15, 0.18, 0.27]
```

方塊光是烘進實例顏色的，而實例顏色在著色器裡是乘在貼圖上。最終亮度等於「場景光照 × 貼圖 × 實例顏色」。

燈火只是把照到的那幾面放大到兩倍多的反照率。白天光照是 1、看得出來；夜裡光照只剩四分之一，兩倍多乘完還是暗的，烘進去的燈光就跟著夜色一起被壓掉了。

補光走的是場景的 `ambientColor`，也就是加在光照上、再乘上反照率的那一項。所以它一進來，燈火照到的地方會照比例亮起來。

那圈光才真的照得出去。%ヽ(●`∀´●)ﾉ%

還記得 EP03 那一行嗎？

```ts
material.ambientColor = new Color3(1, 1, 1)
```

材質這一項預設是黑的，不設成白色的話這整條路都不通。

<demo-night-fill />

把白晝程度拉到 0，再把補光關掉。燈還亮著，但它照出去的那一圈整個沉進夜色裡，牆上什麼都看不到。%(›´ω`‹ )%

補光打開的瞬間，那圈光就浮出來了。而它並不是「畫面變亮」而已，把方塊光也關掉比對一下就知道，兩者是乘在一起的。

### 色相要走短邊

```ts
function lerpHue(from: number, to: number, ratio: number): number {
  const delta = ((to - from) % 360 + 540) % 360 - 180

  return (from + delta * ratio + 360) % 360
}
```

色相是繞一圈的角度，直接線性補間會從橘繞過整個色環到藍。%(・∀・(・∀・(・∀・*)%

### 日出方位會慢慢漂

最後一個小巧思。

```ts
const AZIMUTH_DRIFT_PER_DAY = 9

export function advanceSunriseDrift(dayStep: number): void {
  driftAzimuth = (driftAzimuth + dayStep * AZIMUTH_DRIFT_PER_DAY) % 360
  applySunAxes()
}
```

一天過去，日出方位往前挪九度，四十天繞回原處。

數字挑得很小是刻意的。一天之內只挪九度，站著看不出來，但隔幾天回來，日出已經換到另一叢樹的後面了。

這種「說不上來哪裡不同」正是想要的。%(*´∀`)~♥%

拖時間軸不算數，那是翻頁去看某個時刻，不是真的過了一天。
