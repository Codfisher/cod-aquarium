# Minespace - EP04：接觸硬化陰影

大家好，我是鱈魚。

前兩章都在加光，這一章換個方向，來擋光。%( •̀ ω •́ )✧%

目標很具體。鳥居的柱子立在白沙上，柱腳那一段影子要是銳利的，往上到橫樑那一段才慢慢化開。這樣柱子才真的「站」在地上。

## 影子從哪裡來

陰影貼圖的原理只有一句話。

從光源的位置往場景看一次，把每個方向上「最近的東西有多遠」記下來。之後畫地面的時候，拿這一點到光源的距離跟那張表比對，比表上的數字遠就代表前面有東西擋著。

```text
1. 從光源的角度算繪一次，只留深度 → 陰影貼圖
2. 正常算繪時把每個片元換算到光源空間
3. 比對深度，較遠的就是在影子裡
```

Babylon 把這整套包成 `ShadowGenerator`，建起來只要兩行。

```ts
const shadowGenerator = new ShadowGenerator(1024, sunLight)
shadowGenerator.addShadowCaster(pillar)
```

再幫要接收影子的網格打開開關。

```ts
ground.receiveShadows = true
```

路人：「這樣就好了？」
鱈魚：「畫面上會有影子沒錯，但接下來六個設定每一個都會讓它變得完全不一樣。」

## 第一步：平行光與正交投影

太陽在一億五千萬公里外，射到這座庭園的光線可以當成互相平行。所以光源用 `DirectionalLight`。

```ts
const sunLight = new DirectionalLight('sun', new Vector3(0.58, -0.66, -0.48), scene)
```

平行光沒有「位置」的概念，只有方向。但投影用的鏡頭需要位置，所以要沿著光線的反方向退開一段。

```ts
sunLight.position = new Vector3(-0.58, 0.66, 0.48).scale(SHADOW_LIGHT_DISTANCE)
```

退多遠？退到把場景裡最高的東西整個含進去為止。這個世界最高的岩體大約四十格，光源退九十格綽綽有餘。

接著是投影範圍。平行光走的是正交投影，範圍由四個數字決定。

```ts
sunLight.autoUpdateExtends = false
sunLight.orthoLeft = -SHADOW_HALF_EXTENT
sunLight.orthoRight = SHADOW_HALF_EXTENT
sunLight.orthoTop = SHADOW_HALF_EXTENT
sunLight.orthoBottom = -SHADOW_HALF_EXTENT

sunLight.shadowMinZ = 10
sunLight.shadowMaxZ = SHADOW_LIGHT_DISTANCE + 80
```

`autoUpdateExtends` 要關掉。開著的話 Babylon 每幀會依所有投影者重算範圍，視野裡多一棵樹範圍就跳一次，影子邊緣跟著抖。

關掉之後 `autoCalcShadowZBounds` 也跟著失效，深度範圍得自己給。給法就是光源退開的距離加上世界的高度，前後各留一點餘裕。

投影範圍是這一章最重要的數字。一張 2048 的貼圖攤在八十格見方上，每一格地分到二十一個紋素；攤在三百五十格見方上，每一格只剩十一個。同樣的成本，影子的銳利度差了一倍。

## 第二步：darkness 與那道 clamp

`darkness` 是「影子裡還留多少光」，0 是全擋、1 等於沒有影子。

```ts
shadowGenerator.darkness = 0.05
```

直覺上給 0.5 很合理，影子淡一點才自然。但在這座白沙庭園上，0.5 會讓正午的影子**完全消失**。

原因在 `StandardMaterial` 算漫射的那一行。

```glsl
vec3 finalDiffuse = clamp(diffuseBase * diffuseColor + emissiveColor + vAmbientColor, 0.0, 1.0)
  * baseColor.rgb;
```

那道 `clamp` 是關鍵。

正午的白沙正對太陽，環境光 0.72 加上平行光 1.03，合計 1.75。影子裡擋掉一半也還有 1.24。兩個數字都超過 1，`clamp` 之後一律變成 1.00，亮處與影子完全相同。%(⊙ o ⊙)%

太陽很斜的凌晨黃昏，合計掉到 1 以下，影子就回來了。月光強度只有 0.3，整晚都遠在天花板以下，所以夜裡的投影一直都在。

<demo-shadow-basic />

把天光拉到頂、darkness 給 0.5，白沙上的影子就這樣消失了。改成全擋之後，影子裡只剩環境光的 0.72，與亮處的 1.00 就分得開。

留 0.05 是不讓它硬生生地黑掉。白沙上的影子該是柔和偏藍的一片。%( ˘•ω•˘ )%

## 第三步：bias 與 normalBias

陰影貼圖的深度是有解析度的，一格紋素涵蓋一小塊面積，裡面存的卻只有一個深度值。

於是一個平面自己比對自己的時候，會有一半的取樣點算出「我比表上的數字遠」，判成在影子裡。畫面上就是滿地黑白相間的條紋，術語叫做 shadow acne。

`bias` 是把比對的門檻往前推一點。

```ts
shadowGenerator.bias = 0.0005
```

這個數字是**正規化深度**，要換算成世界單位才有意義。深度範圍三百四十格，0.0005 大約是 0.17 格。

推太多會有另一個症狀。一格高的花草整株落在偏移量以內，投出來的影子被抹掉了，草看起來浮在地上。這叫 peter-panning，因為影子跟本體脫節了。%(´･_･`)%

`normalBias` 走的是另一條路。

```ts
shadowGenerator.normalBias = 0.08
```

它沿著法線的反方向把投影者推進去。對付平面的自我遮蔽特別有效，又不會像 `bias` 那樣連帶吃掉貼地的短影子。

這裡有個要注意的地方。這個世界的花草為了讓交叉的兩片立板亮度一致，法線統一改成朝上了，推的方向剛好是往地底下。值一大整株草就沉進地面，影子自然消失。所以 `normalBias` 只留剛好夠壓住條紋的量，其餘交給提高解析度。

<demo-shadow-bias />

把 bias 拉到零，矮牆與地面立刻浮出條紋；拉到底，貼地的小石頭連影子都不見了。投影半徑那條拖桿則是拿來看解析度的，範圍越大邊緣越粗。

## 第四步：PCF 與接觸硬化

直接比對深度只有兩種答案，在影子裡或不在。邊緣因此是一排硬梆梆的階梯。

**PCF**（Percentage Closer Filtering）的做法是在陰影貼圖上取好幾個點各比一次，算出「這一點有幾成在影子裡」。

```ts
shadowGenerator.usePercentageCloserFiltering = true
shadowGenerator.filteringQuality = ShadowGenerator.QUALITY_MEDIUM
```

邊緣因此有了漸層。麻煩的是那個模糊寬度從頭到尾都一樣，柱腳與橫樑的影子軟得一模一樣。

現實裡的影子沒有這回事。太陽有半度的張角，遮蔽物離地面越遠，半影就越寬。柱腳貼著地，影子幾乎是刀切的；橫樑在六格高，影子已經化開了。

<figure-penumbra />

**PCSS**（Percentage Closer Soft Shadows）就是在算這件事，Babylon 叫它接觸硬化。

```ts
shadowGenerator.useContactHardeningShadow = true
shadowGenerator.contactHardeningLightSizeUVRatio = 0.05
```

它分成兩步。先在陰影貼圖上搜一圈，找出擋在前面的東西平均離得多遠；再依那段距離決定模糊寬度。近的就硬，遠的就散。

`contactHardeningLightSizeUVRatio` 這個名字很長，意思其實只有一句，光源在陰影貼圖上佔多寬。

換句話說就是「太陽有多大」。給得太大，一根柱子離地兩格影子就散得看不出形狀；給得太小則與硬邊的 PCF 沒有分別。投影範圍是八十格見方時，0.05 換算下來大約是四格的光源直徑，貼著地的那一段仍然銳利，樹冠那一段已經化開。

<demo-shadow-contact />

代價要記著。中等品質是十六次遮蔽搜尋加三十二次比較，大約是 PCF 五乘五的兩倍，高等再翻一倍。這是整套渲染裡最貴的一項，所以最省的畫質等級直接走 PCF。

```ts
function applyShadowFiltering(shadowGenerator: ShadowGenerator, preset: QualityPreset) {
  if (preset.shadowFilter === 'pcf') {
    shadowGenerator.useContactHardeningShadow = false
    shadowGenerator.usePercentageCloserFiltering = true
    shadowGenerator.filteringQuality = SHADOW_FILTER_QUALITY_MAP[preset.shadowFilterQuality]
    return
  }

  shadowGenerator.useContactHardeningShadow = true
  shadowGenerator.contactHardeningLightSizeUVRatio = CONTACT_HARDENING_LIGHT_SIZE
  shadowGenerator.filteringQuality = SHADOW_FILTER_QUALITY_MAP[preset.shadowFilterQuality]
}
```

順帶一提，指數陰影（ESM）那條路在這裡走不通。投影範圍只罩住鏡頭附近，範圍外的地面照樣要決定自己有沒有被遮住。PCF 與接觸硬化的著色器對範圍外會直接回傳「全亮」，指數陰影那條路沒有這個判斷，範圍外會取到邊界的深度值，遠處的沙地於是浮出一圈莫名其妙的陰影。%(›´ω`‹ )%

## 第五步：投影範圍跟著鏡頭走

投影範圍只有八十格見方，而世界有三百五十格寬。範圍當然要跟著人走。

```ts
light.position.set(
  center.x - forward.x * SHADOW_LIGHT_DISTANCE,
  center.y - forward.y * SHADOW_LIGHT_DISTANCE,
  center.z - forward.z * SHADOW_LIGHT_DISTANCE,
)
```

`center` 直接給鏡頭的位置就行了。走到哪，影子就跟到哪。

麻煩的是連續移動。投影矩陣一直在變，同一道邊緣每一幀落在不同的深度取樣點上，影子邊緣會沿著走路的方向不停爬動，術語叫 shadow shimmering。

解法是把投影中心對齊到貼圖的取樣格。只要人沒有跨過一格取樣格，整張陰影貼圖就是上一幀那一張，一個像素都不會變。

關鍵在於**對齊到哪個座標系**。

鱈魚：「簡單啊，把鏡頭的世界座標 X、Y、Z 各自四捨五入就好了。」
路人：「光源是斜的耶，那樣對得到嗎？」
鱈魚：「⋯⋯對不到。」

陰影貼圖的格子長在光源空間上。世界座標對齊之後投影到光源空間並不會落在整數格上，邊緣照樣每一幀重新取樣。%(´,,•ω•,,)%

正解是先把中心點投影到光源自己的三軸上，在那裡對齊，再轉回世界座標。

<figure-grid-align />

```ts
const texelSize = (SHADOW_HALF_EXTENT * 2) / mapSize

forward.copyFrom(light.direction).normalize()
Vector3.CrossToRef(Vector3.UpReadOnly, forward, right)
right.normalize()
Vector3.CrossToRef(forward, right, up)

const alongRight = Math.round(Vector3.Dot(camera.position, right) / texelSize) * texelSize
const alongUp = Math.round(Vector3.Dot(camera.position, up) / texelSize) * texelSize
const alongForward = Math.round(Vector3.Dot(camera.position, forward) / texelSize) * texelSize

center.set(
  right.x * alongRight + up.x * alongUp + forward.x * alongForward,
  right.y * alongRight + up.y * alongUp + forward.y * alongForward,
  right.z * alongRight + up.z * alongUp + forward.z * alongForward,
)
```

三軸的建法必須與 Babylon 算陰影視圖矩陣時完全一致，也就是 `LookAtLH` 以世界的上方為參考，否則對齊的還是另一組格子。

深度那一軸也要對齊。它不影響取樣格的位置，卻影響存進去的深度值。光源沿著光線連續前後移動時，同一個表面每一幀記下來的深度都差一點點，而比較深度是有門檻的。那些剛好卡在門檻上的取樣點會在「被擋住」與「沒被擋住」之間反覆翻面，看起來就是邊緣在閃。

還有一項要注意。`light.direction` 每一幀都在轉，白天從太陽射下、夜裡換成月亮，所以三軸要從光源當下的方向重算。照著固定的方向退開，投影範圍會歪到鏡頭以外的地方去。

## 第六步：分層陰影

單層的做法有個沒辦法解決的問題。

八十格見方罩得住鏡頭附近，而霧要到一百格才開始收。中間那一整圈看得一清二楚的景物完全沒有影子。

把範圍拉大到兩百格呢？那每一格地分到的紋素會少掉六倍多，近處的影子糊成一團。%(´･_･`)%

分層陰影（Cascaded Shadow Maps，CSM）就是為此而生。它把鏡頭前方依距離切成幾段，每一段各給一張貼圖。最近那一層罩得小，每格分到的像素最多；越遠的層罩得越大，但那裡的東西本來就小，看不出解析度掉了。

```ts
function createCascadedShadowGenerator(sunLight: DirectionalLight, preset: QualityPreset) {
  const shadowGenerator = new CascadedShadowGenerator(preset.shadowMapSize, sunLight)

  shadowGenerator.numCascades = preset.shadowCascadeCount
  shadowGenerator.stabilizeCascades = true
  shadowGenerator.lambda = 0.8
  shadowGenerator.shadowMaxZ = preset.shadowDistance
  shadowGenerator.autoCalcDepthBounds = false

  return shadowGenerator
}
```

逐項來說。

**`lambda`** 決定每一層的邊界怎麼切。0 是等距切，1 是照對數切，近處的層極窄、遠處的層極寬。0.8 偏向對數那一端，人眼對近處的影子解析度敏感得多，把像素往近處堆是划算的。

<figure-cascade />

**`stabilizeCascades`** 必須開。關著的話每一層的投影範圍會隨鏡頭轉動重新貼合視錐，同一道邊緣每幀落在不同的取樣點上，邊緣會沿著轉頭的方向爬動。上一節花了一整段對付的問題，分層版由它自己處理。

**`autoCalcDepthBounds`** 這裡選擇關掉。它每幀要把深度圖縮到一個像素去讀最小與最大深度，換來的是更貼身的深度範圍。這個場景的高度只有四十格，範圍本來就很緊，那一趟縮圖換不到相稱的品質。

還有一件事要記得。切到分層之後，上一節那整套追蹤鏡頭的程式碼要**整個讓開**。

```ts
scene.onBeforeRenderObservable.add(() => {
  const generator = light.getShadowGenerator()
  if (generator instanceof CascadedShadowGenerator)
    return

  alignShadowCenter(light, camera)
})
```

分層自己會依鏡頭的視錐算出每一層的投影範圍與深度，光源的位置與正交範圍對它完全沒有意義。照著單層的做法去挪動光源，只會讓那幾層的計算基準每幀被推走一次。

<demo-shadow-cascade />

影子一路鋪到霧裡，這是這座庭園望出去最明顯的一項改變。%ヽ(●`∀´●)ﾉ%

## 完整實作

把六個步驟組起來。

```ts
function createShadowGenerator({ scene, existingLight }: {
  scene: Scene;
  existingLight?: DirectionalLight | null;
}) {
  const sunLight = existingLight
    ?? new DirectionalLight(SUN_LIGHT_NAME, SUN_DIRECTION, scene)
  sunLight.intensity = SUN_INTENSITY
  sunLight.diffuse = new Color3(1, 0.93, 0.78)
  sunLight.specular = new Color3(1, 1, 1)

  const { preset } = useGraphicsQuality()
  const isCascaded = preset.value.shadowCascadeCount > 1

  if (!isCascaded) {
    sunLight.autoUpdateExtends = false
    sunLight.orthoLeft = -SHADOW_HALF_EXTENT
    sunLight.orthoRight = SHADOW_HALF_EXTENT
    sunLight.orthoTop = SHADOW_HALF_EXTENT
    sunLight.orthoBottom = -SHADOW_HALF_EXTENT
    sunLight.shadowMinZ = 10
    sunLight.shadowMaxZ = SHADOW_LIGHT_DISTANCE + 80
  }

  const shadowGenerator = isCascaded
    ? createCascadedShadowGenerator(sunLight, preset.value)
    : new ShadowGenerator(preset.value.shadowMapSize, sunLight)

  shadowGenerator.bias = 0.0005
  shadowGenerator.normalBias = 0.08
  shadowGenerator.darkness = 0.05
  applyShadowFiltering(shadowGenerator, preset.value)
  shadowGenerator.frustumEdgeFalloff = 0.2

  return shadowGenerator
}
```

最後那一行是給投影範圍的邊緣用的。範圍外全亮、範圍內有影子，中間沒有過渡就會是一條筆直的分界線。讓陰影在接近邊緣時逐漸淡掉，那條線就融進去了。

換畫質時要整個重建，因為貼圖的邊長與分幾層都是建構時就決定的。重建時把原本那盞光傳進來，場景裡才不會多出第二顆太陽。日夜循環是按名字找光的，多一盞就會有一盞永遠不被更新。

另外，陰影貼圖必須每一幀重畫。

太陽十分鐘才走完一整天，慢得不得了，很容易想省下那一趟幾何重繪。但慢不等於不動。比對用的光源矩陣是每一幀從光源當下的位置與方向重算的，深度資料卻停在上一次重畫的時刻。太陽一移動，兩者就對不起來，整片地面會浮出自我遮蔽的髒污，下一幀重畫後又消失。%(›´ω`‹ )%

## 總結 🐟

以上程式碼可以[在此取得](https://github.com/Codfisher/cod-aquarium/tree/main/content/aquarium/minespace)

- 平行光走正交投影，投影範圍越小影子越銳利，所以範圍要跟著鏡頭走
- `darkness` 要全擋，`StandardMaterial` 那道 clamp 會把「擋一半」整個吃掉
- `bias` 壓自我遮蔽的條紋，`normalBias` 沿法線推開，兩者要一起調
- 接觸硬化依遮蔽物的距離決定模糊寬度，柱腳才站得住
