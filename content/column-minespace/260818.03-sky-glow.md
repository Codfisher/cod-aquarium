# Minespace - EP03：日月光暈

大家好，我是鱈魚。

上一章的燈火光暈是一片面向鏡頭的圓盤加上相加混合。這一章把同一套機制搬到天上，主角換成太陽、月亮與星空。%( •̀ ω •́ )✧%

難處在於它們不能只是掛在那裡。天色一整天都在變，這三樣東西得跟著進場、退場、被染色，而且彼此的時間點還不一樣。

## 天上要掛什麼

先講清楚天空與天體的分工。

天空那一層負責漸層與霞光，那是大氣散射算出來的，整片鋪滿視野。太陽與月亮則是另外掛上去的小東西，各自是一片有貼圖的網格。

路人：「散射不是連太陽都一起算出來了嗎？」
鱈魚：「算得出來，但它會是一顆帶著柔邊的圓球。」

方塊世界的天上不該有圓的東西。所以太陽本體改掛一張正方形的貼圖，該有的圓潤感交給外圈的光暈。%( ˘•ω•˘ )%

整套要做的東西列一下。

1. 方形的太陽，配一圈暖色的暈
2. 方形的月亮，表面有月海與坑，配一圈冷色的暈
3. 一整片星空
4. 一套讓三者隨太陽高度淡入淡出、順便染色的機制

## 第一步：一顆方形的太陽

太陽的貼圖只有十六格見方，而且整片填滿同一個白。

```ts
const size = 16
const texture = new DynamicTexture(
  'sun',
  { width: size, height: size },
  scene,
  false,
  Texture.NEAREST_SAMPLINGMODE,
)

const context = texture.getContext()
context.fillStyle = 'rgb(255, 250, 230)'
context.fillRect(0, 0, size, size)
texture.update()
```

`NEAREST_SAMPLINGMODE` 是這裡的重點。

十六格的圖要拉到畫面上好幾百個像素寬，預設的雙線性取樣會在每個相鄰的紋素之間內插，硬邊立刻化成一圈糊掉的漸層。最近鄰取樣則是直接取最靠近的那一格，放大幾倍都還是方的。

這一顆填滿的白看不出差別，等一下畫月亮就很明顯了。

第五個參數的 `false` 是關掉 mipmap。天體在畫面上永遠是被放大的，縮圖鏈那幾層一輩子用不到。%(´,,•ω•,,)%

## 第二步：天體共用的材質

太陽、月亮、兩圈暈與星空總共五樣東西，材質是同一套。

```ts
function createSkyBodyMaterial(name: string, texture: DynamicTexture, scene: Scene) {
  const material = new StandardMaterial(name, scene)

  material.diffuseTexture = texture
  material.diffuseColor = new Color3(0, 0, 0)
  material.specularColor = new Color3(0, 0, 0)
  material.emissiveColor = new Color3(1, 1, 1)
  material.disableLighting = true
  material.fogEnabled = false
  material.backFaceCulling = false

  material.alphaMode = Constants.ALPHA_ADD
  material.alpha = 0.999
  material.disableDepthWrite = true

  return material
}
```

相加混合、`alpha = 0.999`、不寫深度這三項與上一章的燈火光暈完全一樣，理由也一樣。

`fogEnabled` 要關掉。霧是給地面上的東西用的，天體離鏡頭好幾十格遠，照著霧的公式算會直接被霧色蓋滿。

### 貼圖為什麼掛在 diffuseTexture

這一項最關鍵，也最容易寫錯。

直覺上「會自己發亮的東西」該掛 `emissiveTexture`。但 Babylon 的著色器裡，自發光是這樣算的。

```glsl
vec3 emissiveColor = vEmissiveColor;
#ifdef EMISSIVE
  emissiveColor += texture2D(emissiveSampler, vEmissiveUV).rgb * vEmissiveInfos.y;
#endif
```

顏色與貼圖是**相加**的關係。

於是把顏色調成黑色，貼圖照樣全亮，大白天會有一顆月亮跟一整片星星掛在藍天上；調成白色則是整片再加上一層白，夜裡整個天空被灌成灰的。無論怎麼調，那張貼圖都收不掉。

改掛 `diffuseTexture` 之後，關掉光照，那一行就成了乘法。

```glsl
vec3 finalDiffuse = clamp(diffuseBase * diffuseColor + emissiveColor + vAmbientColor, 0.0, 1.0)
  * baseColor.rgb;
```

`diffuseBase` 因為關了光照是零，`diffuseColor` 也給了黑，`vAmbientColor` 是零，`baseColor.rgb` 正是那張貼圖。整條式子收成 `clamp(自發光) * 貼圖`。

自發光的顏色因此成了乾淨的亮度乘數。淡入淡出、染色，全部都靠它。%ヽ(●`∀´●)ﾉ%

<demo-sky-body-material />

左邊那顆乘數歸零就整個淡出去了。右邊那顆歸零時貼圖還在原地發亮，拉到 1 反而糊成一片白。%(⊙ o ⊙)%

## 第三步：掛在天上

網格本身要設兩個屬性。

```ts
const disc = MeshBuilder.CreatePlane('sun', { size: 15 }, scene)
disc.material = material
disc.position = SUN_DIRECTION.scale(-110)
disc.infiniteDistance = true
disc.billboardMode = Mesh.BILLBOARDMODE_ALL
disc.isPickable = false
```

**`infiniteDistance`** 讓這片網格每一幀跟著鏡頭平移。人往前走一百格，太陽也往前挪一百格，於是它與鏡頭的相對位置永遠不變。

少了這一項，太陽就成了場景裡固定在某個座標的板子。走近它會變大，走遠會變小，繞過去還能看到它的背面。%(´･_･`)%

**`BILLBOARDMODE_ALL`** 讓網格永遠正對鏡頭。抬頭、低頭、轉身，看到的都是同一個正方形。

再補一項。

```ts
disc.alwaysSelectAsActiveMesh = true
```

`infiniteDistance` 的網格是每一幀跟著鏡頭跑的，拿它原本的包圍盒去判斷在不在視野裡會判錯。乾脆讓它跳過剔除那一步。

## 第四步：月亮的臉

月亮與太陽一樣是填滿的方形，差別在表面。

太陽是一片沒有細節的白，月亮則要有月海、坑與明暗。冷色調也與太陽的暖白分得開，同樣是方塊，一眼就認得出誰是誰。

底色先鋪滿。

```ts
context.fillStyle = 'rgb(226, 233, 250)'
context.fillRect(0, 0, size, size)
```

接著是月海，暗一階的幾塊斑。

```ts
context.fillStyle = 'rgb(196, 206, 231)'
const seaList: [number, number, number, number][] = [
  [2, 3, 5, 4],
  [8, 2, 3, 3],
  [10, 7, 4, 5],
  [1, 9, 3, 3],
  [5, 11, 4, 3],
  [12, 1, 2, 2],
]
for (const [x, y, width, height] of seaList) {
  context.fillRect(x, y, width, height)
}
```

這幾組座標刻意不規則，也刻意不對稱。

鱈魚：「來吧，用個雙層迴圈把斑均勻灑滿整張圖！」
路人：「那不就變成雜訊了嗎？」
鱈魚：「說得也是，還是手排吧。」

排得整齊會變成一顆骰子，均勻散開又會變成雜訊。幾塊大的湊在一邊、幾塊小的散在另一邊，那才像月面。%( ´ ▽ ` )ﾉ%

再暗一階的坑落在月海裡面，表面才有第三層深度。

```ts
context.fillStyle = 'rgb(170, 181, 209)'
const craterList: [number, number, number, number][] = [
  [3, 4, 2, 2],
  [11, 9, 2, 2],
  [6, 12, 2, 1],
  [2, 10, 1, 1],
]
```

最後把右下角壓暗一層。

```ts
context.fillStyle = 'rgba(120, 132, 164, 0.32)'
context.fillRect(9, 12, 7, 4)
context.fillRect(13, 8, 3, 4)
```

一整片同亮度的方塊看起來是平的。讓一角暗下去，月亮才有一點球的錯覺，卻又沒有真的把它畫成圓。

<demo-moon-face />

順手把取樣模式也放進去了。切成雙線性之後，十六格的圖拉大三十倍，剛才排了半天的月海整個化成一團霧。%(›´ω`‹ )%

材質那邊給的自發光比太陽暗一階。

```ts
material.emissiveColor = new Color3(0.86, 0.88, 0.95)
```

月亮是反射的光，本來就沒有太陽亮。壓在泛光的門檻以下，月面就維持乾淨的硬邊像素，散開的工作交給外圈那圈暈。

## 第五步：星空

夜裡抬頭只有一片深藍的話，天空會像一塊布。

星空的做法是一張隨機點上星點的貼圖，貼在一個罩住鏡頭的盒子上。

```ts
const size = 512
const texture = new DynamicTexture('star', { width: size, height: size }, scene, true)
const context = texture.getContext()

context.fillStyle = '#000000'
context.fillRect(0, 0, size, size)

const random = createSeededRandom('minespace-star')
for (let index = 0; index < 460; index++) {
  const x = Math.floor(random() * size)
  const y = Math.floor(random() * size)

  const isBright = random() < 0.1
  const brightness = isBright ? 0.85 + random() * 0.15 : 0.25 + random() * 0.45
  const pixelSize = isBright ? 2 : 1

  context.fillStyle = `rgba(255, 252, 242, ${brightness})`
  context.fillRect(x, y, pixelSize, pixelSize)
}
```

底畫成全黑很重要。這張圖走的是相加混合，黑色加上去等於沒加，於是只有星點會浮出來。

一成的星點畫成兩格寬、亮度接近滿格，其餘的又小又暗。疏密有層次，抬頭才不會是一整片均勻的白點。

```ts
const dome = MeshBuilder.CreateBox('star', { size: 240 }, scene)
dome.material = material
dome.infiniteDistance = true
```

盒子六個面共用同一張圖，圖樣其實重複了六次。星點本來就是隨機散布、沒有結構，轉頭時看不出重複。%( ˘•ω•˘ )%

## 第六步：淡入淡出與染色

最後把三樣東西接上時間。

太陽沿著一個傾斜的圓在天球上繞一圈，月亮永遠在正對面。

```ts
const angle = (time - 0.25) * Math.PI * 2
const alongRise = Math.cos(angle)
const alongNoon = Math.sin(angle)

sunPosition.set(
  SUNRISE_AXIS.x * alongRise + NOON_AXIS.x * alongNoon,
  SUNRISE_AXIS.y * alongRise + NOON_AXIS.y * alongNoon,
  SUNRISE_AXIS.z * alongRise + NOON_AXIS.z * alongNoon,
)
moonPosition.copyFrom(sunPosition).scaleInPlace(-1)
```

兩根軸永遠互相垂直——這是路徑維持正圓（而非橢圓）的關鍵，垂直是結構保證的。傾角其實藏在 NOON_AXIS 自己的仰角裡：它只抬到約 58 度，不是九十度，正午才不會落在正上方。

<figure-sun-path />

有了太陽的高度，三者各自的門檻就好訂了。

```ts
const sunHeight = sunPosition.y

sunVisibility = smoothRange(sunHeight, -0.05, 0.06)
moonVisibility = smoothRange(-sunHeight, -0.02, 0.14)
starVisibility = smoothRange(-sunHeight, 0.02, 0.24)
```

`smoothRange` 把一段區間換成兩端斜率為零的平滑曲線，天體進場退場才不會有突然的一跳。

```ts
function smoothRange(value: number, from: number, to: number) {
  const ratio = Math.min(1, Math.max(0, (value - from) / (to - from)))

  return ratio * ratio * (3 - 2 * ratio)
}
```

三個門檻刻意錯開。太陽從地平線下五度就開始亮，月亮要等太陽真的沉下去，星星則要再暗一階才敢出來。這樣黃昏才有那段「太陽剛走、星星還沒到」的空檔。%( •̀ ω •́ )✧%

<figure-visibility-threshold />

### 越低的太陽越紅

天空的漸層是大氣散射算出來的，太陽本體卻是一張自己畫的貼圖。

兩邊各走各的，日落時就會有一顆慘白的方塊掛在一片橘紅的天上。所以要拿當下的光色回去染它。

```ts
const horizonRatio = 1 - smoothRange(sunHeight, 0.04, 0.42)
const sunFade = sunVisibility * skyBodyFade

for (const [index, material] of sunMaterialList.entries()) {
  const base = sunBaseList[index]

  material.emissiveColor.set(
    base.r * sunFade,
    base.g * lerp(1, lightColor.g, horizonRatio) * sunFade,
    base.b * lerp(1, lightColor.b, horizonRatio) * sunFade,
  )
}
```

紅色那一項不動，綠與藍往光色靠。太陽越低，`horizonRatio` 越接近 1，扣掉的綠藍越多，那顆方塊就越橘。

月亮與星空不需要染色，只要乘上各自的淡出比例。

```ts
material.emissiveColor.set(base.r * moonFade, base.g * moonFade, base.b * moonFade)
starMaterial.emissiveColor.set(starFade, starFade, starFade)
```

`skyBodyFade` 是另一件事。走到世界邊界時整片天要收乾淨，那個比例會把所有天體一起壓到零。

## 完整實作

把六個步驟組起來，就是專案裡 `use-babylon-scene.ts` 天空那一段在做的事。

流程整理一次。

1. 畫四張貼圖，太陽、月亮各一張，兩圈暈與星空各一張
2. 五份材質全部走 `createSkyBodyMaterial`，貼圖掛 `diffuseTexture`
3. 網格全部開 `infiniteDistance` 與 `BILLBOARDMODE_ALL`
4. 每一幀依太陽高度更新五份材質的自發光，順便把太陽染色

光暈那兩片沿用上一章的 `createGlowTexture`，只換峰值顏色。

```ts
const sunGlowTexture = createGlowTexture('sun-glow', scene, [130, 127, 109])
const moonGlowTexture = createGlowTexture('moon-glow', scene, [103, 112, 128])
```

太陽的暈偏暖，月亮的偏冷，夜裡那點空氣感就是這一圈冷色撐出來的。

### 峰值要壓在本體之下

太陽那圈原本我給的是 `[217, 211, 182]`，跟本體的白只差一點，想說這樣暈才夠亮。

結果太陽整顆不見了。%(´,,•ω•,,)%

鱈魚：「太陽被暈吃掉了，那就把暈也調亮，讓它們一起發光。」
路人：「你這是要把整片天燒了嗎？」
鱈魚：「開玩笑的啦，該調暗的是暈。」

本體跟光暈其實走同一套混合方式，都是相加混合，疊在本來就不暗的天色上。本體疊出一塊固定亮度的方形，光暈疊出一圈由亮到暗的漸層。峰值相當時，兩邊疊加的結果一起衝出顯示能接的上限，clamp 成同一片白，方形的邊界因此消失，跟本體透不透明沒有關係。

收到六成之後，太陽與貼邊的光暈差開二十五階，方形的輪廓回來了，暈的尾巴照樣鋪得出去。%( •̀ ω •́ )✧%

這個階數是在專案正式場景量出來的，那邊開了 ACES 色調映射，曝光給到 1.06、對比 1.05。底下兩支範例沒有套這層後製，同樣的峰值疊上去，太陽一樣會先溶進暈裡，六成之後才重新浮出來，但量到的階數會是另一組數字，沒辦法拿這兩支範例回頭對照「二十五階」這個數字。

<demo-sky-glow-peak />

暈的網格半徑要對應貼圖的內切圓。

```ts
function createGlowMesh(name: string, planeSize: number, scene: Scene): Mesh {
  const mesh = MeshBuilder.CreateDisc(
    name,
    { radius: planeSize / 2, tessellation: 48 },
    scene,
  )
  mesh.infiniteDistance = true
  mesh.billboardMode = Mesh.BILLBOARDMODE_ALL
  mesh.isPickable = false

  return mesh
}
```

圓盤的 UV 是「邊緣落在貼圖的內切圓上」，而放射狀漸層的外徑正是那個圓。所以半徑取原本方片邊長的一半，暈的大小才不會變。

最後，暈要掛得比本體再遠兩格。

```ts
sunDisc.position = sunDirection.scale(-110)
sunGlow.position = sunDirection.scale(-112)
```

兩片都不寫深度，誰先畫誰後畫由排序決定。差那兩格就是拿來穩住順序的。%(´,,•ω•,,)%

## 總結 🐟

以上程式碼可以[在此取得](https://github.com/Codfisher/cod-aquarium/tree/main/content/aquarium/minespace)

- 方塊世界的太陽是方的，硬邊靠 `NEAREST_SAMPLINGMODE` 保住
- 天體的貼圖掛 `diffuseTexture`，自發光的顏色才會是乾淨的乘數
- `infiniteDistance` 讓天體跟著鏡頭平移，`billboardMode` 讓它永遠正對鏡頭
- 月面靠底色、月海、坑、暗角四階疊出來，座標刻意不規則
- 太陽、月亮、星星的門檻要錯開，黃昏才有那段空檔
- 光暈的峰值要壓在本體之下，相加混合疊在天色上很容易蓋過太陽
