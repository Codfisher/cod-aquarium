# Minespace - EP03：像素材質工廠

大家好，我是鱈魚。

上一章把方塊畫出來了，這一章來看那些方塊身上的貼圖。%੭ ˙ᗜ˙ )੭%

Minespace 支援五套材質包，玩家可以隨時切換。所以貼圖這件事不能寫死在方塊上。

## 方塊只說「我要石頭」

方塊定義裡寫的不是檔案路徑，而是一個語意 key。

```ts
const MINI_PIXEL_TEXTURE_MAP = {
  stone: 'default_stone',
  cobblestone: 'default_cobble',
  grassTop: 'default_grass_top',
  waterStill: 'default_water_source_animated',
  // ...
}
```

方塊說「我要石頭」，材質包回答「石頭在我這叫 `stone.png`」。

加一套新材質包只需要再寫一份對照表，方塊那一千五百行完全不必動。%( •̀ ω •́ )✧%

有趣的是，有些東西是材質包的性質而不是方塊的性質。

```ts
export interface PackTexture {
  file: string;
  /**
   * 動畫張數
   *
   * 同樣是水，迷你像素只有六張畫格，原版是三十二張
   * 寫在方塊上的話換一次包整條瀑布就會錯格
   */
  frameCount?: number;
  /** 給 null 表示「這張圖本身顏色就對了，不要再染」 */
  tint?: [number, number, number] | null;
  pixelTint?: [number, number, number] | null;
}
```

原版的花草是實色的，迷你像素那組把灰階圖染上顏色的倍率套到已經有顏色的圖上，只會得到一朵髒掉的花。%(›´ω`‹ )%

## 換包時不重建材質

一開始的做法是換材質包就整批重建材質，結果災難。

材質物件上還掛著風的擺動、淋雨會變暗的登記、水面的高光與自發光，那些與貼圖無關的東西重建一次全都要重新接一遍。

所以改成留一份「配方」，換包時照著配方再做一次貼圖就好，材質物件本身原封不動。

```ts
export interface PixelMaterialRecipe {
  name: string;
  textureKey: TextureKey;
  /** 疊在基底上的覆蓋層，例如礦點 */
  overlayKey?: TextureKey;
  tint?: [number, number, number];
  pixelTint?: [number, number, number];
  frameCount?: number;
  /** 鏤空貼圖不能有 mipmap */
  noMipmap?: boolean;
  /** 走 alpha test 的鏤空材質 */
  cutout?: boolean;
  /** 網格的法線被改成一律朝上 */
  flatShaded?: boolean;
  /** 背面用翻轉後的法線打光，樹葉要、花草不要 */
  twoSidedLighting?: boolean;
  /** 逆光時透出來多少 */
  translucency?: number;
  specularColor?: Color3;
}
```

工廠長這樣。

```ts
export interface TextureSkinner {
  /** 依配方生一份材質，貼圖用目前這套材質包的 */
  create: (recipe: PixelMaterialRecipe) => StandardMaterial;
  /** 換一套材質包，或改變立體紋理的開關 */
  applyPack: (pack: TexturePack, bumpEnabled: boolean) => void;
  dispose: () => void;
}
```

全世界的方塊材質都從這裡出來，也只有這裡知道「目前是哪一套材質包」。

## 礦石是疊出來的

迷你像素那套的礦石是「石頭當底，礦點那張背景全透明的圖疊上去」。

用 `DynamicTexture` 在 Canvas 上合成就好。

```ts
function createCompositedTexture(
  name: string,
  basePath: string,
  overlayPath: string,
  size: number,
  scene: Scene,
): DynamicTexture {
  const dynamicTexture = new DynamicTexture(name, size, scene, false, Texture.NEAREST_SAMPLINGMODE)

  const baseImage = new Image()
  const overlayImage = new Image()
  let loadedCount = 0

  const tryComposite = () => {
    loadedCount++
    if (loadedCount < 2)
      return

    const context = dynamicTexture.getContext()
    if (context instanceof CanvasRenderingContext2D) {
      context.imageSmoothingEnabled = false
    }
    context.clearRect(0, 0, size, size)
    context.drawImage(baseImage, 0, 0, size, size)
    context.drawImage(overlayImage, 0, 0, size, size)
    dynamicTexture.update()
  }

  baseImage.onload = tryComposite
  overlayImage.onload = tryComposite
  baseImage.src = basePath
  overlayImage.src = overlayPath

  return dynamicTexture
}
```

`imageSmoothingEnabled = false` 與 `NEAREST_SAMPLINGMODE` 一定要記得，不然像素風會被瀏覽器好心糊掉。%(・∀・(・∀・(・∀・*)%

<demo-texture-compose />

中間那顆是礦點單獨掛上來的樣子，背景全透明所以整顆缺了大半。兩張合起來才是一顆金礦。%(*´∀`)~♥%

## 綠葉為什麼染不成橘色

這一段是我覺得最有趣的坑。%(๑•̀ㅂ•́)و✧%

秋天的金葉苑要把綠葉變成橘黃，直覺就是把材質的 `diffuseColor` 調成橘色。

結果不管紅色開多大，葉子就是紅不起來。

原因在著色器那一行。`StandardMaterial` 是先把「光照 × tint」夾在 1 以內，再乘上貼圖的顏色。

所以某個通道最亮就是貼圖本身的值。一張綠葉貼圖的紅只有 0.26，tint 的紅開到多大都只會停在 0.26。

材質的 tint 只能把顏色調暗，做不到調亮。%(´థ‸థ)%

三種做法放在一起就一目瞭然了。

<demo-recolor />

那就只好在像素層下手。

```ts
const imageData = context.getImageData(0, 0, size, size)
const { data } = imageData
for (let index = 0; index < data.length; index += 4) {
  if (isRecolor) {
    /**
     * 先取亮度，再乘上目標色
     *
     * 亮度用的是人眼的加權，不是三個通道的平均
     */
    const luminance = (
      data[index]! * 0.2126
      + data[index + 1]! * 0.7152
      + data[index + 2]! * 0.0722
    ) / 255

    data[index] = Math.min(255, luminance * 2 * pixelTint[0] * 255)
    data[index + 1] = Math.min(255, luminance * 2 * pixelTint[1] * 255)
    data[index + 2] = Math.min(255, luminance * 2 * pixelTint[2] * 255)
    continue
  }

  data[index] = Math.min(255, data[index]! * pixelTint[0])
  data[index + 1] = Math.min(255, data[index + 1]! * pixelTint[1])
  data[index + 2] = Math.min(255, data[index + 2]! * pixelTint[2])
}
context.putImageData(imageData, 0, 0)
```

有兩個細節。

亮度用人眼的加權而不是平均，因為綠色看起來本來就比藍色亮。用平均會讓綠葉整片偏亮、藍花整片偏暗，明暗層次就跑掉了。

乘二是把中間調當基準。亮度 0.5 的像素剛好染成目標色本身，比它亮的往上、暗的往下，貼圖原本的紋理都還在。%ヽ(●`∀´●)ﾉ%

鏤空的透明度原封不動留著，不然葉子會變成一塊實心方磚。

## 讓水流動

流水的貼圖是好幾張圖上下疊成一長條，播放就是把 v 軸縮到只取一格，再逐格往下捲。

```ts
const TEXTURE_FRAME_RATE = 3.5

function playTextureFrames(texture: Texture, frameCount: number, scene: Scene): () => void {
  texture.vScale = 1 / frameCount
  texture.wrapV = Texture.WRAP_ADDRESSMODE

  let elapsed = 0
  const observer = scene.onBeforeRenderObservable.add(() => {
    elapsed += scene.getEngine().getDeltaTime() / 1000
    texture.vOffset = Math.floor(elapsed * TEXTURE_FRAME_RATE) % frameCount / frameCount
  })

  /** 換材質包時要拆掉 */
  return () => scene.onBeforeRenderObservable.remove(observer)
}
```

回傳一個拆除函式很重要。不拆的話每換一次材質包就多一個觀察者在推已經被釋放的貼圖。%(・∀・(・∀・(・∀・*)%

## 鏤空的三件事

花草、樹葉、鐵鏈這種貼圖是鏤空的，走 alpha test 那條路。

```ts
if (recipe.cutout) {
  material.useAlphaFromDiffuseTexture = true
  material.transparencyMode = Material.MATERIAL_ALPHATEST
  material.twoSidedLighting = recipe.twoSidedLighting ?? true
  material.alphaCutOff = 0.5
}
```

### 不能有 mipmap

這些貼圖的 alpha 是全有全無的，不是完全透明就是完全不透明。

但 mipmap 是把相鄰像素平均出來的，縮小之後透明與不透明的邊界上會生出 0.5 這種中間值。

alpha test 判定它「要畫」，於是花草上方浮出一道細細的十字，那正是交叉立板本身的輪廓。%(´థ‸థ)%

關掉 mipmap 之後 alpha 只剩 0 與 1 兩種值，門檻擺在中間最保險。

<demo-cutout-mipmap />

把 mipmap 打開，往遠處的草看過去，那道十字就出來了。%(・∀・(・∀・(・∀・*)%

順便拉一下裁切門檻，門檻拉太高會連葉尖那種只有一兩個像素的部分一起啃掉，草會愈變愈禿。

### 背面要不要翻轉法線

樹葉這種有體積的方塊，背面要用翻轉後的法線計算光照，從縫隙看進樹冠內部才不會是一片黑。

花草則相反。它們的法線已經統一改成朝上（見 EP02），再翻轉就會讓背面朝下而變暗。

所以樹葉開、花草關。

上面那個範例可以切這一項。打開之後有一半的草會暗下去，因為它們的法線宣稱自己朝上，翻轉之後就變成朝下了。%(・∀・(・∀・(・∀・*)%

### 沒有高光

花草與玻璃這類鏤空的東西不該有高光。

```ts
const NO_SPECULAR = new Color3(0, 0, 0)
```

## 立體紋理

有些材質包附了法線圖與高光圖，開起來之後石縫看起來會真的有深度。

```ts
const bumpTexture = new Texture(normalUrl, scene, {
  /** 法線也要用最近鄰 */
  samplingMode: Texture.NEAREST_SAMPLINGMODE,
  noMipmap: recipe.noMipmap,
})
material.bumpTexture = bumpTexture
```

法線也要用最近鄰。這是像素風的世界，法線若被線性內插，一格貼圖裡的凹凸會糊成一團圓滑的起伏，與方稜方角的方塊完全對不起來。

Babylon 的 `bumpTexture` 剛好吃「RGB 是切線空間法線、alpha 是高度」這個排法，一個像素都不必改寫。

高度那一欄讓視差開得起來。

```ts
if (currentPack?.hasHeightMap && !recipe.cutout) {
  material.useParallax = true
  material.parallaxScaleBias = 0.06
}
```

兩個條件缺一不可。

一是材質包的法線 alpha 真的存了高度，否則整片同一個高度，白算一遍。

二是這份材質不能鏤空。視差的做法是「依視角把取樣座標推開一點」，而推開後的座標連漫射的 alpha 一起帶著跑。

於是不透明的像素被拉進本該全透明的地方，alpha test 判定要畫，草的上方就浮出一圈描邊。%(・∀・(・∀・(・∀・*)%

位移量也壓得很小。一格方塊只有一格見方，位移大一點邊緣就會被推出格子外，相鄰兩顆方塊之間裂出一道縫。

<demo-bump-parallax />

三個開關可以一項一項加上去。法線給表面凹凸、視差讓石縫真的有深度、高光圖決定哪裡會亮起一條邊。%( •̀ ω •́ )✧%

位移量拉大就看得到文章說的問題，邊緣被推出格子外，相鄰兩顆方塊之間裂出一道縫。

還記得 EP02 說「法線改成朝上的代價後面會還」嗎？就是這裡。

```ts
/** 法線造假的表面解不回正確的偏移方向，掛上去只會算出一團亂 */
if (!isBumpEnabled || !normalUrl || recipe.flatShaded) {
  material.bumpTexture = null
  material.specularTexture = null
  material.useParallax = false
  return
}
```

## 兩個容易被忽略的預設值

### 材質的環境色預設是黑的

```ts
material.ambientColor = new Color3(1, 1, 1)
```

Babylon 的環境光是「場景的 ambientColor × 材質的 ambientColor」，而材質這一項預設是黑的。

也就是說，材質預設完全不吃場景補光。%(⊙ o ⊙)%

這件事在 Minespace 很關鍵。夜裡那道補光是加在光照上、再乘上反照率的，而方塊光正烘在反照率裡。這是燈火照得出範圍的唯一途徑。

詳細的來龍去脈留到 EP06。

### 自發光不要開 useEmissiveAsIllumination

```ts
if (blockDef.emissive) {
  material.emissiveColor = new Color3(blockDef.emissive, blockDef.emissive, blockDef.emissive)
}
```

`emissiveColor` 是一整片相加的顏色。開了 `useEmissiveAsIllumination` 之後它會跳過貼圖直接加在最後，而且最終顏色仍然夾在 1 以內。

燈石與餘燼因此被洗成一塊死白，貼圖的圖案整個看不見。%(›´ω`‹ )%

關掉它，自發光會先併進光照量再乘上貼圖，效果等同 Minecraft 的亮度等級。方塊亮起來，圖案還在。%ヽ(●`∀´●)ﾉ%

## 水面反日光

液體另外調高高光。

```ts
if (blockDef.isLiquid) {
  material.specularColor = new Color3(0.8, 0.82, 0.85)
  material.specularPower = 160
}
```

水的法線已經統一改成朝上，整池水因此是一個光學上的平面。太陽在上面只會反出一個點，人一走那個點就跟著移。

那道光是靜水最有說服力的東西，比任何波紋貼圖都有效。%(*´∀`)~♥%

指數給得很高，高光才收得緊。散開的高光是磨砂玻璃，不是水。

而它加在漫射的 clamp 外面，所以正午時真的會刺眼。這就是 EP01 說「平行光的 specular 給滿」的理由。

這一段的三件事湊在同一個範例裡，因為它們都只在夜裡的場景看得清楚。

<demo-emissive-ambient />

打開 `useEmissiveAsIllumination`，三顆燈石立刻被洗成一塊死白，貼圖的顆粒整個不見。%(´థ‸థ)%

把「材質 ambientColor 給白」關掉，再拉場景補光，會發現拉到底畫面都沒有反應，那道補光完全進不來。

水面反日光關掉之後，池面上那道月光就消失了，只剩一塊死板的深藍。

## 總結 🐟

以上程式碼可以[在此取得](https://github.com/Codfisher/cod-aquarium/tree/main/content/aquarium/minespace)

- 方塊只寫語意 key，材質包負責翻譯成檔名，加一套包不必動方塊定義
- 換材質包時只重做貼圖、不重建材質，掛在材質上的那些效果才不會斷線
- 材質的 tint 只能調暗不能調亮，要換色只能在 Canvas 上逐像素重新上色
- 鏤空貼圖不能有 mipmap，也不能開視差，兩者都會讓輪廓浮出來
- 材質的 ambientColor 預設是黑的，不設成白色就完全吃不到場景補光
