# Minespace - EP15：草叢踩踏

大家好，我是鱈魚。

這個系列到目前為止，材質外掛都用在同一件事上，改片元最後的顏色。雲影是把顏色調暗，大氣透視是把顏色往霧色收，晨霧的高度加厚也是。

這一章換一邊。改的是頂點的位置本身。%( •̀ ω •́ )✧%

## 為什麼只能在著色器裡做

世界上的花草有上萬株，全部是 thin instance，共用同一份頂點資料。

這件事的意思是，CPU 這邊連「單獨移動其中一株」的餘地都沒有。手上只有一份網格與一大包矩陣，改網格等於整片草一起改，改矩陣則是整株平移。

要讓每一株各自彎腰，就只能在頂點著色器裡做。GPU 跑那支程式的時候，每一個頂點都知道自己屬於哪一株、在那一株的哪個高度。

```ts
class WindSwayPlugin extends MaterialPluginBase {
  getCustomCode(shaderType: string) {
    if (shaderType !== 'vertex')
      return null

    return {
      CUSTOM_VERTEX_DEFINITIONS: VERTEX_DEFINITIONS,
      CUSTOM_VERTEX_UPDATE_POSITION: VERTEX_UPDATE_POSITION,
    }
  }
}
```

材質外掛的完整機制在 EP05 講雲影時已經說過。這裡只有兩個地方不一樣。

**`shaderType` 要認 `vertex`。**片段那支回傳 `null`，一個字都不必動。

**注入點換成頂點著色器的那兩個。**`CUSTOM_VERTEX_DEFINITIONS` 在函式區，用來放自己寫的 GLSL 函式；`CUSTOM_VERTEX_UPDATE_POSITION` 在 `vec3 positionUpdated = position;` 之後、`instancesVertex` 展開之前。

那個順序很要緊。世界矩陣還沒乘上去，所以這裡動的是**區域座標**。一株草的區域座標是負零點五到正零點五，加上零點五剛好就是「離地多高」。

### 這一株長在哪裡

區域座標問不出「這一株站在世界的什麼位置」，可是風的強弱要看位置。

```glsl
#ifdef INSTANCES
  vec3 plantOrigin = world3.xyz;
#else
  vec3 plantOrigin = vec3(0.0);
#endif
```

`world0` 到 `world3` 是 Babylon 給實例的四個頂點屬性，湊起來就是那一株的世界矩陣。矩陣的第四行是平移，所以 `world3.xyz` 直接就是它的世界座標。

實例的矩陣要是純平移加上等比縮放。一旦帶了旋轉，區域座標上的位移會跟著轉，整片草就各自往不同的方向倒了。

### uniform 只登記一次

```ts
class WindSwayPlugin extends MaterialPluginBase {
  getUniforms() {
    return {
      ubo: [
        { name: 'windTime', size: 1, type: 'float' },
        { name: 'windAmplitude', size: 1, type: 'float' },
        { name: 'windTrampleList', size: 4, type: 'vec4', arraySize: TRAIL_MARK_COUNT },
      ],
    }
  }
}
```

登記在 `ubo` 裡的名字，Babylon 會自己把宣告注入材質的 uniform 區塊，頂點與片段兩支都拿得到。

所以 `VERTEX_DEFINITIONS` 那個字串裡千萬不要再寫一次 `uniform float windTime`。同一個名字宣告兩次，著色器編譯直接失敗，而編譯失敗的材質不會報錯，只會整批不畫。畫面上看到的就是所有的草突然消失。%(´･_･`)%

## 風怎麼做

風由三層疊起來，各管一件事。

### 第一層：柏林噪聲的陣風

這一層決定「這一帶此刻風多大」。

```glsl
vec2 samplePoint = plantOrigin.xz * 0.09 - windDirection * windTime * 0.09 * 2.6;
float gust = windNoise(samplePoint) * 0.68 + windNoise(samplePoint * 2.3 + 17.0) * 0.32;
float gustStrength = clamp(0.7 + gust * 0.45, 0.35, 1.15);
```

取樣點隨時間往風的方向退，噪聲場因此像一陣風掃過草原。

用的是梯度噪聲，格點上存的是一個方向。內插出來的場沒有格子的痕跡，這是「像風」的關鍵。換成存高度的值噪聲，格線就會露出來。

```glsl
vec2 windHash(vec2 point) {
  point = vec2(dot(point, vec2(127.1, 311.7)), dot(point, vec2(269.5, 183.3)));
  return -1.0 + 2.0 * fract(sin(point) * 43758.5453123);
}
```

疊兩層，大的那層是一陣一陣的強弱，小的那層讓陣與陣之間不會是同一個形狀。

`clamp` 壓成一個恆正的包絡。風會忽強忽弱，但不會反過來吹，下限留一點，草地永遠有一絲微風。

`0.09` 這個疏密約是十一格一個起伏，差不多一座箱庭的三分之一。看得出「一陣」的形狀，又不會整座木座同進同出。

### 第二層：沿著風向前進的行進波

問題來了。十一格才一個起伏，相鄰兩株在噪聲場上只差零點零九，取到的值幾乎一模一樣。整片草看起來是同時動的。

陣風管得了範圍，管不了順序。

```glsl
float rippleTravel = dot(plantOrigin.xz, windDirection) - windTime * 2.6;
float ripple = sin(windRippleFrequency * rippleTravel);
```

相位只看「這一株在風向上站得多前面」，減去時間就成了一道往下游跑的行進波。

波長給六格，隔壁那一株就差六十度的相位。這一株彎到底時下一株才剛開始傾，一排草因此是接力倒下去的。%ヽ(●`∀´●)ﾉ%

它與陣風用同一個速度前進，所以看到的是「一陣風掃過來，草一株接一株倒下去」，兩者不會各走各的。

樹葉的波長則要拉到二十四格。樹冠是一團互相緊貼的方塊，波長若與草一樣短，相鄰兩塊葉子會往不同方向偏，塊與塊之間就裂出縫來。拉長之後同一棵樹幾乎整團同進同出，波的作用只剩「這棵樹與那棵樹不同步」。

<demo-sway-wave />

關掉行進波，整片草變成同步擺動，看起來像一塊在抖的地毯。打開之後那股「掃過去」的感覺立刻回來。波長拉到二十幾格則會慢慢變回同步。%(⊙ o ⊙)%

### 第三層：每一株自己的顫動

```glsl
float plantPhase = plantOrigin.x * 1.7 + plantOrigin.z * 2.3;
float flutter = sin(windFlutterPhase + plantPhase);
```

只有前兩層的話，同一小塊裡的草會整齊得像一塊布。疊一層又快又小的擾動，每一株的相位由它自己的座標決定，葉尖那種細碎的顫動就出來了。

幅度寫成佔主擺幅的比例，這樣調整主擺幅時顫動會跟著等比縮放。

這裡的相位用的是 CPU 累積好的數字。

```ts
flutterPhase += deltaSecond * FLUTTER_SPEED * (0.55 + squall * 0.5)
```

在著色器裡寫「時間乘上當下的速度」會出事。速度是會變的，而那個乘積的變化率還帶著時間本身，跑了十分鐘之後速度稍微一動就會把相位甩出去好幾圈。畫面上是整片草莫名其妙抽動一下。

每一幀只加上「這一幀該轉多少」就沒有這個問題。

## 高度槓桿

三層算出一個幅度，接下來要決定這個幅度怎麼分配到一株草的上下。

```glsl
float height = clamp(positionUpdated.y + 0.5, 0.0, 1.0);
float leverage = mix(1.0, height * height, windHeightLeverage);

vec2 sway = windDirection * amplitude * leverage;
```

`height` 是「離地多高」，零在根部、一在頂端。再平方一次，根部幾乎釘在地上，只有頂端在動。

草是從土裡長出來的，底邊不該移動。而立板只有上下兩排頂點，`leverage` 在根部是零，所以底邊在數學上不可能動，這是一個保證而不是一個調參。

`windHeightLeverage` 給零的時候，`mix` 直接回傳 1.0，整株一起平移。那是樹葉要的擺法。

樹冠是一團互相緊貼的方塊，各自彎腰的話塊與塊之間會裂開，整團同進同出才是一棵樹被風推的樣子。

<demo-sway-leverage />

槓桿拉到零，草底邊跟著跑，看起來像浮在地上的一塊布。拉到一，根就釘住了。%( ˘•ω•˘ )%

順帶一提，樹葉的幅度只給花草的三分之一，還有另一個理由。樹葉會投影子，而陰影貼圖走的是另一支著色器，影子不會跟著擺。差零點零五格看不出來，差零點一五就對不上了。

## 踩踏：記住人走過哪裡

風是整片一起晃的，那是背景。接下來這一項是「因為我在這裡」，世界對人有反應，那是走進去與看著它的差別。

### 一組腳印存成 uniform 陣列

```ts
const TRAIL_MARK_COUNT = 12

const trailState = {
  /** 每四個數字一個腳印：世界 XYZ 與此刻的強度 */
  markList: new Float32Array(TRAIL_MARK_COUNT * 4),
  ageList: new Float32Array(TRAIL_MARK_COUNT),
  nextMarkIndex: 1,
}
```

十二個腳印，每個佔一個 `vec4`。前三個分量是它蓋在哪裡，第四個是此刻還壓著多重。強度為零代表這是空位。

送進著色器就是一整包。

```ts
uniformBuffer.updateFloatArray('windTrampleList', trailState.markList)
```

第零個位置是活的，每一幀覆寫成人此刻站在哪裡。所以站著不動時，腳邊那一圈會一直伏著。

其餘十一個是走過留下的腳印，各自照自己的年齡恢復。

### 著色器這邊怎麼算

```glsl
for (int markIndex = 0; markIndex < 12; markIndex++) {
  vec4 trampleMark = windTrampleList[markIndex];
  if (trampleMark.w <= 0.0) continue;

  float trampleDistance = length(plantOrigin.xz - trampleMark.xz);

  float trampleFalloff = 1.0 - smoothstep(0.6, 1.5, trampleDistance);
  trampleFalloff *= 1.0 - smoothstep(0.0, 2.2, abs(plantOrigin.y - trampleMark.y));

  trampleAmount = max(trampleAmount, trampleMark.w * trampleFalloff);
}
```

**外圈給一格半**，差不多是一個人張開手臂。走過去時貼著身體的那一圈草讓開，再遠一點的維持原狀。這個數字放到四格半的話，整片草地會以人為中心攤平成一個大圓，那看起來像有一台壓路機開過去。

**裡面還有一個滿檔的核心。**衰減若從距離零就開始算，力道最強的地方永遠是腳底下那一株，而那一株在畫面上根本看不到，看得到的那些全落在曲線的尾巴上。核心之內一律滿檔，草才是整片一起讓開。

這兩個數字是 `smoothstep` 的上下界，顛倒過來在 GLSL 是未定義行為，畫面上會變成整片草莫名其妙地抽動。

**高度差也要算。**沒有這一項的話，站在木橋上、坐在屋頂上、跳起來的那一刻，底下的草都會跟著往外倒，那看起來像有一團看不見的東西在飄。

**十二個腳印取最重的那一個。**相加會出事。人走過去之後那一株草的前後都有腳印，兩邊方向相反、互相抵銷，合力歸零，草在人還站在旁邊時就站了起來，下一個腳印蓋下去又倒回去。

取最大值則永遠不會抵銷。而最大值是連續的，每一項都連續，逐項取 `max` 出來的包絡也連續，換誰當最大的那一刻兩者剛好相等，接得上。

### 推開的同時要壓下去

```glsl
float tramplePush = trampleAmount * windHeightLeverage * leverage;
sway += windTrampleFlow.xy * tramplePush;

positionUpdated.x += sway.x;
positionUpdated.z += sway.y;
positionUpdated.y -= tramplePush * 0.55;
```

只有橫推的話，草是整株往旁邊挪，高度卻一點沒變。人的重量要看得出來，頂端就得同時矮下去一截。

五成五配上零點七五的推開量，草尖大約從一格高沉到六成，同時橫移四分之三格。那是伏倒的樣子。

推開量給到風的五倍多也是刻意的。風是整片草一起晃，看的是節奏；踩踏是「這幾株被讓開了」，看的是對比，推得不夠明顯就等於沒做。

下壓與橫推同樣乘在 `leverage` 上，而 `leverage` 在根部是零，所以壓下去的永遠是上半截，草的根不會沉進土裡。

<demo-trample-push />

三個滑桿一起看最清楚。下壓比例歸零時草只是平移，畫面上完全沒有重量。%(๑•́ ₃ •̀๑)%

### 倒向哪一邊

方向全場共用一個，存成角度。

```ts
const targetAngle = Math.atan2(moveZ, moveX)
let deltaAngle = (targetAngle - trailState.flowAngle) % (Math.PI * 2)
if (deltaAngle > Math.PI)
  deltaAngle -= Math.PI * 2
if (deltaAngle < -Math.PI)
  deltaAngle += Math.PI * 2

const turnLimit = TRAIL_FLOW_TURN_RATE * deltaSecond
trailState.flowAngle += Math.min(turnLimit, Math.max(-turnLimit, deltaAngle))
```

每個腳印各記一個方向的話，一條走過又走回來的路上會出現方向相反的腳印，加起來同樣是互相抵銷。共用一個方向就不會，代價是轉彎時身後那條舊的痕會跟著轉過來。

這裡存的是角度，理由是轉向要能限速。兩個相反的單位向量做內插，中途會經過零向量，而零向量正規化出來的方向是跳的。原地前後走的時候，每一次改變方向都會踩到這件事。

改成每一幀往目標角度轉一小段，一百八十度的迴轉要花大半秒，中間會經過側面。那正是「草被掃過去」的樣子。

## 恢復曲線與輪流覆寫

腳印蓋下來之後要慢慢站回原狀。

```ts
function measureRecovery(age: number): number {
  const ratio = Math.min(1, Math.max(0, age / TRAIL_RECOVER_SECOND))

  return 1 - ratio * ratio * (3 - 2 * ratio)
}
```

一樣是 smoothstep 反過來用，一是全倒、零是站直。平滑收尾很重要，草不該在恢復的最後一刻啪地彈回去。

恢復時間給一秒。這是「回頭還看得到」與「草是活的」之間的那個點。真正的草只需要一兩秒就撐回去了，給到六秒的話身後那條徑遲遲不闔上，看起來像地上留著一條被踩出來的凹痕。

<demo-trample-recover />

關掉記憶就只剩人此刻站的那一圈，走開的瞬間草整片彈起來，看起來像草在躲人。%( ´ ▽ ` )ﾉ%

### 腳印數量有限，所以要輪流覆寫

```ts
trailState.nextMarkIndex = trailState.nextMarkIndex + 1 >= TRAIL_MARK_COUNT
  ? 1
  : trailState.nextMarkIndex + 1
```

繞回一而不是零。第零個位置是活的，不參與輪替。

這裡有個要處理的狀況。十二個位置蓋滿之後，最舊的那一個會被新的覆寫掉，而它當時往往還壓著八成。被覆寫的那一刻，它壓著的那片草是**瞬間**站回原狀的。

這件事有多快發生，取決於蓋腳印的速度。間距固定零點八五格、人走五點二格每秒，一秒六個，十一個位置一點八秒就繞完一圈。恢復要走完一秒的話還好，要是給到六秒，每一秒多都有一片草無聲地彈起來。「慢慢站回來」寫在恢復曲線裡，畫面上卻永遠看不到，因為沒有一個腳印活得到那個時候。

解法是讓一圈的長度追上恢復的時間。

```ts
function measureStampDistance(speed: number): number {
  const span = speed * TRAIL_RECOVER_SECOND / (TRAIL_MARK_COUNT - 1)

  return Math.min(TRAIL_STAMP_DISTANCE_MAX, Math.max(TRAIL_STAMP_DISTANCE_MIN, span))
}
```

一圈涵蓋的路是「間距乘上位置數」，走完它要「那段路除以速度」秒。要它不短於恢復時間，間距就得跟著速度走。跑起來時腳印散開，慢慢晃時腳印變密。

於是最舊的那一個總是在恢復完之後才被回收，覆寫掉的永遠是一個已經站直的位置。

上下限也各有用途。下限管的是慢慢晃過去時不要蓋得太密，上限管的是兩個腳印之間不能脫節，間距超過核心的直徑，走過的路就會斷成一串圓點。

### 速度要自己量

```ts
const frameSpeed = deltaSecond > 0
  ? Math.hypot(footX - trailState.lastFootX, footZ - trailState.lastFootZ) / deltaSecond
  : 0

trailState.speed += (Math.min(TRAIL_SPEED_MAX, frameSpeed) - trailState.speed)
  * Math.min(1, deltaSecond * TRAIL_SPEED_FOLLOW)
```

直接拿這一幀的位移除以時間會抖得很厲害。撞到方塊、跳起來、掉幀都會讓某一幀的瞬時速度暴衝，而腳印的間距跟著暴衝就會在路上開一個洞，所以要先夾住上限再平滑。

夾子那個上限是給瞬移用的。快速前往那一幀的位移有幾十格，不夾的話平滑後的速度會被那一下推高好幾秒。

為什麼不去跟漫遊控制器要一個常數？那個常數改了，這裡不會知道，而位移是量得到的。

## 完整實作

`wind-sway.ts` 整支做的事排一次。

1. 場景每一幀推進時間、整場風的強弱與顫動的相位
2. 依人的位移更新軌跡，蓋新腳印、讓舊腳印恢復
3. 每一份材質綁定時把這些數字寫進 uniform buffer
4. 頂點著色器逐頂點算出風的位移與踩踏的位移，一起加到區域座標上

```ts
export function createWindSway(scene: Scene): WindSway {
  const pluginList: WindSwayPlugin[] = []

  scene.onBeforeRenderObservable.add(() => {
    const deltaSecond = scene.getEngine().getDeltaTime() / 1000
    elapsedSecond += deltaSecond
    squall = measureSquall(elapsedSecond)
    flutterPhase += deltaSecond * FLUTTER_SPEED * (0.55 + squall * 0.5)

    updateTrail(scene, deltaSecond, devToggle.grassTrample)

    for (const plugin of pluginList) {
      plugin.setWindState(elapsedSecond, squall, flutterPhase)
    }
  })

  return { attach, dispose }
}
```

## 總結 🐟

以上程式碼可以[在此取得](https://github.com/Codfisher/cod-aquarium/tree/main/content/aquarium/minespace)

- 上萬株草共用一份頂點資料，要各自彎腰就只能寫在頂點著色器裡
- 注入點在世界矩陣之前，所以動的是區域座標，`world3.xyz` 才是那一株的世界座標
- 柏林噪聲管「這一帶風多大」，行進波管「一株接一株倒下去」
- `leverage` 在根部是零，所以底邊在數學上不可能移動
- 腳印取最重的那一個，相加會在來回走的路上互相抵銷
- 腳印的間距跟著速度算，最舊的那一個才會在恢復完之後才被回收
