# Minespace - EP01：燈火光暈

大家好，我是鱈魚。

這個系列會把 Minespace 裡每一個特效拆開來講，從最單純的原理開始，一路做到專案裡實際跑的版本。%( •̀ ω •́ )✧%

第一章從燈火的光暈開始，因為它不需要寫任何著色器，用現成的網格與材質就做得出來。

## 為什麼需要光暈

方塊世界裡的燈籠，材質上會給它自發光。

```ts
const material = new StandardMaterial('lantern', scene)
material.emissiveColor = new Color3(1, 0.86, 0.62)
```

自發光的意思是「這顆方塊自己會亮」，跟場景裡有沒有燈完全無關。

問題在於自發光只影響這顆方塊自己的像素。方塊的邊界一到，亮度就停在那裡，光完全沒有溢出去。%(´･_･`)%

現實裡的燈不是這樣。空氣裡有灰塵與水氣，光走過去會散射，所以我們看到燈的周圍有一團暈；眼睛本身也會散射，湊近看更明顯。

<demo-glow-basic />

關掉光暈的時候，那顆方塊確實是亮的，卻怎麼看都像一塊會發光的貼紙。加上圓盤之後才有「這裡點著一盞燈」的感覺。%ヽ(●`∀´●)ﾉ%

路人：「所以光暈就是在燈前面貼一張圖？」
鱈魚：「對，而且是一張永遠正對著你的圖。」

## 第一步：一片永遠面向鏡頭的圓盤

先把最小的版本做出來。

```ts
const halo = MeshBuilder.CreateDisc('halo', { radius: 1.8, tessellation: 32 }, scene)
halo.billboardMode = Mesh.BILLBOARDMODE_ALL
halo.position.copyFrom(lampPosition)
```

`BILLBOARDMODE_ALL` 讓這片網格永遠轉向鏡頭。走到燈的側面、繞到背後，看到的都是同一個正圓。

這裡用圓盤而不是方片，有兩個理由。

第一個是省。光暈的衰減是放射狀的，方片的四個角落在衰減曲線之外，那一圈永遠是白算的片元。

第二個理由更要緊。萬一邊界上還剩下任何一點亮度，方片露出來的會是一個方形；圓盤露出來的至少還是一圈圓。%( ˘•ω•˘ )%

## 第二步：把衰減畫進貼圖

接著要一張中心亮、往外化開的圖。用 `DynamicTexture` 開一張畫布，畫一圈放射狀漸層就好。

```ts
const texture = new DynamicTexture('glow', { width: 128, height: 128 }, scene, false)
const context = texture.getContext()

const center = 64
const gradient = context.createRadialGradient(center, center, 0, center, center, center)
```

這裡有個關鍵，衰減要畫在**顏色**上，不要畫在透明度上。

光暈走的是相加混合，透明度在那條路上不起作用，只有顏色會加到畫面上。所以把該有的透明度先乘進顏色裡，一路收到全黑就對了。黑色加上去等於沒加，暈開的效果自然就出來。

```ts
for (let index = 0; index <= 32; index++) {
  const ratio = index / 32
  const intensity = measureFalloff(ratio)

  gradient.addColorStop(
    ratio,
    `rgb(${255 * intensity}, ${220 * intensity}, ${160 * intensity})`,
  )
}
```

### 衰減曲線挑哪一條

最直覺的寫法是直線，從中心的 1 一路降到邊緣的 0。

```ts
function measureFalloff(ratio: number) {
  return 1 - ratio
}
```

這條線有個麻煩的地方在於它走到底會**突然**變成零。

人眼對亮度的轉折特別敏感，這個現象叫馬赫帶效應（Mach bands）。一條直線斜坡走到底忽然平掉，就算兩側只差一個色階，那道界線照樣看得一清二楚。

換成 `(1 - t²)^n` 這一族曲線就沒有這個問題，它在邊緣的值與斜率同時是零。

```ts
function measureFalloff(ratio: number) {
  const base = Math.max(0, 1 - ratio * ratio)

  return 0.55 * base ** 8 + 0.45 * base ** 3
}
```

兩項相加，次方高的那項是緊實的核心，次方低的那項鋪出長長的尾巴。

<demo-glow-falloff />

亮度拉到 1 以上，左邊那團的邊界就浮出來了，右邊那團則是一路化開到看不見。%(⊙ o ⊙)%

順帶一提，漸層停點要給得夠密。畫布的漸層在停點之間走的是直線，段數太少的話每個停點上都會留下一個折角，那正是我們想避開的東西。三十二段之後，每一段的轉折都小於一個色階。

## 第三步：相加混合

材質這邊有五個設定要一起下。

```ts
const material = new StandardMaterial('halo', scene)

material.diffuseTexture = texture
material.diffuseColor = new Color3(0, 0, 0)
material.emissiveColor = new Color3(1, 1, 1)
material.disableLighting = true

material.alphaMode = Constants.ALPHA_ADD
material.alpha = 0.999
material.disableDepthWrite = true
```

逐項來說。

**貼圖掛在 `diffuseTexture`**，不要掛在 `emissiveTexture`。Babylon 的自發光是「顏色加上貼圖」，掛在自發光上的話，顏色調黑貼圖照樣全亮。關掉光照之後走 diffuse 那條路才是我們要的乘法，自發光的顏色就成了乾淨的亮度乘數。

**`ALPHA_ADD`** 就是相加混合，把顏色直接加到已經畫好的畫面上。光本來就是相加的，兩盞燈照同一個地方會更亮。

**`alpha = 0.999`** 這行看起來很怪。Babylon 要材質走半透明那條路，相加混合才會生效，而 alpha 剛好等於 1 會被歸類成不透明。差那 0.001 就是為了讓它落到正確的那一邊。%(´,,•ω•,,)%

**`disableDepthWrite`** 是說「別留下深度」。暈是空氣裡的一團光，不是一塊擋得住東西的板子。照常寫深度的話，燈後面的東西會被那片看不見的圓盤整齊地切掉。

路人：「那不寫深度，光暈會不會跑到牆前面？」
鱈魚：「它照樣要通過深度測試，只是不留下自己的深度。牆比它近的話還是擋得住。」

## 第四步：把圓盤挪出方塊之外

現在有個很實際的狀況要處理。

光源的座標是燈籠那顆方塊的中心，而方塊是不透明的、會寫深度。於是整團暈最亮的核心永遠埋在方塊裡面，只剩外圈那幾階近乎全黑的地方露得出來。

解法是每一幀把圓盤沿著「這盞燈往鏡頭看過去」的方向挪出來。

```ts
const toCamera = new Vector3()

scene.onBeforeRenderObservable.add(() => {
  toCamera.copyFrom(camera.position).subtractInPlace(origin)
  const distance = toCamera.length()

  const lift = Math.min(0.95, distance * 0.5)
  halo.position.copyFrom(origin).addInPlace(toCamera.scaleInPlace(lift / distance))
})
```

圓盤本來就永遠面向鏡頭，所以不論從哪個角度走過去，它都剛好浮在那顆方塊的前面。

<demo-glow-lift />

偏移量給 0.95 是算出來的。一顆方塊的半對角線是 0.866，挪 0.95 剛好從任何角度都繞得出來，而它遠小於一堵牆的厚度，所以「隔著牆看不到燈」這件事仍然成立。%( •̀ ω •́ )✧%

`Math.min` 那一行是給貼很近的時候用的。人臉快要碰到燈的時候照樣挪 0.95，會把圓盤送到鏡頭背後，那盞燈反而在走近的最後一步憑空消失。

## 第五步：亮度隨晝夜走

夜裡的燈該搶眼，白天則要收斂。

```ts
const NIGHT_STRENGTH = 0.85
const DAY_STRENGTH_RATIO = 0.45

const dayRatio = getDayRatio()
const strength = NIGHT_STRENGTH * (1 - dayRatio * (1 - DAY_STRENGTH_RATIO))
```

白天保留四成五，而不是收到零。一盞點著的燈就算在正午也還是點著的。

這裡有個容易忽略的地方，白天要留的比例得給得比直覺高。畫面出去還要過一次 ACES 色調映射，而那條曲線在高處壓縮得很兇。夜裡加 0.17 是一團明顯的光，白天加同樣的 0.17 幾乎整個被壓掉。%(›´ω`‹ )%

亮度寫在材質的自發光上，所以幾十盞燈只要改兩三個顏色物件。

```ts
for (const entry of materialMap.values()) {
  const [red, green, blue] = entry.color
  entry.material.emissiveColor.set(red * strength, green * strength, blue * strength)
}
```

材質依光色分組就好。整個世界的燈火其實只有兩種顏色，燈籠的暖黃與火的橘。

## 第六步：靠近實體時化開

最後補一個細節。

光暈是一片平的圓盤，貼著牆或地面的時候，圓盤與那個平面會交出一條筆直的線。空氣裡的一團光不該有直邊。

處理方式是拿一張場景深度圖，比對這個片元與它背後實體的距離，靠得越近就越淡。

```glsl
float gap = max(sceneDepth - fragmentDepth, 0.0);
float fade = smoothstep(0.0, softDistance, gap);
```

這一段要寫進著色器，屬於材質外掛的範圍，之後講到大氣透視時會完整說明那套機制。

## 完整實作

把六個步驟組起來，就是專案裡 `lamp-glow.ts` 在做的事。

流程整理一次。

1. 世界生成完掃一次，收集所有夠亮的光源方塊
2. 依光色建立材質，一種顏色一份
3. 每盞燈給一片圓盤，半徑跟著亮度等級縮放
4. 每一幀把圓盤挪到方塊之外，並依晝夜更新亮度

```ts
const haloList = sourceList.map((source, index) => {
  const size = (source.isFire ? FIRE_SIZE : LAMP_SIZE) * source.level

  const mesh = MeshBuilder.CreateDisc(
    `lamp-halo-${index}`,
    { radius: size / 2, tessellation: 24 },
    scene,
  )
  mesh.material = getMaterial(source.color, source.isAreaLight)
  mesh.billboardMode = Mesh.BILLBOARDMODE_ALL
  mesh.isPickable = false

  return { mesh, origin: new Vector3(source.x, source.y, source.z) }
})
```

岩漿這種一整片的光源要另外處理。一池岩漿上灑十幾顆圓盤，相加混合疊起來會是一塊沒有層次的白，所以單片的濃度要壓到三成半，重疊處剛好回到一團火的亮度。

圓盤的邊數也留了餘裕。世界上每一盞燈都是一片這樣的圓盤，省下來的頂點是乘上燈數的，所以低畫質收到十邊，那時候它本來就糊成一團，看不出是幾邊形。%( ´ ▽ ` )ﾉ%

## 總結 🐟

以上程式碼可以[在此取得](https://github.com/Codfisher/cod-aquarium/tree/main/content/aquarium/minespace)

- 自發光只讓方塊自己亮，光要溢出來得靠額外的網格
- 光暈是一片 `BILLBOARDMODE_ALL` 的圓盤，配上相加混合
- 衰減曲線在邊緣的斜率也要是零，`(1 - t²)^n` 這一族剛好
- 圓盤每一幀往鏡頭的方向挪 0.95，才不會埋在自己的方塊裡
- 白天保留四成五的亮度，色調映射會吃掉一大截
