# Minespace - EP06：葉片透光

大家好，我是鱈魚。

黃昏的時候站在樹下往太陽的方向看，整棵樹會亮起來。葉子的邊緣透出黃綠，樹冠像一盞燈。

方塊世界裡的樹在同一個時刻剛好相反。背對太陽那一側只吃得到環境光，於是逆光時整團最暗，那是它最不像樹的一刻。%(´･_･`)%

這一章把它換過來。

## 為什麼葉子在逆光裡會亮

光打到不透明的東西上就停在表面，反彈回來的那一部分就是我們看到的顏色。葉子不一樣，它薄到光可以直接穿過去。

穿的過程裡，光會在葉肉的細胞之間反覆彈跳，出來的時候方向已經散開了，顏色也被葉綠素吃掉一部分。這件事有個名字叫**次表面散射**（subsurface scattering），皮膚、蠟燭、牛奶、玉，全部靠它。

<demo-leaf-backlit />

關掉的時候那團樹冠只是一塊深綠色的東西。打開之後才有「太陽在它背後」的感覺。%ヽ(●`∀´●)ﾉ%

鱈魚：「知道了，那就把整棵樹改成半透明！」
路人：「那會變成一叢塑膠花吧！%(´・ω・`)%」
鱈魚：「開玩笑的啦，只要讓背光那一面多加一道光就好。」

## 正經做法有多貴

真的要算次表面散射，得先知道兩件事。

第一件是光在葉子裡走了多遠。這要量「光從哪一點進去、從哪一點出來」，中間隔著多少材質。

第二件是那段路上被吃掉多少。不同波長被吃掉的比例不同，所以出來的光會偏色。

即時繪圖裡通常拿一張厚度圖來逼近第一件事，那張圖要另外烘。而一顆一格見方的樹葉方塊沒有厚度圖，它只是一顆方塊。%( ˘•ω•˘ )%

所以這裡走另一條路。

## 第一步：用「視線與光線多接近」當近似

觀察一件事，光穿過薄的東西之後，大致還是順著原本的方向繼續走。散射會讓它偏一點，但主要的能量還在原方向上。

那麼「我看得到多少透過來的光」就約等於「我的視線與那道光線有多接近」。

一次點積就量得出來。

```glsl
float forward = max(dot(viewDirection, sunDirection), 0.0);
```

`viewDirection` 是從表面指向眼睛的方向，`sunDirection` 是光線前進的方向。太陽正在樹的另一頭、光直直朝著我走過來的時候，兩者重合，點積是一。

問題是點積給出來的曲線太胖。它要到夾角九十度才歸零，也就是站在樹的側面照樣看得到透光，那不合理。

加一次次方就收得起來。

```glsl
float forward = pow(max(dot(viewDirection, sunDirection), 0.0), 3.5);
```

<demo-leaf-forward />

次方給到 1 的時候整棵樹不管從哪個方向看都在發光，那已經是自發光了。給到 16 則只剩太陽正後方那一點，走過去根本遇不上。%(⊙ o ⊙)%

三點五大約是「視線與光線夾角三十度以內看得出來」，一天裡剛好接得住清晨與黃昏那兩段。

## 第二步：把亮區化開

上一步的式子有個地方要修。

純粹順著光線走的話，亮的只有「視線與光線完全重合」那一條線。玻璃走的正是那條路，光進去多少方向、出來就多少方向。

葉子則已經把光散開了，該亮的是一整片。

做法是把出射方向往法線的反面偏一點。

```glsl
vec3 throughDirection = normalize(sunDirection - surfaceNormal * distortion);
float forward = pow(max(dot(viewDirection, throughDirection), 0.0), 3.5);
```

法線指向葉子的外側，減掉它就是往內側扳。每一片葉子的法線方向都不一樣，於是每一片透出來的方向也各自偏一點，整團樹冠的亮區自然就化開了。

<demo-leaf-distortion />

偏移量拉到 0.35 左右，鏡頭繞過太陽背後的那一段路上，整片樹冠會一直亮著。%( •̀ ω •́ )✧%

## 第三步：只加在背光面

現在有件很要緊的事。

正對太陽的那一面已經被直射光照亮了。在那一面上再加一次透光，等於同一道光算了兩遍。

會透光的是背著太陽的那一側，那正是原本最暗的地方。

```glsl
float backFacing = 1.0 - max(dot(surfaceNormal, -sunDirection), 0.0);
```

`-sunDirection` 是「往太陽看過去」的方向。法線與它同向代表這一面朝著太陽，那個點積接近一，減完之後剩下零，透光整個收掉。

<demo-leaf-backface />

關掉這道限制之後，向光側整片過曝。%(›´ω`‹ )%

路人：「這一行是為了省效能嗎？」
鱈魚：「它擋掉的是一份本來就不該存在的光，效能只是順便。」

## 第四步：乘上葉子自己的顏色

透過來的光帶著葉子本身的顏色。綠葉透出來的是黃綠，楓葉透出來的是橘紅。

要為每一種葉子各調一組顏色嗎？不必。方塊的顏色本來就在貼圖裡，把透光乘上去就對了。

```glsl
color.rgb += leafTranslucency(viewDirectionW, normalW) * baseColor.rgb;
```

<demo-leaf-tint />

`baseColor` 是貼圖取樣出來的結果，這件事有兩層意思。

**一是顏色**。綠葉透綠、楓葉透橘，一份程式碼吃下所有葉子。

**二是遮蔽**。方塊的環境遮蔽與燈火都烘在這個顏色裡，所以樹冠深處那幾片本來就照不到光的葉子，透光也會跟著弱下去。

這裡要乘的是 `baseColor`。Babylon 的 `diffuseColor` 只是材質上那個色票，貼圖的內容進不去，所以葉子的顏色一定要畫進貼圖裡。範例的 `createLeafTexture` 做的就是這件事。

## 第五步：加在霧之前

注入點挑 `CUSTOM_FRAGMENT_BEFORE_FOG`。

```ts
class LeafTranslucencyPlugin extends MaterialPluginBase {
  getCustomCode(shaderType: string) {
    if (shaderType !== 'fragment')
      return null

    return {
      CUSTOM_FRAGMENT_BEFORE_FOG: `
        color.rgb += minespaceLeafTranslucency(viewDirectionW, normalW) * baseColor.rgb;
      `,
    }
  }
}
```

遠處的樹冠與近處的一樣會透光，但那道光也要跟著被霧吃掉。加在霧之後的話，霧裡會浮出一片發亮的葉子，遠山糊成一團而樹葉還亮著。

這個位置還有兩個好處。

一是 `viewDirectionW` 與 `normalW` 到這裡都算好了，直接拿來用。

二是它落在 Babylon 夾住漫射亮度那道 clamp 的外面。逆光的樹冠因此可以真的超過一，後面的色調映射會把它收回畫面裡。

## 第六步：只掛在該掛的材質上

石頭不會透光。

材質外掛的完整機制在 EP05 雲影那一章講過，這裡只用到它的開關。外掛建立時把「預設啟用」那一格傳 `false`，材質工廠依配方再打開。

```ts
class LeafTranslucencyPlugin extends MaterialPluginBase {
  private amount = 0

  constructor(material: Material) {
    /** 倒數第二個參數是「預設不啟用」 */
    super(material, PLUGIN_NAME, 220, {}, true, false)
  }

  setAmount(amount: number): void {
    if (this.amount === amount)
      return

    this.amount = amount
    this._enable(amount > 0)
  }
}
```

`_enable(false)` 的意思是這段程式碼連編都不會編進著色器。石頭、泥土、木頭那兩百多份材質，著色器裡一個字都不會多。

這與「算完再乘上零」差很多。乘零的版本照樣要跑那一次點積、那一次次方、那一次正規化。

打開的那幾份只有樹葉與花草。

```ts
export function setLeafTranslucency(material: StandardMaterial, amount: number): void {
  const plugin = material.pluginManager?.getPlugin<LeafTranslucencyPlugin>(PLUGIN_NAME)
  plugin?.setAmount(amount)
}
```

## 第七步：兩種植物給不一樣的量

樹葉 0.8，花草 1。

```ts
export const LEAF_TRANSLUCENCY = 0.8
export const PLANT_TRANSLUCENCY = 1
```

地上的草與花瓣只有一層細胞那麼薄，逆光時幾乎是半透明的。樹冠那一團則是好幾片葉子疊在一起，光要穿過去會被吃掉更多。

## 第八步：跟著這一刻的陽光走

透光的量與顏色每一幀寫一次，材質綁定時自己來讀。

```ts
export function updateLeafTranslucency(
  sunDirection: Vector3,
  sunColor: Color3,
  strength: number,
  isEnabled = true,
): void {
  const length = Math.hypot(sunDirection.x, sunDirection.y, sunDirection.z) || 1
  sunState.directionX = sunDirection.x / length
  sunState.directionY = sunDirection.y / length
  sunState.directionZ = sunDirection.z / length

  const ratio = isEnabled ? Math.min(1, Math.max(0, strength)) : 0
  sunState.red = sunColor.r * ratio
  sunState.green = sunColor.g * ratio
  sunState.blue = sunColor.b * ratio
}
```

方向一定要正規化過。出射方向是拿它與視線做點積算出來的，長度不等於一的話那個夾角就錯了，而日夜循環寫進來的方向不保證是單位向量。%(´,,•ω•,,)%

`strength` 吃的是「直射陽光還剩幾成」。雲層把太陽打散之後，天空整片還是亮的，但沒有一道明確的方向可以透，葉子也就不再發亮。專案裡直接拿大氣參數的 `specularRatio` 來用，那個值量的正是同一件事。

夜裡換成月光時光源強度掉到很低，葉子跟著暗下去。月光確實透不過一片葉子。

## 完整實作

整章整理成一次。

1. 註冊外掛，預設關著
2. 材質工廠依配方打開樹葉與花草那幾份
3. 每一幀寫入太陽的方向、顏色與此刻的強度
4. 片元著色器裡算出透光量，乘上貼圖顏色，加在霧之前

核心那幾行放在一起是這樣。

```glsl
vec3 minespaceLeafTranslucency(vec3 viewDirection, vec3 surfaceNormal) {
  float backFacing = 1.0 - max(dot(surfaceNormal, -leafTranslucencySun.xyz), 0.0);

  vec3 throughDirection = normalize(
    leafTranslucencySun.xyz - surfaceNormal * leafTranslucencyColor.a
  );
  float forward = pow(
    max(dot(viewDirection, throughDirection), 0.0),
    leafTranslucencySun.w
  );

  return leafTranslucencyColor.rgb * forward * backFacing;
}
```

一次點積、一次次方、一次正規化，換來一天裡最好看的兩段。%♪( ◜ω◝و(و%

## 總結 🐟

以上程式碼可以[在此取得](https://github.com/Codfisher/cod-aquarium/tree/main/content/aquarium/minespace)

- 葉子在逆光裡會亮是次表面散射，而算它要知道厚度，方塊沒有那張圖
- 光穿過薄物之後大致順著原方向走，所以「視線與光線多接近」就約等於透出來多少
- 點積太胖，加一次次方收緊；出射方向往法線反面偏一點，亮區才化得開
- 只加在背光面，向光面已經被直射光照亮了
- 乘上 `baseColor`，綠葉透綠、楓葉透橘，順便吃到方塊的環境遮蔽
- 加在霧之前，遠處的透光才會跟著被霧收掉
