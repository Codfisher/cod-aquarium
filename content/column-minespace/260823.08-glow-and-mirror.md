# Minespace - EP08：光暈與水面倒影

大家好，我是鱈魚。

方塊的自發光只讓燈自己看起來是亮的，光並沒有溢出它的邊界。

夜裡少了那一圈暈，一排燈籠看起來像貼在木架上的亮貼紙。%(›´ω`‹ )%

這一章來把光暈與倒影補上。

## 為什麼不用 GlowLayer

Babylon 有現成的 `GlowLayer`，第一直覺當然是拿來用。

但它是一道後製。它把發光的網格單獨重畫進一張離屏圖、模糊、再加回成品上，整個過程與場景的深度完全無關。

也就是說，隔著一堵牆也看得到牆後的燈在發光。%(⊙ o ⊙)%

對一個到處是實心方塊、還有洞穴的世界來說那是不能接受的。

有辦法讓它擋得住，把不發光的網格也一起加進那一層，讓它們畫成全黑。但那等於整個場景在離屏圖上再畫一趟，代價與自己開一張深度圖一樣，換來的卻是「暈的形狀跟著方塊的輪廓走」。

那不是這裡要的形狀。

所以改成一盞燈一顆圓盤網格。幾十次繪製呼叫換一個看得到的效果，而且它們是幾何而不是後製，被牆擋住就真的不見。%( •̀ ω •́ )✧%

## 整件事唯一的難處

這是我卡最久的一段。%(´థ‸థ)%

把圓盤擺在光源座標上，畫面上什麼都看不到。換了三種畫法都沒用。

原因是光源的座標就是燈籠那顆方塊的中心。方塊是不透明的、會寫深度；光暈雖然自己不寫深度，卻照樣要通過深度測試。

於是整團暈最亮的核心永遠被它自己那顆方塊擋住，只剩外圈那幾階近乎全黑的地方露得出來。

問題從來不在怎麼畫，而在擺在哪裡。%( ˘•ω•˘ )%

```ts
const HALO_LIFT = 0.95
```

解法是把那片圓盤沿著「往鏡頭看過去」的方向挪出方塊之外。

一顆方塊的半對角線是 0.866，挪 0.95 剛好從任何角度都繞得出來。而它遠小於一堵牆的厚度，所以「隔著牆看不到燈」這件事仍然成立。

```ts
for (const halo of haloList) {
  toCamera.copyFrom(camera.position).subtractInPlace(halo.origin)
  const distance = toCamera.length()
  if (distance < 0.001) {
    halo.mesh.position.copyFrom(halo.origin)
    continue
  }

  const lift = Math.min(HALO_LIFT, distance * 0.5)
  halo.mesh.position.copyFrom(halo.origin).addInPlace(toCamera.scaleInPlace(lift / distance))
}
```

滑桿一開始是零，也就是我卡了很久的那個狀態。

<demo-halo-lift />

零的時候畫面上只剩燈籠自己在亮，暈完全看不到。慢慢往上拉，光暈就從方塊後面繞出來了。%(๑•̀ㅂ•́)و✧%

圓盤本來就永遠面向鏡頭，所以不論從哪個角度走過去，它都剛好浮在那顆方塊的前面。

貼得很近時要收手。照樣挪 0.95 會把圓盤送到鏡頭背後，那盞燈反而在走近的最後一步憑空消失。%(・∀・(・∀・(・∀・*)%

## 光暈的材質

```ts
const material = new StandardMaterial(`lamp-halo-${key}`, scene)
material.diffuseTexture = texture
material.diffuseColor = new Color3(0, 0, 0)
material.specularColor = new Color3(0, 0, 0)
/** 不吃光照，畫面上的顏色就只剩自發光乘上貼圖 */
material.disableLighting = true
/** 暈是一團自己在發的光，讓它往霧色混只會在夜裡把它染成一塊灰 */
material.fogEnabled = false
material.backFaceCulling = false
material.alphaMode = Constants.ALPHA_ADD
material.alpha = 0.999
/** 暈是空氣裡的一團光，不是一塊擋得住東西的板子 */
material.disableDepthWrite = true
```

`disableDepthWrite` 很重要。照常寫深度的話，燈後面的東西會被那片看不見的圓盤切掉。

材質只建兩份。光色就燈籠的暖黃與火的橘兩種，顏色寫在材質上，每一幀調亮度時只要改兩個顏色物件。

```ts
const key = `${color.join(',')}_${isAreaLight ? 'area' : 'point'}`
```

鍵要帶上面光源這個旗標。岩漿與餘燼共用同一組火色，只用顏色當鍵的話兩者會拿到同一份材質，而它們的濃度必須不一樣。

## 白天也留一點

```ts
const NIGHT_STRENGTH = 0.85
const DAY_STRENGTH_RATIO = 0.45

const dayRatio = Math.min(1, Math.max(0, getDayRatio()))
const strength = NIGHT_STRENGTH * (1 - dayRatio * (1 - DAY_STRENGTH_RATIO))
```

從全暗的滿檔淡到大白天的四成五，而不是淡到零。一盞點著的燈就算在正午也還是點著的。

這個數字曾經是 0.22，照抄燈池那邊真光的白天比例。那是錯的。%( ˘•ω•˘ )%

兩者的處境不同。真光是乘法，它讓照到的表面變亮；光暈是加法，它把一團光疊在已經很亮的背景上。

加法在亮處吃虧得多。畫面出去還要經過 ACES 色調映射，而那條曲線在高處壓縮得很兇。夜裡加 0.17 是一團明顯的光，白天加同樣的 0.17 幾乎整個被壓掉，等於沒加。

## 岩漿是另一套參數

一整片岩漿液面上每兩格一顆圓盤，幾十片相加疊起來只會糊成一塊白。

這個觀察沒有錯，錯在結論。當初的結論是「整個不畫」，該調的其實是格距與濃度。

```ts
/** 比一團營火再大一截，是要它蓋得過四格的格距 */
const AREA_LIGHT_SIZE = 7.5
/** 單片壓到三成半，重疊處剛好回到一團火的亮度 */
const AREA_LIGHT_STRENGTH_RATIO = 0.35
```

三處一起改。光源清單那邊把岩漿的格距放到四格一顆，數量剩四分之一；圓盤放大到蓋得過那個格距；單片的濃度壓到三成半。

一整池的亮度是十幾片疊出來的，而不是單片給出來的。邊緣那些只有一兩片蓋到的地方就成了淡淡的熱氣。%(*´∀`)~♥%

## 光暈的衰減曲線

這一段很有趣，是關於人眼的。%(๑•̀ㅂ•́)و✧%

```ts
function measureFalloff(ratio: number): number {
  const base = Math.max(0, 1 - ratio * ratio)

  return 0.55 * base ** 8 + 0.45 * base ** 3
}
```

這個函數的形狀不是隨便挑的，關鍵在於它在邊緣的**斜率也是零**。

一團加法混合的光暈疊在平滑的天空上時，最容易露餡的不是亮度本身，而是亮度變化的轉折。

人眼會強化一階導數的不連續，這叫馬赫帶效應。一條線性的斜坡走到底突然變成零，即使兩側只差 1/255，那道界線照樣看得一清二楚。

太陽外圍那個「淡淡的方形」、換成圓盤之後的「半透明的圓」，都是這同一條界線。%(´థ‸థ)%

`(1 - t²)^n` 這一族曲線在 `t = 1` 時值與斜率同時為零，於是光暈是「化開」的而不是「切斷」的，邊界無從察覺。

<demo-glow-falloff />

左邊那團的外圍有一圈邊，而且盯久了會更明顯，那就是馬赫帶。右邊沒有。%(・∀・)%

兩項相加，次方高的那項是緊的核心，次方低的那項鋪出長長的尾巴。

### 衰減畫在顏色上，不是透明度上

```ts
const gradient = context.createRadialGradient(center, center, 0, center, center, center)

for (let index = 0; index <= STOP_COUNT; index++) {
  const ratio = index / STOP_COUNT
  const intensity = measureFalloff(ratio)
  gradient.addColorStop(
    ratio,
    `rgb(${Math.round(peakRed * intensity)}, ${Math.round(peakGreen * intensity)}, ${Math.round(peakBlue * intensity)})`,
  )
}
```

這些光暈走的是相加混合，透明度在那條路上不起作用，只有顏色會被加上去。

把該有的透明度先乘進顏色裡，一路收到全黑。黑色加上去等於沒加，暈開的效果自然就出來了。%( •̀ ω •́ )✧%

### 漸層要切夠多段

```ts
const STOP_COUNT = 32
```

這條曲線是彎的，而畫布的漸層停點之間走的是直線。

段數太少會在每個停點上留下一個折角，那正是這整件事要避免的東西。三十二段之後每一段的轉折都小於一個色階。

### 用圓盤不用方片

```ts
const mesh = MeshBuilder.CreateDisc(name, { radius: planeSize / 2, tessellation: 48 }, scene)
```

光暈的衰減是放射狀的，網格的形狀本來就該跟著它。

方片的四個角落在衰減曲線之外，那一圈永遠是浪費掉的片元。更要緊的是，一旦邊界上還剩下任何一點亮度，露出來的會是一個方形，而圓盤露出來的至少是一圈圓。

## 那道切開方塊的直邊

圓盤不寫深度，卻要通過深度測試。所以只要這個平面切進實體，交線上就會出現一道邊。

那道邊是筆直的，而暈是糊的，一團糊東西被直線切齊看起來就是穿模。%(・∀・(・∀・(・∀・*)%

掛在半空中的燈籠遇不到，坐在地上的營火與整片躺平的岩漿每次都遇到。

業界對這件事的答案叫柔性粒子（soft particle），做法只有一句話。拿一張存著場景深度的圖，比對「這個像素背後的實體有多遠」，越接近就越淡。

交線因此不是被切斷，而是化開。%(*´∀`)~♥%

```glsl
if (haloFade.z > 0.0) {
  float haloSceneZ = texture2D(haloDepthSampler, gl_FragCoord.xy * haloFade.xy).r;
  color.rgb *= clamp((haloSceneZ - vHaloViewZ) / haloFade.z, 0.0, 1.0);
}
```

<demo-soft-particle />

把柔性淡出關掉，營火那團暈與地面的交線立刻變成一條筆直的邊，牆角那裡也是。%(´థ‸థ)%

淡出距離拉大會化得更開，但拉過頭光暈連自己那堆餘燼都會躲掉，這正是它與 `HALO_LIFT` 綁在一起的原因。

### 開一張深度圖

```ts
const depthRenderer = scene.enableDepthRenderer(
  camera,
  false,
  false,
  /** 浮點深度圖的雙線性取樣不是每張顯卡都支援，取最近的那一格就好 */
  Texture.NEAREST_SAMPLINGMODE,
  /** 直接存視空間的 Z */
  true,
)

/** 沒有東西的地方要當成無限遠 */
depthRenderer.clearColor = new Color4(camera.maxZ, 0, 0, 1)
```

最後那個參數選「存視空間的 Z」而不是正規化深度。另一條路要用就得把近遠平面再乘回去，而那組數字散在相機上，日後有人動了 `maxZ` 這裡會靜靜地算錯。

`clearColor` 那一行也是踩過的坑。存視空間 Z 時的預設底色是零，那等於「實體就貼在鏡頭上」，天空前面的光暈會整團被自己淡掉。%(´థ‸థ)%

### 自己算一份視空間 Z

```ts
if (shaderType === 'vertex') {
  return {
    CUSTOM_VERTEX_DEFINITIONS: 'varying float vHaloViewZ;',
    CUSTOM_VERTEX_MAIN_END: 'vHaloViewZ = (view * worldPos).z;',
  }
}
```

不借用 `vPositionW`，那個 varying 要材質有霧或有光照才會存在，而光暈兩者都關掉了。

這裡算的式子與 Babylon 深度著色器裡那一行完全相同，兩邊比的才會是同一個量。

### 換視窗大小時要跟著換

```ts
const resizeObserver = engine.onResizeObservable.add(() => {
  depthMap.resize({
    width: engine.getRenderWidth(),
    height: engine.getRenderHeight(),
  })
})
```

這張圖是照建立當下的畫面尺寸開的，而 Babylon 不會自己重開它。

放著不管的話深度與畫面就對不起來，淡出會淡錯位置。調畫質也會走到這裡，硬體縮放一改就是一次重設大小。

### 代價

WebGL 拿不到主畫面正在用的那份深度緩衝區，所以深度圖只能自己再畫一趟。

整個場景要多跑一次，雖然著色器只寫一個數字、幾乎不吃填充率，但繪製呼叫是實打實的一倍。

這是為什麼低畫質不開，那一檔本來就在跟繪製呼叫計較，寧可留著那道邊。

```ts
const { quality } = useGraphicsQuality()
const softFade = createHaloSoftFade({ scene, camera })
const stopQualityWatch = watch(
  quality,
  (currentQuality) => softFade.setEnabled(currentQuality !== 'low'),
  { immediate: true },
)
```

順帶一提，`FADE_DISTANCE` 與 `HALO_LIFT` 是綁在一起的。

```ts
const FADE_DISTANCE = 0.6
```

圓盤與那顆方塊的正面只差 0.45 格，淡出距離一旦超過那個數字，光暈最亮的核心就會被自己的燈籠淡掉。

0.6 是踩在中間，核心保住七成五，而那道邊在貼著地面的掠射角下會被拉成一整片漸層。

## 水面倒影

換個主題，來看水鏡池。%( •̀ ω •́ )✧%

Babylon 的 `MirrorTexture` 用起來很單純。

```ts
const texture = new MirrorTexture(`water-mirror-${gardenId}`, textureSize, scene, true)
texture.mirrorPlane = new Plane(0, -1, 0, surface.surfaceY)
texture.renderList = renderList
```

鏡面方程式的法線朝下、位移等於水面高度。平面上的每一點滿足 `-y + d = 0`，也就是 `y = d`。

方向弄反的話倒影會映到水面上方去。%(・∀・(・∀・(・∀・*)%

### 天空與地景都要進來

```ts
const skyMeshList = [
  SKYBOX_NAME,
  STAR_FIELD_NAME,
  SUN_DISC_NAME,
  SUN_GLOW_NAME,
  MOON_DISC_NAME,
  MOON_GLOW_NAME,
  CLOUD_LAYER_NAME,
  OVERCAST_NAME,
]
  .map((name) => scene.getMeshByName(name))
  .filter((mesh): mesh is NonNullable<typeof mesh> => !!mesh)

const blockMeshList = scene.meshes.filter((mesh) => mesh.name.startsWith(BLOCK_MESH_PREFIX))
const renderList = [...skyMeshList, ...blockMeshList]
```

<demo-water-mirror />

把「映地景」關掉就是那塊天窗，池面上只剩雲；把「映天空」關掉則只剩岸邊的石燈籠，水面上方一片死黑。%(・∀・(・∀・(・∀・*)%

只映天空的話，池面上看得到雲飄過去，岸邊那圈石燈籠與松樹卻不在水裡。那不是一面鏡子，是一塊開在地上的天窗。

地景是逐方塊類型一個網格配 thin instance 畫的（見 EP02），所以加進來的成本是「每種方塊多一次繪製呼叫」，而不是每一顆方塊多一次。%(๑•̀ㅂ•́)و✧%

### 材質只留倒影

```ts
material.diffuseColor = new Color3(0, 0, 0)
material.specularColor = new Color3(0, 0, 0)
material.emissiveColor = new Color3(0, 0, 0)
material.disableLighting = true
material.reflectionTexture = texture
material.reflectionTexture.level = 1
/** 倒影疊在水上，不是取代水 */
material.alpha = MIRROR_STRENGTH
material.opacityTexture = fadeTexture
material.transparencyMode = Material.MATERIAL_ALPHABLEND
material.fogEnabled = false
```

反射在 `StandardMaterial` 裡是加在最後的一項，漫射與自發光留著的話會在倒影上疊一層灰。

不吃霧則是因為倒影裡的東西已經是從場景取來的顏色，各自吃過自己那一份霧了。再套一次會讓水面比它映的東西更灰。

`opacityTexture` 是一張中心滿、往外收到全透明的遮罩。倒影面是一片方形的板子，沒有這層遮罩的話，水池的四個角會露出筆直的邊。

### 水面高度用量的，不要寫死

這件事原本是寫死的，水鏡池的半徑 4.3、高度取木座那一格。

四座箱庭的水各有各的高度與形狀，照著抄四組座標，只要地形生成改一次就全錯。而且錯的樣子是「倒影浮在半空中」，沒走到那裡不會發現。%(´థ‸థ)%

改成掃描。

```ts
/** 水面高度 → 落在那一層的格柱 */
const layerMap = new Map<number, { x: number; z: number }[]>()

for (let x = minX; x <= maxX; x++) {
  for (let z = minZ; z <= maxZ; z++) {
    for (let y = WORLD_HEIGHT - 1; y >= 0; y--) {
      if (!isSurfaceBlock(getBlock(worldState, x, y, z), target.surface))
        continue

      const columnList = layerMap.get(y)
      if (columnList) {
        columnList.push({ x, z })
      }
      else {
        layerMap.set(y, [{ x, z }])
      }
      break
    }
  }
}
```

逐格柱找最上層的水，照高度分組，取格數最多的那一層。

分組是必要的。一座箱庭可能同時有主池與岸邊的小水窪，兩者高度不同，混在一起算出來的中心會落在兩池之間的岸上。

還有兩個小修正。

```ts
/** 兩片幾乎同高的半透明面會互相爭深度 */
const SURFACE_LIFT = 0.02
/** 岸線是吃噪音生成的，照著鋪會讓倒影漫到岸上的草地 */
const RADIUS_INSET = 0.35
```

### 走遠就完全不畫

倒影是要付錢的，一面鏡子等於那一帶的地景多畫一趟。

```ts
const ACTIVE_DISTANCE = 30
const CHECK_INTERVAL = 0.3

function setActive(mirror: Mirror, nextActive: boolean): void {
  if (nextActive === mirror.isActive)
    return

  mirror.isActive = nextActive
  mirror.mesh.setEnabled(nextActive)
  /** 只把網格關掉是不夠的，算繪目標是掛在場景上的 */
  mirror.texture.refreshRate = nextActive
    ? RenderTargetTexture.REFRESHRATE_RENDER_ONEVERYFRAME
    : 0
}
```

只把網格 `setEnabled(false)` 是不夠的，算繪目標掛在場景上，網格看不看得見它都照畫。頻率歸零才是真的不畫。%( •̀ ω •́ )✧%

距離檢查也不必每一幀做，0.3 秒一次就夠了。

四座箱庭彼此相距數十格，所以同一刻至多只有一面鏡子在畫。

順帶一提，人在水面以下時也要關掉。從水裡往上看不會看到倒影，那時該看到的是水面本身，而倒影面是單面的，從底下看過去只會是一片空白。

## 總結 🐟

以上程式碼可以[在此取得](https://github.com/Codfisher/cod-aquarium/tree/main/content/aquarium/minespace)

- `GlowLayer` 是後製、與深度無關，隔著牆也看得到，所以改用一盞燈一顆圓盤
- 光暈要沿著「往鏡頭看過去」的方向挪出方塊之外，這是整個效果成立的關鍵
- 衰減曲線在邊緣的斜率也要是零，否則馬赫帶效應會讓人看到一圈輪廓
- 柔性粒子靠一張場景深度圖把交線化開，代價是整個場景多畫一趟
- 水面倒影只在走近時才畫，`refreshRate` 歸零才是真的不畫
