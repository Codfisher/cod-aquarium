# Minespace - EP01：從零打造一個方塊世界

大家好，我是鱈魚。

Minespace 是一片無盡的白沙禪庭，十七座木頭底座的箱庭散落其間，每一座只收一種聲音的質地。戴上耳機走進去，走到哪裡就聽到哪裡的聲音。%( ˘ω˘ )%

這個系列會把裡面每一個特效拆開來講，一章一個。光暈、風、雲、陰影、雨雪，全部從最單純的原理開始做到專案裡實際跑的版本。

不過在講特效之前，得先有一個世界可以放特效。%੭ ˙ᗜ˙ )੭%

這一章就從一張空白的畫布開始，把方塊世界整個搭起來。

## 第一步：準備一塊畫布

先裝引擎。

```bash
npm install @babylonjs/core
```

再給它一塊畫布。

```html
<canvas ref="canvasRef" class="w-full h-full" />
```

Babylon 需要知道畫布實際有多大，所以樣式上要給它明確的尺寸，別讓它自己去猜。

## 第二步：引擎與場景

引擎負責跟 WebGL 講話，場景負責裝東西。

```ts
import { Engine, Scene } from '@babylonjs/core'

const engine = new Engine(canvas, false, {
  antialias: false,
  alpha: false,
  stencil: false,
  preserveDrawingBuffer: false,
})

const scene = new Scene(engine)

engine.runRenderLoop(() => scene.render())
window.addEventListener('resize', () => engine.resize())
```

Minespace 固定走 WebGL2，沒有開 WebGPU。WebGPU 在部分裝置上會出現難以重現的異常，而這個場景吃不到它的效能優勢，那就穩定優先。

第二個參數是抗鋸齒，這裡關掉。整個場景最後會畫進後製管線的離屏貼圖，canvas 那份多重取樣緩衝區只接得到最後那一張全螢幕方塊，上面沒有任何幾何邊緣可以抗鋸齒，等於白白配置一份記憶體與頻寬。%(›´ω`‹ )%

`runRenderLoop` 交給引擎去接 `requestAnimationFrame`，中途要暫停就呼叫 `stopRenderLoop`。畫面捲出視窗、分頁切到背景，停掉算繪迴圈是最划算的一件事。

## 第三步：鏡頭

第一人稱漫遊用 `UniversalCamera`。

```ts
import { UniversalCamera, Vector3 } from '@babylonjs/core'

const camera = new UniversalCamera('roam-camera', new Vector3(0, 12, 0), scene)
camera.attachControl(canvas, true)

camera.minZ = 0.1
/** 要看得到延伸到天邊的沙地 */
camera.maxZ = 1600
camera.fov = 1.15
```

`fov` 預設是 0.8，那個視角很窄，走在箱庭之間像從管子裡看出去。一點一五大約是六十六度，寬到看得見兩側的木座，又還沒到廣角鏡那種邊緣拉長的程度。

`minZ` 與 `maxZ` 決定深度緩衝區的精度怎麼分配。近平面壓得太近，遠處會出現兩個面互相搶著顯示的閃爍，所以 0.1 是底線，不要再小。

## 第四步：兩盞燈

場景最少要有兩盞燈。

```ts
import { Color3, DirectionalLight, HemisphericLight } from '@babylonjs/core'

const ambientLight = new HemisphericLight('ambient', new Vector3(0, 1, 0), scene)
ambientLight.intensity = 0.82
/** 天空偏冷 */
ambientLight.diffuse = new Color3(0.78, 0.88, 1)
/** 地面反射偏暖 */
ambientLight.groundColor = new Color3(0.82, 0.77, 0.72)
ambientLight.specular = new Color3(0, 0, 0)

const sunLight = new DirectionalLight(
  'sun',
  new Vector3(0.666, -0.62, -0.416).normalize(),
  scene,
)
sunLight.intensity = 1.3
/** 午後的暖陽 */
sunLight.diffuse = new Color3(1, 0.93, 0.78)
/** 高光給滿，讓材質自己決定要反射多少 */
sunLight.specular = new Color3(1, 1, 1)
```

半球光是「由上往下一個顏色、由下往上另一個顏色」，方塊的頂面、側面、底面因此有三層不同的亮度。

色溫差是重點。陽光是暖的、補光是冷的，兩者拉開才會讓畫面活起來。全部用同一種白光，再多層次也只是灰階濃淡。%( •̀ ω •́ )✧%

<demo-first-block />

先把平行光關掉，只剩半球光時最看得出那三層。木簷底下那一面完全照不到太陽，它的亮度全部來自「由下往上的地面反射色」。

再切「冷暖色溫差」，亮度層次一格都沒少，畫面卻立刻變成一張黑白照片。%(・∀・(・∀・(・∀・*)%

平行光的 `specular` 給滿這件事，後面幾章會一直用到。`StandardMaterial` 裡漫射與自發光在乘上貼圖之前就被夾在 1.0，高光則加在那道 clamp 外面，所以高光是整套渲染裡唯一能真的超過純白的通道。光源這端給滿，「這個表面有多亮」就交還給各自的材質去決定。

## 第五步：霧

```ts
scene.fogMode = Scene.FOGMODE_LINEAR
scene.fogColor = new Color3(0.955, 0.95, 0.935)
scene.fogStart = 100
scene.fogEnd = 220
```

禪庭的霧色幾乎是純白，只帶一點點沙的暖。

背景色要跟霧色設成同一個顏色。

```ts
scene.clearColor = new Color4(0.955, 0.95, 0.935, 1)
```

天空若是另一塊顏色，兩者交界就會露出一條線，而那條線要靠霧藏起來。%( ˘•ω•˘ )%

## 第六步：第一顆方塊

場景有了，來畫第一顆方塊。

```ts
import { MeshBuilder, StandardMaterial } from '@babylonjs/core'

const block = MeshBuilder.CreateBox('stone', { size: 1 }, scene)

const material = new StandardMaterial('stone-material', scene)
material.diffuseTexture = createStoneTexture(scene)
material.specularColor = new Color3(0.02, 0.02, 0.02)
block.material = material
```

貼圖是十六格見方的像素畫，取樣方式要指定成最近鄰。

```ts
const texture = new Texture(url, scene, true, false, Texture.NEAREST_SAMPLINGMODE)
```

預設的雙線性取樣會把相鄰兩格的顏色混在一起，一顆方塊放大到滿螢幕時，看到的是一片糊掉的漸層。最近鄰取樣則是老老實實地放大每一格，硬邊完全保留，那才是這套美術要的樣子。%( ´ ▽ ` )ﾉ%

到這裡，畫面上有一顆帶著石頭紋理、吃得到光的方塊。

接下來要放第二顆、第三顆，以及剩下的幾十萬顆。

## 一顆一顆畫會怎樣

Minespace 的世界是 280 格見方、40 格高。

```ts
export const WORLD_SIZE = 280
export const WORLD_HEIGHT = 40
```

實際填出來的方塊有幾十萬顆。

鱈魚：「那就跑一個迴圈建幾十萬個 `CreateBox`，很快嘛。%(๑•̀ㅂ•́)و✧%」
路人：「你的瀏覽器會先跟你說再見。」
鱈魚：「⋯⋯好啦，這條路走不通。」

問題出在繪製呼叫（draw call）。CPU 每畫一個網格，就要跟 GPU 交代一次「用這份頂點、這份材質、這個矩陣，畫」。這趟溝通本身有固定成本，跟那顆方塊有幾個三角形幾乎無關。

換句話說，一萬顆方塊就是一萬趟。CPU 整幀的時間全花在講話上，GPU 反而閒著等。%(´థ‸థ)%

自己拉一下滑桿最快。

<demo-draw-call />

左邊的繪製呼叫跟著方塊數一路往上，右邊永遠停在個位數。%(⊙ o ⊙)%

## 第七步：換成 Thin Instance

右邊那條路叫 thin instance。

同一份頂點資料配上一整條變換矩陣的緩衝區，GPU 一次畫完幾萬顆，成本只有一個繪製呼叫。

```ts
const box = MeshBuilder.CreateBox('stone', { size: 1 }, scene)
box.material = material

const matrixBuffer = new Float32Array(positionList.length * 16)
positionList.forEach(([x, y, z], index) => {
  Matrix.Translation(x, y, z).copyToArray(matrixBuffer, index * 16)
})

box.thinInstanceSetBuffer('matrix', matrixBuffer, 16, true)
```

矩陣是 4×4，所以 stride 給 16。

第四個參數的意思是「這份緩衝區是靜態的」。Minespace 的世界不可編輯，這些矩陣算好之後就再也不動，這個旗標一定要給。傳 `false` 等於告訴 Babylon 之後還會改它，於是 GPU 緩衝區以 `DYNAMIC_DRAW` 配置，驅動層會另外做搬運與反交錯。官方論壇有一個兩百五十萬個面的實測，只改這個旗標就從 15 幀變成 60 幀。%(⊙ o ⊙)%

路人：「一個布林值差四倍？」
鱈魚：「一個布林值差四倍。%( ˘•ω•˘ )%」

### 兩個必須成對的旗標

緩衝區設完之後，還有兩行要一起下。

```ts
/** 邊界盒已經在設定緩衝區時算好了 */
box.doNotSyncBoundingInfo = true
box.alwaysSelectAsActiveMesh = true
```

這兩個必須一起出現。`doNotSyncBoundingInfo` 單獨用會讓網格整個消失，因為邊界盒不再更新，視錐剔除卻照樣拿它去判斷，判成「不在畫面裡」就整批不畫了。%(・∀・(・∀・(・∀・*)%

而對 thin instance 來說，剔除本來就幫不上忙。一顆網格的邊界盒是它所有實例的聯集，在體素世界裡通常橫跨整座場景，永遠剔不掉，那幾百次測試全都白做。直接說「一律當成看得見」，省下測試也順便修掉消失的風險。

網格生成之後就再也不會動，所以世界矩陣也可以凍結。

```ts
box.freezeWorldMatrix()
box.isPickable = false
```

還有一行很容易忘。

```ts
/**
 * Babylon 預設每一次 pointermove 都會發一條射線去找游標下的網格
 * 這個場景用的是指標鎖定，游標下有什麼完全沒有意義
 */
scene.skipPointerMovePicking = true
```

## 第八步：只畫露得出來的面

繪製呼叫解決了，還有一件事沒解決。

一顆方塊有六個面。幾十萬顆方塊全部丟給 GPU，等於幾百萬個面，而其中絕大多數埋在土裡，誰也看不到。

<figure-face-culling />

所以生成矩陣的時候要順便問一句，這一面的鄰居是空的嗎。

```ts
const shouldDrawFace = (
  neighborX: number,
  neighborY: number,
  neighborZ: number,
): boolean => {
  /** 世界邊界外一律剔除，玩家走不出去，看不到外牆 */
  if (
    neighborX < 0 || neighborX >= worldSize
    || neighborZ < 0 || neighborZ >= worldSize
    || neighborY < 0
  ) {
    return false
  }
  if (neighborY >= worldHeight)
    return true

  const neighborId = worldState[coordinateToIndex(neighborX, neighborY, neighborZ)]!
  /** 鄰居是空氣，這一面看得到 */
  if (neighborId === 0)
    return true

  /** 相同方塊相鄰剔除，一整片湖水才不會把內部的面全畫出來 */
  if (neighborId === blockId)
    return false

  /** 鄰居是玻璃、水這類半透明的東西，這一面還是看得到 */
  return !!(blockFlags[neighborId]! & F_TRANSPARENT)
}
```

六個方向都問過之後，如果一個面都畫不出來，這顆方塊直接跳過。

```ts
const hasTop = shouldDrawFace(x, y + 1, z)
const hasBottom = shouldDrawFace(x, y - 1, z)
const hasFront = shouldDrawFace(x, y, z + 1)
const hasBack = shouldDrawFace(x, y, z - 1)
const hasLeft = shouldDrawFace(x - 1, y, z)
const hasRight = shouldDrawFace(x + 1, y, z)

if (!hasTop && !hasBottom && !hasFront && !hasBack && !hasLeft && !hasRight)
  continue
```

<demo-face-culling />

關掉剔除，畫面看起來一模一樣，面數卻是四倍多。切開一半就知道那些面躲在哪裡了。%(๑•̀ㅂ•́)و✧%

半透明的鄰居要特別處理。水面底下那格如果照著「鄰居不是空氣就剔掉」去做，隔著水看下去會是一片看得穿的黑。玻璃、冰、樹葉全都是同一件事。

## 第九步：把世界切成區塊

面剔除要掃過整個世界的每一格，一格要問六個鄰居。280 × 280 × 40 大約是三百一十萬格，乘六是一千八百多萬次查詢。

這件事在主執行緒上做，畫面會整個凍住。

路人：「不能直接算嗎？反正只算一次。」
鱈魚：「算得完，只是那幾秒鐘連滑鼠都動不了，讀者會以為當掉了。」

解法是切成區塊，丟給打工仔（Web Worker）。

```ts
export const CHUNK_SIZE = 56
export const CHUNKS_PER_AXIS = WORLD_SIZE / CHUNK_SIZE
export const TOTAL_CHUNKS = CHUNKS_PER_AXIS * CHUNKS_PER_AXIS
```

56 格見方一塊，整個世界切成 25 塊。

區塊刻意給得大。Minespace 的世界不可編輯，重建的粒度完全不重要，切得越碎只是讓每一塊的邊界處理成本越高。

Worker 這端用 `useWebWorkerFn` 包起來就好。

```ts
import { useWebWorkerFn } from '@vueuse/core'

const { workerFn, workerTerminate } = useWebWorkerFn(computeChunkMatricesInWorker)

const results = await workerFn(
  worldState,
  JSON.stringify(chunkList),
  blockFlags,
  lightEmissionList,
  CHUNK_SIZE,
  WORLD_HEIGHT,
  WORLD_SIZE,
)
```

這裡有個限制要記住。`computeChunkMatricesInWorker` 會先序列化，再丟進 Worker 執行，所以它必須完全自包含，不能引用任何外部模組或閉包變數。方塊的旗標、發光等級這些查表資料要一併當參數傳進去。

世界資料本身用 `Uint8Array` 存，一格一個位元組。

```ts
export function coordinateToIndex(x: number, y: number, z: number): number {
  return (x * WORLD_HEIGHT * WORLD_SIZE) + (y * WORLD_SIZE) + z
}
```

三百多萬顆方塊塞在一條連續的記憶體裡，只有三 MB 多，傳給 Worker 也快。

## 第十步：算完之後接成一條

各區塊算好了，接下來是最後一步。

切成區塊的唯一理由是讓計算能分頭跑，算完之後就沒有必要繼續分開。同一種石頭在世界各處若各留各的網格，二十五份網格每一幀主畫面與陰影各畫一次，繪製呼叫又回去了。%(´థ‸థ)%

所以把各區塊的矩陣接成一條，同一種方塊全世界共用一個網格。

```ts
/** 把一串緩衝區接成一條 */
function mergeBufferList(bufferList: Float32Array[] | undefined): Float32Array | null {
  if (!bufferList || bufferList.length === 0)
    return null

  const total = bufferList.reduce((sum, buffer) => sum + buffer.length, 0)
  if (total === 0)
    return null

  const merged = new Float32Array(total)
  let offset = 0
  for (const buffer of bufferList) {
    merged.set(buffer, offset)
    offset += buffer.length
  }

  return merged
}
```

<demo-chunk-merge />

把「接成一條」關掉，繪製呼叫立刻從一變成十六，畫面卻沒有任何差別。打開上色就看得出哪一塊是哪一塊。%ヽ(●`∀´●)ﾉ%

代價是失去逐區塊的視錐剔除。但這個世界只有 280 格見方、霧又開到 220 格，本來就幾乎整片都在視野內，剔除省不到什麼。

接的時候要等全部到齊再一次接完。每收到一塊就重設一次緩衝區的話，等於把同一份資料上傳好幾遍。

```ts
this.receivedChunkCount++
if (this.receivedChunkCount >= TOTAL_CHUNKS) {
  this.flush()
}
```

## 第十一步：需要時才建網格

還有一個很容易踩到的地方。

直覺的寫法是在建構時就替「所有有貼圖的方塊」建好網格，一種都不漏。但一個區塊裡通常只出現十來種方塊，整個世界一百多種、二十五個區塊，算下來會建出七千三百多個網格，其中八成八一個實例都沒有。

空網格照樣要進每一幀的剔除與排序，白白吃掉大量時間。

改成等 Worker 算完、知道實際用到哪些方塊之後才建。

```ts
private ensureBlockMeshes(blockId: BlockId): void {
  if (this.builtBlockSet.has(blockId))
    return

  this.builtBlockSet.add(blockId)

  const blockDef = BLOCK_DEFS[blockId]
  if (!blockDef || blockDef.isHidden || !blockDef.textures)
    return

  this.initSingleMaterialMesh(blockId, blockDef, blockDef.textures)
}
```

網格數從 7300 降到 880。%( •̀ ω •́ )✧%

## 第十二步：順手把亮度烘進去

最後補一個之後會一直用到的機制。

Babylon 的 thin instance 除了矩陣，還支援每個實例一個顏色，著色器會拿它去乘上貼圖顏色。

```ts
mesh.thinInstanceSetBuffer('color', shadeBuffer, 4, true)
```

方塊的立體感有一半來自環境遮蔽，也就是角落比較暗那件事。這種明暗算一次就定案，而 Worker 反正已經在掃鄰居，順手算出來直接烘進緩衝區，執行期沒有任何額外成本。

上面那個區塊範例的顏色就是走這條路。燈火照亮的範圍也烘在同一份顏色裡，這件事講到晝夜循環時還會再出現一次。

## 世界搭好了

整理一下這一章做完的事。

1. 引擎、場景與算繪迴圈
2. 第一人稱鏡頭
3. 一冷一暖兩盞光，加上一片收住遠方的霧
4. 一顆用最近鄰取樣的像素方塊
5. 面剔除，只留露得出來的那些面
6. 世界切成 25 個區塊丟給打工仔算
7. 矩陣接成一條，一種方塊一個網格

現在畫面上是一整片吃得到光、遠處收在霧裡的方塊地景，幾十萬顆方塊只花掉幾百個繪製呼叫。

地基打好了，接下來每一章就往上疊一個特效。%( ´ ▽ ` )ﾉ%

## 總結 🐟

以上程式碼可以[在此取得](https://github.com/Codfisher/cod-aquarium/tree/main/content/aquarium/minespace)

- 引擎固定 WebGL2，canvas 的多重取樣關掉，抗鋸齒交給後製管線
- 半球光的冷暖色溫差讓畫面活了起來，平行光的高光給滿讓材質自己決定
- 一顆一顆畫，繪製呼叫會先壓死你，thin instance 一次畫完幾萬顆
- 靜態緩衝區旗標是最便宜的四倍效能，`doNotSyncBoundingInfo` 與 `alwaysSelectAsActiveMesh` 必須成對出現
- 面剔除只留鄰居是空氣的那些面，範例裡的地形砍完只剩不到四分之一
- 切區塊是為了讓打工仔分頭算，算完就該接成一條
