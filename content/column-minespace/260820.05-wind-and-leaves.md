# Minespace - EP05：風、葉與頂點著色器

大家好，我是鱈魚。

上一章講了材質外掛的機制，這一章來看第一個實際應用，讓整片草原隨風擺動。%੭ ˙ᗜ˙ )੭%

## 這件事只能在著色器裡做

全世界有上萬株草，全部是 thin instance 共用同一份頂點資料。

CPU 這邊連「單獨移動其中一株」的餘地都沒有。%( ˘•ω•˘ )%

所以擺動只能寫在頂點著色器裡，每一株靠自己的世界座標算出屬於自己的相位。

先看成品，三個開關可以單獨關掉每一層風，等一下會逐層說明。

<demo-wind />

只留陣風的時候整片草是同時動的，那正是下面要解決的問題。%( ˘•ω•˘ )%

```ts
class WindSwayPlugin extends MaterialPluginBase {
  getCustomCode(shaderType: string): Record<string, string> | null {
    if (shaderType !== 'vertex')
      return null

    return {
      CUSTOM_VERTEX_DEFINITIONS: VERTEX_DEFINITIONS,
      CUSTOM_VERTEX_UPDATE_POSITION: VERTEX_UPDATE_POSITION,
    }
  }

```

## 這一株長在哪裡

第一個問題，頂點著色器怎麼知道自己是第幾株草？

thin instance 的矩陣是純平移，第四行就是它的世界座標。

```glsl
#ifdef INSTANCES
  vec3 plantOrigin = world3.xyz;
#else
  vec3 plantOrigin = vec3(0.0);
#endif
```

`CUSTOM_VERTEX_UPDATE_POSITION` 插在 `instancesVertex` 之前，`finalWorld` 還沒算出來，但 `world3` 這個屬性已經在了。%( •̀ ω •́ )✧%

## 三層風

風由三層疊起來，各管一件事。

### 第一層：陣風

用柏林噪聲決定「這一帶此刻風多大」。

```glsl
vec2 windHash(vec2 point) {
  point = vec2(dot(point, vec2(127.1, 311.7)), dot(point, vec2(269.5, 183.3)));
  return -1.0 + 2.0 * fract(sin(point) * 43758.5453123);
}

float windNoise(vec2 point) {
  vec2 cell = floor(point);
  vec2 offset = fract(point);
  /** 平滑係數，讓格線兩側的斜率接得上 */
  vec2 weight = offset * offset * (3.0 - 2.0 * offset);

  return mix(
    mix(
      dot(windHash(cell), offset),
      dot(windHash(cell + vec2(1.0, 0.0)), offset - vec2(1.0, 0.0)),
      weight.x
    ),
    mix(
      dot(windHash(cell + vec2(0.0, 1.0)), offset - vec2(0.0, 1.0)),
      dot(windHash(cell + vec2(1.0, 1.0)), offset - vec2(1.0, 1.0)),
      weight.x
    ),
    weight.y
  );
}
```

這是梯度噪聲，不是值噪聲。格點上存的是方向而非高度，內插出來的場沒有格子的痕跡，這是「像風」的關鍵。

取樣點隨時間往風的方向退，噪聲場因此像一陣風掃過草原。

```glsl
vec2 samplePoint = plantOrigin.xz * 0.090
  - windDirection * windTime * 0.090 * 2.600;
float gust = windNoise(samplePoint) * 0.68
  + windNoise(samplePoint * 2.3 + 17.0) * 0.32;

float gustStrength = clamp(0.7 + gust * 0.45, 0.35, 1.15);
```

壓成一個恆正的包絡，風會忽強忽弱，但不會反過來吹。下限留一點，草地永遠有一絲微風，不會出現整片完全靜止的死角。

### 陣風不夠

問題來了。%(´థ‸థ)%

噪聲場的疏密給 0.09，也就是大約十一格一個起伏，差不多是一座箱庭的三分之一。

但這代表相鄰兩株草在噪聲場上只差 0.09，取到的值幾乎一模一樣。

於是整片草看起來是**同時**動的，像一塊布。

它管得了範圍，管不了順序。

### 第二層：行進波

真正看得出順序的是一道沿著風向前進的波。

```glsl
float rippleTravel = dot(plantOrigin.xz, windDirection) - windTime * 2.600;
float ripple = sin(windRippleFrequency * rippleTravel);
```

相位只看「這一株在風向上站得多前面」，減去時間就成了一道往下游跑的行進波。

```ts
const PLANT_RIPPLE_WAVELENGTH = 6
```

六格一個週期，隔壁那株差六十度。這一株彎到底時下一株才剛開始傾，一排草因此是接力倒下去的。%ヽ(●`∀´●)ﾉ%

它與陣風用同一個速度前進，所以看到的是「一陣風掃過來，草一株接一株倒下去」，而不是波與陣風各走各的。

### 第三層：顫動

只有前兩層的話，同一小塊裡的草還是太整齊。

疊一層又快又小的擾動，每一株的相位由它自己的座標決定，葉尖那種細碎的顫動就出來了。

```glsl
float flutterPhase = plantOrigin.x * 1.7 + plantOrigin.z * 2.3;
float flutter = sin(windFlutterPhase + flutterPhase);
```

幅度寫成佔擺幅的比例，這樣調整主擺幅時顫動會跟著等比縮放。

```ts
const FLUTTER_RATIO = 0.25
```

不然會出現「樹葉幾乎不動、卻抖得跟草一樣厲害」這種奇景。%(・∀・(・∀・(・∀・*)%

## 整場風的強弱

上面三層都是「同一時刻各處的差別」，還缺一個「這一陣風有多大」。

這件事與位置無關，所以在 CPU 算一次、所有材質共用。

```ts
const SQUALL_PERIOD_LIST = [79, 32, 153]
const SQUALL_RANGE: [number, number] = [0.3, 1.75]

function measureSquall(elapsedSecond: number): number {
  let total = 0
  for (const [index, period] of SQUALL_PERIOD_LIST.entries()) {
    total += Math.sin(elapsedSecond * (Math.PI * 2 / period) + index * 1.7)
  }

  const normalized = total / SQUALL_PERIOD_LIST.length
  const [min, max] = SQUALL_RANGE

  return min + (max - min) * (normalized * 0.5 + 0.5)
}
```

三條週期互不整除的正弦疊起來，79 秒、32 秒、153 秒。

大部分時候它們互相抵消，風就維持在中等；偶爾三條同時走到高點，那一下就是一陣把整片草壓下去的大風。

因為週期永遠對不回同一個相位，那樣的時刻不會照著節拍出現。%(*´∀`)~♥%

## 相位要累積，不能用時間乘速度

顫動的快慢跟著風走，風大時葉尖抖得急。

直覺會寫成 `sin(t * speed)`，但這樣會出事。

那個乘積的變化率是「速度 + 時間 × 速度的變化率」。跑了十分鐘之後 `t` 很大，速度稍微一動就會把相位甩出去好幾圈。

畫面上是整片草莫名其妙抽動一下。%(⊙ o ⊙)%

正確做法是每一幀只加上「這一幀該轉多少」。

```ts
const observer = scene.onBeforeRenderObservable.add(() => {
  const deltaSecond = scene.getEngine().getDeltaTime() / 1000
  elapsedSecond += deltaSecond
  squall = measureSquall(elapsedSecond)
  /** 風越大抖得越急，但再緩也還在動 */
  flutterPhase += deltaSecond * FLUTTER_SPEED * (0.55 + squall * 0.5)

  for (const plugin of pluginList) {
    plugin.setWindState(elapsedSecond, squall, flutterPhase)
  }
})
```

## 從根部彎，還是整塊一起動

最後一段是把三層加起來。

```glsl
float height = clamp(positionUpdated.y + 0.5, 0.0, 1.0);
float leverage = mix(1.0, height * height, windHeightLeverage);

float amplitude = windAmplitude * strength * (ripple + flutter * 0.250);
vec2 sway = windDirection * amplitude * leverage;

positionUpdated.x += sway.x;
positionUpdated.z += sway.y;
```

區域座標從 -0.5 到 +0.5，加上 0.5 就是「離地多高」。

再平方一次，根部幾乎釘在地上，只有頂端在動。草是從底下長出來的，不是浮在空中的一片布。

樹葉則要整塊一起動，`windHeightLeverage` 給零。

```ts
export const PLANT_SWAY_AMPLITUDE = 0.14
export const LEAF_SWAY_AMPLITUDE = 0.05
```

樹葉的幅度只有花草的三分之一，理由有兩個。

一是樹冠是一團互相緊貼的方塊，各自彎腰的話塊與塊之間會裂開。整團同進同出才是一棵樹被風推的樣子。

二是樹葉會投影子，而陰影貼圖走的是另一支著色器，影子不會跟著擺。差 0.05 格看不出來，差 0.15 就對不上了。%( ˘•ω•˘ )%

同理，樹葉的波長也要拉長。

```ts
const LEAF_RIPPLE_WAVELENGTH = 24
```

拉到 24 格之後同一棵樹幾乎整團同進同出，波的作用只剩「這棵樹與那棵樹不同步」。

這兩件事都可以在前面那個範例上切。把「從根部彎」關掉，整株草會像一片浮在空中的布橫著滑，那就是樹葉那條路；波長從 6 拉到 24，接力倒下去的順序感也會跟著消失。%( ˘•ω•˘ )%

## 一個很雷的小陷阱

常數要內插進 GLSL 字串時，千萬記得補小數點。

```ts
function toGlslFloat(value: number): string {
  return value.toFixed(3)
}
```

常數若哪天被調成整數，JS 會印出 `3`，而 GLSL 的 `3` 是 `int`，`vec2` 乘 `int` 直接編譯失敗。%(´థ‸థ)%

一律補到小數點後三位，改成什麼值都不會踩到。

## 順便讓葉子透光

風做完了，再來看樹葉的第二個效果。

太陽在樹後面的時候，真實的葉子會透光，邊緣亮成一圈黃綠，整棵樹在逆光裡是發亮的。

原本的樣子剛好相反。背對太陽那一側只吃得到環境光，於是逆光時反而最暗，那是它最不像樹的一刻。%(›´ω`‹ )%

正經做法是算次表面散射，那要知道葉子有多厚、光在裡面跑了多遠。

這裡用的是即時繪圖界的老招數。光穿過薄物之後大致順著原方向繼續走，所以「視線與光線多接近」就約等於「透出來多少」。

```glsl
vec3 minespaceLeafTranslucency(vec3 viewDirection, vec3 surfaceNormal) {
  float backFacing = 1.0 - max(dot(surfaceNormal, -leafTranslucencySun.xyz), 0.0);

  vec3 throughDirection = normalize(
    leafTranslucencySun.xyz - surfaceNormal * leafTranslucencyColor.a
  );
  float forward = pow(
    max(dot(viewDirection, throughDirection), 0.0),
    leafTranslucencySun.w
  );

  return leafTranslucencyColor.rgb * forward * backFacing;
}
```

一次點積加一次次方，換到一天裡最好看的兩段，清晨與黃昏。%(*´∀`)~♥%

<demo-leaf-translucency />

把太陽方位轉到樹的後面再切開關，差別最明顯。

三個細節。

### 正對太陽的那一面不加

`backFacing` 那一項在做這件事。

那一面已經被直射光照亮了，再加一次透光就是同一道光算兩遍。會透光的是背著太陽的那一側，那正是原本最暗的地方。

### 出射方向要被法線扳開一點

```ts
const NORMAL_DISTORTION = 0.35
```

純粹順著光線走的話，亮的只有「視線與光線完全重合」那一條線，而葉子是散射不是玻璃。

把出射方向往法線的反面偏一點，亮區就從一條線化開成一片。

### 集中在多窄的角度裡

```ts
const FORWARD_POWER = 3.5
```

這個指數就是「要多正對著太陽才看得到」。

給得低的話整片樹冠不管從哪個方向看都在發光，那不是透光是自發光；給得太高則只剩太陽正後方那一點，走過去根本遇不上。

3.5 大約是視線與光線夾角三十度以內看得出來。

### 最後乘上 baseColor

```glsl
color.rgb += minespaceLeafTranslucency(viewDirectionW, normalW) * baseColor.rgb;
```

這一行有兩層意思。

一是顏色。透出來的光帶著葉子本身的顏色，綠葉透綠、楓葉透橘，不必為每一種葉子各調一組。

二是遮蔽。方塊的環境遮蔽與燈火都烘在這個顏色裡（見 EP02），樹冠深處那幾片本來就照不到光的葉子，透光也會跟著弱下去。%( •̀ ω •́ )✧%

透光量則是方塊自己的性質。

```ts
export const LEAF_TRANSLUCENCY = 0.8
export const PLANT_TRANSLUCENCY = 1
```

花草比樹葉高。地上的草與花瓣只有一層細胞那麼薄，逆光時幾乎是半透明的，而樹冠那一團是好幾片葉子疊在一起。

## 蜘蛛網不該搖

最後補一個很好笑的細節。

交叉立板的花草預設會跟著風擺，但蜘蛛網也是交叉立板。

它長在洞裡、掛在岩壁之間，那裡沒有風。跟著花草一起搖會讓整個山洞看起來像在戶外。%(・∀・(・∀・(・∀・*)%

```ts
if (blockDef.swaysInWind !== false) {
  this.windSway.attach(material, PLANT_SWAY_AMPLITUDE, true)
}
```

所以方塊自己要能說「我不搖」。
