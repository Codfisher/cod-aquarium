# Minespace - EP05：雲影

大家好，我是鱈魚。

上一章把陰影做完了，鳥居與樹都好好地站在白沙上。抬頭看看，天上還飄著一整片方塊雲。%( •̀ ω •́ )✧%

低頭再看一次，地面從早到晚是同一個亮度。

一大片高明度的白沙，太陽角度一直在變，但「這一塊比較暗」這件事從來沒發生過，整座庭園平得像一張紙。這一章就是要把那塊暗補回來。

## 為什麼不能用上一章那套

直覺會想把雲層加進投影者，讓陰影貼圖順手把它畫進去。這條路走不通，原因在數字上。

投影用的鏡頭只沿著光線退開九十格，而雲在一百零四格高。沙面在六格，太陽仰角約三十八度時，遮住腳下這一點的那朵雲位在光線上游一百五十三格處，遠在投影鏡頭的近截面之外。太陽要爬到六十三度以上雲才進得了範圍，而這個世界的太陽從來沒那麼高。%(´･_･`)%

就算進得了範圍，也只罩得住鏡頭附近八十格見方那一塊。雲影該是鋪滿整片視野、一路延伸到天邊的東西。

路人：「那用光的投影貼圖呢？給太陽掛一張捲動的雲圖。」
鱈魚：「Babylon 的 `projectionTexture` 只有聚光燈有，平行光沒有這個東西。」

所以只剩一條路，在著色器裡自己算。地面上這一點，沿著光線往上走到雲層那一層，看那個位置有沒有雲。

## 第一步：可平鋪的值噪音

先做雲的形狀。

這個世界是循環的，走過邊界時位置會平移一整個世界的寬度。所以雲的圖樣必須剛好是一個世界寬，而且無縫接得起來。跨過邊界的那一瞬間整片天換一副樣子的話，那是全場景唯一不吃霧氣、藏不住的東西。

一般的連續噪音給不了這件事，simplex 那一類函式沒有週期，接縫上兩側的值對不起來。

值噪音就簡單多了。在稀疏的格點上灑亂數，再內插放大到要的解析度，讀格點時把座標繞回去。

```ts
function createTileableNoise(random: () => number, size: number, pointCount: number) {
  const pointList = Array.from({ length: pointCount * pointCount }, () => random())

  const readPoint = (x: number, z: number) => {
    const wrappedX = ((x % pointCount) + pointCount) % pointCount
    const wrappedZ = ((z % pointCount) + pointCount) % pointCount

    return pointList[wrappedZ * pointCount + wrappedX] ?? 0
  }

  const scale = pointCount / size

  return Array.from({ length: size * size }, (_, index) => {
    const x = (index % size) * scale
    const z = Math.floor(index / size) * scale
    const baseX = Math.floor(x)
    const baseZ = Math.floor(z)
    const ratioX = smoothRatio(x - baseX)
    const ratioZ = smoothRatio(z - baseZ)

    const top = readPoint(baseX, baseZ) * (1 - ratioX)
      + readPoint(baseX + 1, baseZ) * ratioX
    const bottom = readPoint(baseX, baseZ + 1) * (1 - ratioX)
      + readPoint(baseX + 1, baseZ + 1) * ratioX

    return top * (1 - ratioZ) + bottom * ratioZ
  })
}
```

繞回去那三行是整個機制的關鍵。最右邊那一格的右鄰居會是最左邊那一格，所以放大出來的結果本身就是無縫的。

內插的比例先過一次曲線。

```ts
function smoothRatio(ratio: number) {
  return ratio * ratio * (3 - 2 * ratio)
}
```

這條曲線兩端的斜率都是零，接起來的格點之間才看不出直線的痕跡。

## 第二步：雲的圖樣

有了噪音，接著把它變成布林值的雲格。

兩層噪音疊起來，低頻那一層決定一朵雲多大，高頻那一層負責咬出邊緣的缺口。

```ts
const fieldList = Array.from({ length: size * size }, () => 0)

for (const octave of octaveList) {
  const noiseList = createTileableNoise(random, size, Math.round(size * octave.density))
  for (let index = 0; index < fieldList.length; index++) {
    fieldList[index] = (fieldList[index] ?? 0) + (noiseList[index] ?? 0) * octave.weight
  }
}
```

接著要決定門檻，超過就是雲。

鱈魚：「隨便挑個 0.6 應該就差不多了吧。」
路人：「權重一改分布就跑掉了，你要重新試一輪嗎？」
鱈魚：「⋯⋯好啦，改成排序。」

門檻取分位數，由大到小排完取第 N 名。

```ts
const sortedList = fieldList.slice().sort((a, b) => b - a)
const threshold = sortedList[Math.floor(sortedList.length * coverage)] ?? Infinity

return fieldList.map((value) => value > threshold)
```

這樣說覆蓋幾成就真的是幾成，權重怎麼調都不必回頭改門檻。%( •̀ ω •́ )✧%

圖樣的格數也不能隨便給。

```ts
const patternCount = Math.round(WORLD_SIZE / options.cellSize)
```

格數乘上格寬必須剛好等於世界寬度，理由就是上一節講的循環世界。直接由世界寬度除出來，這件事就不會再對不上。

## 第三步：方塊雲的網格

每一朵雲都是實際的方塊，所以看得到厚度與側面。整片雲做成一個網格，成本只有一次 draw call。

建網格的迴圈很單純，走過每一格，是雲就把六個面加上去。

```ts
for (let x = -halfCount; x < halfCount; x++) {
  for (let z = -halfCount; z < halfCount; z++) {
    if (!isFilled(x, z))
      continue

    const minX = x * options.cellSize
    const maxX = minX + options.cellSize
    const minZ = z * options.cellSize
    const maxZ = minZ + options.cellSize

    addQuad([
      [minX, halfThickness, minZ],
      [minX, halfThickness, maxZ],
      [maxX, halfThickness, maxZ],
      [maxX, halfThickness, minZ],
    ], [0, 1, 0])

    // ⋯ 其餘五個面
  }
}
```

上下兩面一定要畫，側面則要看鄰居。

```ts
if (!isFilled(x - 1, z)) {
  addQuad([
    [minX, halfThickness, minZ],
    [minX, -halfThickness, minZ],
    [minX, -halfThickness, maxZ],
    [minX, halfThickness, maxZ],
  ], [-1, 0, 0])
}
```

這就是方塊世界的面剔除，鄰居是空的才畫那一面。

少了這一步，相鄰兩格之間那兩片牆照樣畫出來。雲是半透明的，隔著雲面看過去就是一格一格的框線交錯在一起，看起來像用積木拼的。%(›´ω`‹ )%

飄移的做法也很省。

```ts
const driftPeriod = patternCount * options.cellSize
cloudMesh.position.x = (elapsed * options.driftSpeed) % driftPeriod
```

圖樣每 `patternCount` 格重複一次，位移滿一個週期就回到完全相同的排列，直接取餘數歸零，看不出接縫。

## 第四步：材質外掛

現在要動著色器了。

Babylon 的 `StandardMaterial` 是一支寫死的著色器，想在裡面加東西又不想整份重寫的話，走的就是材質外掛（`MaterialPluginBase`）。這一章之後好幾個效果都靠它，所以這一節講完整。

### 一份外掛長什麼樣

```ts
class CloudShadowPlugin extends MaterialPluginBase {
  constructor(material: Material) {
    super(material, 'MinespaceCloudShadow', 210, {}, true, true)
  }

  getClassName(): string {
    return 'CloudShadowPlugin'
  }
}
```

建構子那六個參數依序是掛在哪份材質、外掛名稱、優先權、附加的 defines、是否已啟用、是否一律啟用。

優先權決定多個外掛之間的注入順序。最後那個「一律啟用」給 true 的話，這份外掛沒有開關屬性，掛上去就永遠生效。

### 宣告自己要用的資料

著色器需要的參數與貼圖要先報備。

```ts
getSamplers(samplers: string[]): void {
  samplers.push('cloudShadowSampler')
}

getUniforms() {
  return {
    ubo: [
      { name: 'cloudShadowParam', size: 4, type: 'vec4' },
      { name: 'cloudShadowProjection', size: 4, type: 'vec4' },
    ],
    fragment: `
      uniform vec4 cloudShadowParam;
      uniform vec4 cloudShadowProjection;
    `,
  }
}
```

`ubo` 那個陣列會被塞進材質的統一緩衝區。下面那段 `fragment` 字串只有在不支援統一緩衝區時才派得上用場，支援的時候那串字會靜靜地被丟掉。兩邊都寫，退路才在。

參數盡量湊成 `vec4`。統一緩衝區是按十六位元組對齊的，四個 float 湊一組不浪費空間，也少一次綁定。

### 每一幀把數字寫進去

```ts
bindForSubMesh(uniformBuffer: UniformBuffer): void {
  const state = cloudShadowState

  uniformBuffer.updateFloat4(
    'cloudShadowParam',
    state.strength,
    state.inverseSpan,
    COVER_START,
    COVER_FULL,
  )
  uniformBuffer.updateFloat4(
    'cloudShadowProjection',
    state.slopeX,
    state.slopeZ,
    state.height,
    state.driftX,
  )

  if (patternTexture) {
    uniformBuffer.setTexture('cloudShadowSampler', patternTexture)
  }
}
```

`cloudShadowState` 是所有材質共讀的一份物件。天氣系統每一幀寫一次，下一幀各材質綁定時自己來讀。

這個寫法很重要。這個世界有兩百多份材質，各存一套的話，改一次天氣就得走過每一份。%( ˘•ω•˘ )%

### 把程式碼注進去

`getCustomCode` 回傳的是「注入點 → 程式碼」的對照表，分成兩種。

**第一種是具名的注入點。** Babylon 在著色器裡預留了幾個位置，直接填就好。

```ts
'CUSTOM_FRAGMENT_DEFINITIONS': `
  uniform sampler2D cloudShadowSampler;

  float minespaceCloudCover() {
    // ⋯
  }
`,

'CUSTOM_FRAGMENT_BEFORE_LIGHTS': `
  float minespaceCloudCoverValue = minespaceCloudCover();
`,
```

常用的有 `CUSTOM_FRAGMENT_DEFINITIONS`（放函式與宣告）、`CUSTOM_FRAGMENT_BEFORE_LIGHTS`（光照之前）、`CUSTOM_FRAGMENT_BEFORE_FOG`（霧之前）、`CUSTOM_FRAGMENT_MAIN_END`（整支結束前）。

**第二種是正規式取代。** 鍵值開頭加一個 `!`，剩下的部分當成正規式去比對原本的著色器原始碼，比到的那一段換成你給的字串。

```ts
'!info=computeLighting\\(viewDirectionW,normalW,([^,]+),(diffuse(\\d+)\\.rgb),([^,]+),(diffuse\\3\\.a),glossiness\\);': `
  {
    float cloudShade = 1.0;
    #ifdef DIRLIGHT$3
      cloudShade = 1.0 - cloudShadowParam.x * minespaceCloudCoverValue;
    #endif

    info = computeLighting(viewDirectionW, normalW, $1, $2 * cloudShade, $4 * cloudShade, $5, glossiness);
  }
`,
```

這一招很強，Babylon 內建著色器的任何一行都改得動。三件事要記住。

**一、每個 `$n` 只准出現一次。** Babylon 代換捕獲群組用的是 `newCode.replace('$' + i, match[i])`，字串比對，一個編號只換掉最前面那一個。後面的原封不動留在著色器裡變成 `$` 字元，整支著色器編不過。寧可多切幾個群組，也不要重複用同一個編號。

**二、注入的 GLSL 裡不要寫註解。** Babylon 的前處理器用 `/(#ifdef)|(#else)|(#elif)|(#endif)|(#ifndef)|(#if)/` 掃每一行，沒有錨定行首，也不先把註解拿掉。註解裡提到條件編譯指令的名字，就會被當成真的指令，條件層數從此對不起來，游標一路跑到檔尾，後面整段著色器憑空消失。%(´,,•ω•,,)%

**三、找不到就靜靜地不做事。** 哪天 Babylon 改了那一行的寫法，正規式比不到，畫面會退回沒有雲影的樣子。不會壞掉，但也不會有人跳出來告訴你。

### 什麼時候掛上去

```ts
export function registerCloudShadow(): void {
  if (isRegistered)
    return

  isRegistered = true
  RegisterMaterialPlugin('MinespaceCloudShadow', (material) => {
    if (!(material instanceof StandardMaterial))
      return null

    return new CloudShadowPlugin(material)
  })
}
```

`RegisterMaterialPlugin` 註冊的是一個工廠函式，之後**每一份新建的材質**都會走一次這個函式。

所以它必須在任何材質建立之前呼叫。註冊之前就做好的材質不會回頭補掛，畫面上會出現一部分方塊有雲影、一部分沒有的怪狀況。

單獨掛在某一份材質上也可以，直接 `new` 就行。文章裡的範例走的正是這條路，因為那一頁只想影響自己那兩份材質。

```ts
const material = new StandardMaterial('ground', scene)
const cloudShadowPlugin = new CloudShadowPlugin(material)
```

## 第五步：沿著光線往上查圖樣

機制都有了，來寫真正在算雲影的那幾行。

```glsl
float minespaceCloudCover() {
  if (cloudShadowParam.x <= 0.0) {
    return 0.0;
  }

  vec2 cloudPoint = vPositionW.xz
    - (cloudShadowProjection.z - vPositionW.y) * cloudShadowProjection.xy
    - vec2(cloudShadowProjection.w, 0.0);

  float cover = texture2D(cloudShadowSampler, cloudPoint * cloudShadowParam.y).r;

  return smoothstep(cloudShadowParam.z, cloudShadowParam.w, cover);
}
```

逐行來說。

`cloudShadowProjection.z` 是雲層高度，減掉這一點的高度就是要往上走多遠。乘上 `.xy` 那組斜率，得到水平方向要退多少。斜率是太陽方向的水平分量除以仰角，仰角越低退得越遠。

再扣掉 `.w`，那是雲此刻往 +X 飄了多遠。扣掉之後才回得到原始圖樣裡的位置。

取樣器用重複定址，座標推到圖樣外面會自己繞回來，這與循環世界是同一件事。

最後那個 `smoothstep` 把覆蓋率換成遮蔽比例。兩個門檻決定雲影的邊緣有多硬，拉近是輪廓分明的積雲影，拉遠是糊成一片的高層雲。

### 圖樣要先糊過

著色器讀的那張圖不是原本的布林值。直接雙線性取樣一張全有全無的圖會拉出菱形的塊，得先糊一糊。

```ts
const shadowCount = patternCount * SHADOW_TEXEL_PER_CELL
const coverList = blurPattern(
  upsamplePattern(cellList, patternCount, SHADOW_TEXEL_PER_CELL),
  shadowCount,
)
```

先把每一格雲切成四個紋素，再糊兩輪。

切細這一步是有原因的。一格雲有十四格寬，直接在原本的解析度上糊兩輪等於糊掉二十八格，而一朵雲的影子總共才五十來格寬，半影吃掉了將近一半。切成四份之後每個紋素是三點五格，同樣糊兩輪，半影收到四格。貼圖從 1.6 KB 長到 25 KB，換得回來。

邊緣清楚之後看得出雲的方格輪廓，那是對的。天上那朵雲本來就是方塊堆的，影子理當跟著有稜有角。%ヽ(●`∀´●)ﾉ%

糊完還要把最濃的一格拉回滿格。

```ts
const peak = Math.max(...valueList)
if (peak <= 0) {
  return valueList
}

return valueList.map((value) => value / peak)
```

三乘三取平均只有在「一朵雲寬到中心那格的鄰居全是雲」時才留得住 1.0，兩輪之後那要五格寬。多數雲不到那麼大，最濃的地方只剩零點七幾。門檻卻是照著 0 到 1 訂的，不正規化的話最深的雲影也永遠踩不到滿格。

拉回去之後，「雲最厚的地方」對上的就是「影子最深的程度」，這兩個數字本來就該是同一件事。

### 圖樣從哪來

雲影拿的就是雲層那份圖樣。

```ts
if (options.castsShadow) {
  setCloudShadowPattern(scene, cellList, patternCount, options.cellSize, options.height)
}
```

在著色器裡另外鋪一張噪聲當然也做得到，那會是另一副雲。地上那塊暗要與頭頂這朵雲是同一朵，何況這個世界是循環的，雲影的週期非得與雲一樣不可。

順帶一提，兩層雲只有一層投影。兩層都投的話，地面會疊出兩種週期的暗塊，糊成看不出形狀的雜訊。

## 第六步：平行光與天光各收多少

最後是兩個數字。

```ts
const SHADE_DEPTH = 0.72
const SKY_SHADE_DEPTH = 0.42
```

平行光收七成二，天光收四成二。

天光那一項一開始很容易寫成零，理由聽起來很篤定，雲擋住的是太陽，關天空什麼事。那句話只對了一半。一朵積雲罩在頭頂時，它擋掉的除了那顆太陽，還有頭頂那一大塊天空，站在雲底下天光確實也少了一截。

而真正逼著這一項長出來的，是色調映射。

這座庭園的地是白沙。正午時平行光加天光加上環境色，線性亮度是 1.75，早就衝過 ACES 的膝點，整片地貼在天花板上。量過的數字擺出來就很清楚（白沙／一般方塊，數字是最深處與無雲處）。

| 平行光 / 天光 | 白沙 | 一般方塊 |
|---|---|---|
| 0.60 / 0.30 | 204..209 | 142..209 |
| 0.72 / 0.42 | 174..209 | 108..209 |
| 0.82 / 0.55 | 130..209 | 75..209 |

第一組在白沙上只差五階，等於看不見。雲影一直都算對了，只是全部被壓在那道天花板底下。第三組又太深，像雲飄過去整個世界暗一下。

所以這兩個數字是照著這座場景的曝光配的。哪天 pipeline 的曝光或日夜的光強調低、畫面離開了膝點，這兩個數字就該一起往回收。%( ˘•ω•˘ )%

高光那一項也要一起乘。少了那一行，一朵雲飄過水鏡池的時候池面照樣閃著一道刺眼的反光，而那道光的來源明明正被遮著。

洞裡那幾盞燈則完全不該跟著暗，所以那一段包在 `#ifdef DIRLIGHT$3` 裡面。整個場景裡只有日月那一盞是平行光，其餘的燈條件編譯整段會被拿掉，`cloudShade` 就是常數 1.0，乘法會被編譯器摺掉，不花錢。

### 太陽太低就收掉

```ts
const SUN_HEIGHT_FADE_START = 0.1
const SUN_HEIGHT_FADE_FULL = 0.32
```

兩個理由。

物理上，太陽貼著地平線時光要橫穿一百多格的空氣才到得了地面，雲影早就散得沒有形狀了。

投影法本身也撐不住。投影點要沿著光線往回推「(雲高 − 腳下高度) ÷ 太陽仰角」，仰角趨近零時那個距離會爆掉，整片地會被一格雲的顏色蓋滿。與其加保護，不如在還看得出形狀時就淡出。

```ts
const sunHeight = -sunDirection.y

if (!isEnabled || sunHeight <= SUN_HEIGHT_FADE_START) {
  cloudShadowState.strength = 0
  return
}

const heightRatio = Math.min(
  1,
  (sunHeight - SUN_HEIGHT_FADE_START) / (SUN_HEIGHT_FADE_FULL - SUN_HEIGHT_FADE_START),
)

cloudShadowState.strength = SHADE_DEPTH * heightRatio * Math.min(1, Math.max(0, clarity))
cloudShadowState.slopeX = sunDirection.x / sunHeight
cloudShadowState.slopeZ = sunDirection.z / sunHeight
```

`clarity` 是「直射陽光還剩幾成」。陰天與洞裡都要收掉，沒有太陽的時候當然也沒有雲影。

## 完整實作

整套的資料流整理一次。

1. `createCloudPattern` 用兩層可平鋪的噪音算出布林值的雲格
2. `createCloudLayer` 拿那份雲格建網格，順手把同一份交給雲影
3. `setCloudShadowPattern` 把雲格切細、糊過、正規化，烘成一張 RawTexture
4. `registerCloudShadow` 在任何材質建立之前掛上外掛
5. 每一幀，天氣系統寫一次 `cloudShadowState`，雲層寫一次 `driftX`
6. 每一份材質綁定時讀那份狀態，著色器沿著光線往上查一次圖樣

整個效果的代價是一次貼圖取樣，換到的是「地上那塊暗確實是頭頂那朵雲的」。%( •̀ ω •́ )✧%

## 總結 🐟

以上程式碼可以[在此取得](https://github.com/Codfisher/cod-aquarium/tree/main/content/aquarium/minespace)

- 循環世界的噪音必須可平鋪，值噪音讀格點時繞回去就有了
- 雲的門檻取分位數，說覆蓋幾成就真的是幾成
- 方塊雲照方塊世界的面剔除做，鄰居是空的才畫那一面
- 材質外掛靠 `getUniforms`、`bindForSubMesh`、`getCustomCode` 三件事運作，註冊要趕在所有材質之前
- 正規式注入時每個 `$n` 只准出現一次，注入的 GLSL 裡不要寫註解
- 雲影要連天光一起收，不然整片地會卡在色調映射的天花板上
