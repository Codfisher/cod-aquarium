# Minespace - EP01：前言與場景骨架

大家好，我是鱈魚。

之前做完 [HexaZen](/aquarium/hexazen/) 之後，白噪音這件事就一直放在心上。%( ˘ω˘ )%

積木混音器很好玩，但聲音終究是「調」出來的，玩家在做的事情比較接近轉旋鈕。

這次想換個方向，把聲音藏進一個可以走進去的世界裡，讓人自己走過去聽。

於是有了 Minespace，一片無盡的白沙禪庭，十七座木頭底座的箱庭散落其間，每一座只收一種聲音的質地。連綿的風、稀疏的滴水、低頻的蛙鳴，走近才聽得到。

路人：「所以這是遊戲嗎？」
鱈魚：「不是，這是一個用來待著的地方。%( ˘ω˘ )%」

## 說明

### 概念

整個世界是方塊構成的，美術走 Minecraft 那種十六格見方的像素風。

玩家用第一人稱漫遊，走到哪裡聽到哪裡的聲音，天色會自己從清晨走到深夜，雨會下、雪會颳、葉子會掉。

沒有目標、沒有分數、沒有計時器，就是走走看看。

### 這個專欄要寫什麼

Minespace 的程式碼有兩萬七千多行，其中絕大部分是視覺。

這個專欄不打算把整個專案從頭講一遍，而是專門挑「畫面上看得到的東西是怎麼做出來的」來寫。

十集大致是這樣安排：

- EP01 場景骨架與後製管線
- EP02 體素渲染與 Thin Instance
- EP03 像素材質工廠
- EP04 材質外掛與著色器注入
- EP05 風、葉與頂點著色器
- EP06 天空、日月與雲
- EP07 陰影
- EP08 光暈與水面倒影
- EP09 天氣與粒子
- EP10 效能與收尾

那我們開始吧。%੭ ˙ᗜ˙ )੭%

## 建立頁面

第一步與 HexaZen 一樣，在部落格裡開一個完全客製化的頁面。

`content\aquarium\minespace\index.md`

```markdown
---
title: Minespace
description: 戴上耳機，走進一片無盡的白沙禪庭。
layout: false
---

<script setup>
import Minespace from './minespace.vue'
```

`layout: false` 讓 VitePress 不套用預設佈局，再用 [whyframe](https://whyframe.dev/) 把場景關進 iframe 裡。

這樣 VitePress 本身的樣式與狀態就干擾不到 3D 場景了。%( •̀ ω •́ )✧%

## 引擎

Babylon.js 支援 WebGPU，HexaZen 當初也走了「WebGPU 優先、WebGL 降級」的策略。

Minespace 反而退回去只用 WebGL2。

```ts
async function createEngine({ canvas }: { canvas: HTMLCanvasElement }) {
  return new Engine(canvas, false, {
    antialias: false,
    alpha: false,
    stencil: false,
    preserveDrawingBuffer: false,
  })
}
```

理由有兩個，一是 WebGPU 在部分裝置上會出現難以重現的異常，二是這個場景吃不到 WebGPU 的效能優勢，那就穩定優先。

比較值得說的是 `antialias: false`。

整個場景是畫進 `DefaultRenderingPipeline` 的離屏貼圖，canvas 那份多重取樣緩衝區只接得到最後那一張全螢幕方塊。

上面沒有任何幾何邊緣可以抗鋸齒，等於白白配置一份記憶體與頻寬。%(›´ω`‹ )%

## 場景的三件事

一個場景最少要有光與霧，Minespace 的基底就三件事。

### 半球光

```ts
const ambientLight = new HemisphericLight(
  AMBIENT_LIGHT_NAME,
  new Vector3(0, 1, 0),
  scene,
)
ambientLight.intensity = 0.82
/** 天空偏冷 */
ambientLight.diffuse = new Color3(0.78, 0.88, 1)
/** 地面反射偏暖 */
ambientLight.groundColor = new Color3(0.82, 0.77, 0.72)
ambientLight.specular = new Color3(0, 0, 0)
```

半球光是「由上往下一個顏色、由下往上另一個顏色」，方塊的頂面、側面、底面因此有三層不同的亮度。

色溫差是重點。陽光是暖的、補光是冷的，兩者拉開才會讓畫面活起來；全部用同一種白光，再多層次也只是灰階濃淡。%( •̀ ω •́ )✧%

<demo-lighting />

先把平行光關掉，只剩半球光時最看得出那三層。屋簷底下那一面完全照不到太陽，它的亮度全部來自「由下往上的地面反射色」。

再切「冷暖色溫差」，亮度層次一格都沒少，畫面卻立刻變成一張黑白照片。%(・∀・(・∀・(・∀・*)%

環境光拉到 0 也很有意思，沒照到太陽的那幾面會直接黑掉，這就是文章說「太低的話背光面會全黑」的樣子。

### 平行光

```ts
const sunLight = new DirectionalLight(SUN_LIGHT_NAME, SUN_DIRECTION, scene)
sunLight.intensity = 1.3
/** 午後的暖陽 */
sunLight.diffuse = new Color3(1, 0.93, 0.78)
/** 高光給滿，讓材質自己決定要反射多少 */
sunLight.specular = new Color3(1, 1, 1)
```

`specular` 給滿這件事後面會一直用到。

在 `StandardMaterial` 裡，漫射與自發光在乘上貼圖之前就被夾在 1.0，高光則是加在那道 clamp 外面。

換句話說，高光是整套渲染裡唯一能真的超過純白的通道。濕掉的木板、水面能不能反出一道刺眼的光，全靠它。

所以光源這端給滿，「這個表面有多亮」交還給各自的材質決定，乾方塊 0.02、淋濕的表面 0.42、水面 0.8。

### 霧

```ts
scene.fogMode = Scene.FOGMODE_LINEAR
scene.fogColor = GARDEN_FOG_COLOR.clone()
scene.fogStart = 100
scene.fogEnd = 220
```

禪庭的霧色幾乎是純白，只帶一點點沙的暖。

```ts
export const GARDEN_FOG_COLOR = new Color3(0.955, 0.95, 0.935)
```

這片霧同時做兩件事，把遠方的空白藏起來，以及讓玩家走過世界邊界時看不出景物被換過。

沒錯，這個世界是循環的。走到邊界時能見度會收到六格，兩側都是同一片什麼都看不見的白，玩家無從察覺自己被送到了對面。%(๑•̀ㅂ•́)و✧%

```ts
export const EDGE_FOG_END = 6
export const EDGE_FOG_START = 0.5
```

兩檔差多少，切一下就知道。

<demo-fog />

平常那一檔還數得出遠處有幾盞燈籠，切到白幕那一檔，第二盞就已經看不見了。%(⊙ o ⊙)%

順帶一提，背景色與霧色是同一個顏色。天空若是另一塊顏色，兩者交界就會露出一條線，而那條線正是霧要藏起來的東西。

## 繪製分層

Babylon 一律先畫完不透明再畫半透明，同一批半透明之間的順序卻不保證固定。

這會出事。天空、雲、陰天罩、雨絲都是半透明，順序一亂就會看到「陰天罩把太陽從中間切開」這種奇景。%(・∀・(・∀・(・∀・*)%

解法是分層。

```ts
const SKY_OVERLAY_RENDERING_GROUP = 1
export const WEATHER_RENDERING_GROUP = 2

/** 各層之間不清除深度，地形擋住天空的關係都還在 */
scene.setRenderingAutoClearDepthStencil(SKY_OVERLAY_RENDERING_GROUP, false)
scene.setRenderingAutoClearDepthStencil(WEATHER_RENDERING_GROUP, false)
```

第 0 層是天空與地景，第 1 層是罩在外面的雲與陰天罩，第 2 層是天氣粒子。

關掉自動清除深度很重要，不然地形擋住雲、雲擋住太陽的關係會整個被清掉。

<demo-rendering-group />

把分層關掉，雨絲立刻剩下打在地形前的那幾條。抬頭看更明顯，整片天沒有半滴雨，地上卻濕成一片。%(・∀・(・∀・(・∀・*)%

陰天罩濃度拉低一點還看得到雨，拉滿就完全被吃掉了，這就是為什麼順序不能交給引擎自己排。

## 後製管線

畫面出去之前還要過一輪後製。

```ts
const pipeline = new DefaultRenderingPipeline('minespace-pipeline', false, scene, [camera])

pipeline.imageProcessingEnabled = true
pipeline.imageProcessing.toneMappingEnabled = true
pipeline.imageProcessing.toneMappingType = ImageProcessingConfiguration.TONEMAPPING_ACES
pipeline.imageProcessing.exposure = 1.06
pipeline.imageProcessing.contrast = 1.05
pipeline.imageProcessing.vignetteEnabled = true
pipeline.imageProcessing.vignetteWeight = 2.2

/** 日夜循環每一幀會改它的色相與濃度 */
pipeline.imageProcessing.colorCurves = new ColorCurves()
pipeline.imageProcessing.colorCurvesEnabled = true
```

ACES 色調映射把過曝的天空拉回來，色調曲線則交給日夜循環每幀改寫。

夜裡整片畫面偏冷、黃昏偏暖，這件事只靠調暗曝光是做不到的。「暗下來」與「換一種顏色」是兩回事，而後者才是黃昏之所以是黃昏的原因。%(*´∀`)~♥%

色調映射的差別自己動手看最快，把開關關掉再拉一下曝光試試。

<demo-tone-mapping />

關掉映射之後，曝光只要一過 1.2，被曬到的頂面就整片黏在純白上，再拉高也只是讓更多地方一起白掉。%(・∀・(・∀・(・∀・*)%

### 打散色階

```ts
pipeline.imageProcessing.ditheringEnabled = true
```

天空是一整片從天頂到天邊的長漸層，出來時重新量化成八位元，就會浮出一圈圈的等高線。

加一點雜訊就看不出來了，代價是肉眼看不見的顆粒取代看得見的圈。

### 泛光關掉

```ts
pipeline.bloomEnabled = false
```

這是量出來的決定，不是喜好。%( ˘•ω•˘ )%

泛光跑在色調映射之前，看到的是線性值。這個場景的光是滿的，被曬到的白沙算出來大約 1.9，門檻原本擺在 0.86 等於整片地、整片霧、連藍天的藍通道都在發光，天地交界因此糊出一圈白暈。

為了治那圈白暈，門檻被拉到 2.2，但那個高度已經超過場景裡最亮的東西，於是泛光什麼都沒做。

而它的成本是無條件的，不管有沒有東西夠亮，那三趟全螢幕的取樣、模糊與合併每一幀都要跑。

一個什麼都沒做卻每幀收費的效果，就該關掉。

這兩件事放同一個範例，因為它們都發生在同一片天上。

<demo-post-detail />

先把「打散色階」關掉，天空立刻浮出一圈圈的等高線，那就是八位元量化的痕跡。%(´థ‸థ)%

再把泛光打開。門檻停在 0.86 的時候整片地與天地交界都在發光，糊出一圈白暈；一路拉到 2.2 以上，畫面回到跟關掉一模一樣，但那三趟全螢幕運算照跑不誤。

### 抗鋸齒不用 FXAA

```ts
pipeline.fxaaEnabled = false
```

這兩者處理的根本不是同一件事。

FXAA 是一道後製，它拿畫好的成品去找亮度落差大的地方，再把那一帶抹開。它分不出「這條邊是幾何邊緣」還是「這是貼圖上本來就該有的兩格不同顏色的像素」。

而這個世界的貼圖是十六格見方的像素畫，滿滿都是後者。開著 FXAA 等於把整片牆的圖案輕輕糊掉一層，那正是這套美術最不該失去的東西。%(›´ω`‹ )%

改用多重取樣，它發生在光柵化的當下，只對真正的幾何邊緣多取幾個樣本。

```ts
const HIGH_QUALITY_SAMPLE_COUNT = 4

function getSampleCount(quality: GraphicsQuality): number {
  return quality === 'low' ? 1 : HIGH_QUALITY_SAMPLE_COUNT
}
```

方塊的稜線平順了，貼圖一個像素都沒被動到。%ヽ(●`∀´●)ﾉ%

兩邊放在一起就很清楚了。

<demo-antialias />

盯著石縫那幾道深色線，還有右邊那兩株草的葉尖。FXAA 那一邊全部被抹掉一層，而那正是像素風的全部身家。%(›´ω`‹ )%

## 專案結構

目前的檔案結構長這樣。

```text
minespace/
├── index.md                     # VitePress 入口
├── minespace.vue                # 應用根元件
├── components/                  # UI 元件
├── composables/
│   ├── use-babylon-scene.ts     # 引擎、場景、天空、後製
│   ├── use-fps-controller.ts    # 第一人稱漫遊
│   ├── use-day-night.ts         # 日夜循環的場景接線
│   └── use-graphics-quality.ts  # 畫質分檔
└── domains/
    ├── block/                   # 方塊定義與材質包
    ├── renderer/                # 體素渲染、材質、風、陰影、光暈
    ├── weather/                 # 天空、日夜、雲、雨雪、霧
    ├── garden/                  # 箱庭生成與水面倒影
    ├── world/                   # 世界資料與 Worker
    ├── soundscape/              # 空間音景
    └── scene/main-scene.vue     # 3D 場景元件
```

`renderer` 與 `weather` 這兩包就是這個專欄要講的主角。

## 總結 🐟

以上程式碼可以[在此取得](https://github.com/Codfisher/cod-aquarium/tree/main/content/aquarium/minespace)

- 用 whyframe 把 3D 場景關進 iframe，與 VitePress 完全隔離
- 引擎固定 WebGL2 並關掉 canvas 的多重取樣，抗鋸齒交給後製管線
- 半球光的冷暖色溫差是畫面活起來的關鍵，平行光的高光給滿讓材質自己決定
- 用 renderingGroupId 分層，固定天空、雲與天氣粒子的先後順序
- 泛光關掉、FXAA 換成多重取樣，像素風的貼圖一格都不能被糊掉
