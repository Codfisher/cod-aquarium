## 先問一個問題

```ts

```

型別看完，你只能確定一件事，成功的話會拿到 `User`。

其他通通不知道。

- 它會不會失敗？會，但型別沒說
- 失敗有幾種？查無此人？網路斷線？權限不夠？型別還是沒說
- 它需要什麼才跑得起來？資料庫？API 金鑰？型別依然沒說

只好翻進去看，結果它又呼叫了五個函數，於是再一層一層翻下去。%( ´•̥̥̥ ω •̥̥̥` )%

<br/>

今天要聊的 Effect，就是把這三個答案通通寫進型別。

## Effect 到底是什麼

大家常把 Effect 歸類成「Promise 的升級版」或「管理服務的工具」，它的定位其實更底層。

它是一套**描述程式的型別**，長這樣。

```ts
Effect<A, E, R>
```

三個欄位剛好對應剛才那三個問題。

| 欄位 | 意思 | 對應的問題 |
|---|---|---|
| `A` | 成功會拿到什麼 | 回傳值是什麼 |
| `E` | 可能會怎麼失敗 | 會噴哪些錯 |
| `R` | 需要什麼才能跑 | 依賴哪些服務 |

`Promise<User>` 只有第一欄。

<br/>

路人：「另外兩件事寫在 JSDoc 裡不就好了？%(・∀・)%」

鱈魚：「可以啊，然後呢？%(´_ゝ`)%」

<br/>

```ts
/**
 * @throws {UserNotFound} 查無此人
 * @throws {NetworkError} 連線失敗
 */
function getUser(id: string): Promise<User>
```

寫得很認真，問題是**沒有人會檢查它對不對**。

- 少寫一種錯誤，編譯器不會有意見
- 改了實作忘記改註解，註解就開始說謊
- 最麻煩的是它**不會自己長大**，`getUser` 裡面呼叫的函數哪天多噴一種錯誤，這份清單不會跟著更新

註解是寫給人看的備忘錄，型別是編譯器會拿去驗算的東西，差別就在這裡。%( ˘•ω•˘ )%

<br/>

`Effect<User, UserNotFound, Database>` 三欄都在，後面兩欄由編譯器算出來，不用手寫，也不會過期。%( •̀ ω •́ )✧%

### Effect 寫好了也不會跑

理解 Effect 的另一個關鍵。

Promise 一建立就開始跑。

```ts
const promise = fetch('/api/user') // 這行跑完，請求已經送出去了
```

Effect 不會。

```ts
const program = Effect.promise(() => fetch('/api/user')) // 什麼事都沒發生
```

`program` 只是一段「等一下要去打這支 API」的描述，躺在那裡不動，交給執行器才會動起來。

```ts
Effect.runPromise(program) // 這時候才真的送出去
```

<br/>

路人：「多此一舉吧？直接跑不是比較快？%(・∀・)%」

鱈魚：「因為還沒跑的東西才有辦法加工。%( •̀ ω •́ )%」

<br/>

已經在跑的 Promise，你能做的事很有限，頂多 `.then` 接一下。

還沒跑的描述就不一樣了，丟去執行之前，你可以先說「失敗重試三次」、「超過五秒放棄」、「跟另外兩個一起併發」。

```ts
program.pipe(
  Effect.retry({ times: 3 }),
  Effect.timeout('5 seconds'),
)
```

到這裡都還是描述，一行都還沒執行。%(ゝ∀・)b%

### Effect 的守備範圍

介紹 Effect 的文章常常只挑其中一欄講，容易讓人以為它就只做那件事，其實它的守備範圍涵蓋一整包平常散落各處的東西。

| 你原本用什麼 | Effect 裡對應的 |
|---|---|
| `Promise`、`async/await` | `Effect`、`Effect.gen` |
| `try/catch` | `E` 欄位、`catchTag` |
| 一層一層傳參數，或自己寫的服務容器 | `R` 欄位、`Layer` |
| `Promise.all`、`AbortController` | Fiber、`Effect.all`、中斷機制 |
| 自己寫的 retry 迴圈 | `Effect.retry`、`Schedule` |
| `try/finally` 關資源 | `Scope`、`Effect.acquireRelease` |
| `vi.useFakeTimers` | `TestClock` |

一篇文章塞不下這麼多，這次挑最常遇到的兩欄下手，`E` 跟 `R`。%(´,,•ω•,,)%

## 從最小的 Effect 開始長

與其一次看完整範例，不如從最小的形狀開始，一次加一樣東西。

```ts
import { Effect } from 'effect'

const program = Effect.succeed(42)
// Effect<number, never, never>
```

成功會給 42、不會失敗、不需要任何東西，兩個 `never` 就是這個意思。

<br/>

接著讓它可能失敗。錯誤得先定義成帶標籤的類別，後面才有辦法靠標籤分辨。

```ts
import { Data, Effect } from 'effect'

class UserNotFound extends Data.TaggedError('UserNotFound')<{
  readonly id: string;
}> {}

const program = Effect.fail(new UserNotFound({ id: 'u1' }))
// Effect<never, UserNotFound, never>
```

`E` 那欄出現 `UserNotFound` 了。

<br/>

最後讓它需要一個服務，這裡用 `Effect.Service` 定義。

```ts
interface User {
  id: string;
  name: string;
}

class Database extends Effect.Service<Database>()('Database', {
  effect: Effect.sync(() => ({
    findUser: (id: string): Effect.Effect<User> => Effect.succeed({ id, name: '鱈魚' }),
    save: (user: User): Effect.Effect<void> => Effect.void,
  })),
}) {}

const program = Effect.gen(function* () {
  const database = yield* Database
  return yield* database.findUser('u1')
})
// Effect<User, never, Database>
```

`R` 那欄從 `never` 變成 `Database` 了。

沒人手動宣告這件事，編譯器看到 `yield* Database` 就自己算出來。%( •̀ ω •́ )✧%

<br/>

三個欄位到齊，接下來把那個奇怪的星號講清楚。

## 等等，`yield*` 是什麼鬼

路人：「我從剛剛就想問了，那個星號到底是什麼？%(´・ω・`)%」

鱈魚：「Effect 看起來最像外星語的地方，先講結論，它就是 `await`。%(ゝ∀・)b%」

<br/>

先澄清一件事，`yield*` 是 JavaScript 原生語法，2015 年就進標準，跟 Effect 沒關係，正式名稱叫**委派**（delegation），只能用在 generator function 裡面。

```ts
function* getAnswer() {
  return 42
}

function* main() {
  const answer = yield* getAnswer()
  console.log(answer) // 42
}
```

`yield*` 把控制權交給另一個 generator，等它跑完，再**把回傳值接回來**，Effect 借的就是這個行為。

### 心智模型：把它念成 await

async 版本跟 Effect 版本擺在一起，對應關係很齊全，一家人整整齊齊。

| async/await | Effect |
|---|---|
| `async function` | `Effect.gen(function* () {})` |
| `await promise` | `yield* effect` |
| `Promise<User>` | `Effect<User, E, R>` |

同一段邏輯，兩種寫法。

```ts
// async 版本
async function getUser(id: string) {
  const user = await database.findUser(id)
  return user
}
```

```ts
// Effect 版本
function getUser(id: string) {
  return Effect.gen(function* () {
    const database = yield* Database
    const user = yield* database.findUser(id)
    return user
  })
}
```

`async` 換成 `Effect.gen(function* ...)`、`await` 換成 `yield*`，剩下只差 `database` 從 import 進來變成跟環境拿。

讀 Effect 程式碼時，看到 `yield*` 就在心裡念成 `await`，八成不會出錯。%(´,,•ω•,,)%

### 那為什麼不乾脆用 await

路人：「都一樣的話，幹嘛不用 `await` 就好？%(・∀・)%」

鱈魚：「因為 `await` 綁死了，它只認 Promise。%( ˘•ω•˘ )%」

<br/>

`await` 寫死在語言規格裡，它接受什麼、錯誤怎麼處理，都是 JavaScript 說了算，函式庫插不上手。

`yield*` 剛好相反，交出去之後要做什麼，接手的人自己決定。Effect 接手時就順便做了兩件 `await` 做不到的事。

- **把錯誤記到型別上**。`await` 的錯誤只會 `throw` 出去，型別是 `unknown`；`yield*` 會把錯誤累積到 `E` 那欄
- **把依賴記到型別上**。也就是那個 `R`，`await` 完全沒有對應概念

換句話說，每 `yield*` 一次，編譯器就默默幫你更新一次 `E` 跟 `R` 的清單。%( •̀ ω •́ )✧%

### 為什麼 `yield* Database` 能拿到服務

再回頭看這兩行，長得很像，做的事卻好像不同。

```ts
const database = yield* Database // 拿到服務
const user = yield* database.findUser(id) // 執行動作
```

路人：「一個是 class，一個是函數呼叫，為什麼都能 `yield*`？%(´・ω・`)%」

鱈魚：「因為 `Database` 本身就是 Effect。%(ﾉ>ω<)ﾉ%」

<br/>

`Effect.Service` 生出來的 class 除了當型別標籤，同時也是個「跟環境要一份 `Database`」的 Effect，型別長這樣。

```ts
Effect<Database, never, Database>
```

成功會給你一份服務、不會失敗、需要環境裡有這個服務。

所以那兩行其實是同一件事，只是一個負責要東西，另一個負責做事情。%(´,,•ω•,,)%

### 忘記寫星號會怎樣

新手最常踩的坑，而且症狀比忘記 `await` 更詭異。

```ts
database.save(user) // 忘了 yield*
```

忘記 `await`，那個 Promise 至少還是會跑，只是沒人等它。

忘記 `yield*`，那行**根本不會執行**。%(°ㅂ°)%

Effect 是惰性的描述，沒交給執行器之前，它就只是躺在那裡的物件，跟你寫了一行 `{ type: 'save' }` 沒什麼兩樣。

<br/>

路人：「這不是很可怕嗎？資料就這樣人間蒸發了？%(;´༎ຶД༎ຶ`)%」

鱈魚：「所以這是 Effect 少數得靠習慣防守的地方，寫久了看到沒有 `yield*` 開頭的那行會很刺眼。%( ˘•ω•˘ )%」

### 流程控制照常寫

Effect 另一種寫法是用 `pipe` 把函數串起來，而 `Effect.gen` 最大的好處是**流程控制照常寫**。

迴圈、`if`、`try` 這些原生語法通通能用。

```ts
Effect.gen(function* () {
  const failedList: string[] = []

  for (const id of idList) {
    const result = yield* database.findUser(id).pipe(Effect.either)

    if (result._tag === 'Left') {
      failedList.push(id)
    }
  }

  return failedList
})
```

同樣的邏輯用 `pipe` 串起來會非常痛苦，難怪官方文件現在幾乎都拿 `Effect.gen` 當範例。%( •̀ ω •́ )✧%

### `yield*` 的三個限制

不過 `yield*` 有幾條硬規則，踩到會很困惑，先講清楚比較好。

**一、只能寫在 generator 函數的本體裡**

這條最容易中招。上面那段能不能改成 `forEach`？

```ts
Effect.gen(function* () {
  idList.forEach((id) => {
    const result = yield* database.findUser(id) // [!code error]
  })
})
```

**不行，這樣直接編譯失敗。**%(°ㅂ°)%

原因是 `forEach` 的 callback 是**另一個函數**，而 `yield*` 只能出現在 `function*` 自己的函數體內。跨進 callback 就沒有 generator 可以交棒了。

<br/>

`await` 也有一樣的毛病，只是 `await` 至少可以把 callback 改成 `async`，`yield*` 連這條路都沒有。

所以在 `Effect.gen` 裡面，`for...of` 是你的好朋友，`forEach`、`map`、`filter` 的 callback 裡通通不能 `yield*`。

<br/>

真的想用宣告式寫法，Effect 有對應的替代品。

```ts
Effect.gen(function* () {
  // 依序跑，收集結果
  const userList = yield* Effect.forEach(idList, (id) => database.findUser(id))

  // 併發跑，最多同時五個
  const fastList = yield* Effect.forEach(idList, (id) => database.findUser(id), {
    concurrency: 5,
  })

  return { userList, fastList }
})
```

`Effect.forEach` 的 callback 回傳 **Effect 本身**，callback 裡不需要 `yield*`，由外層那個 `yield*` 統一收。%(ゝ∀・)b%

**二、只能 `yield*` Effect 或有實作 Yieldable 的東西**

Promise 跟一般的值都不行。

```ts
Effect.gen(function* () {
  const bad = yield* fetch('/api') // [!code --] 這是 Promise，不是 Effect
  const good = yield* Effect.promise(() => fetch('/api')) // [!code ++] 先包成 Effect
})
```

Promise 得先用 `Effect.promise` 或 `Effect.tryPromise` 轉換過。

**三、`Effect.gen` 裡面不能用 `async`**

```ts
Effect.gen(async function* () { }) // [!code error]
```

`Effect.gen` 收的是同步的 generator，非同步的事情交給 `yield*` 處理就好，不需要也不能加 `async`。

<br/>

路人：「限制還真不少。%(´・ω・`)%」

鱈魚：「習慣就好，而且第一條有官方 lint 規則會提醒你。%( ˘•ω•˘ )%」

## `E` 那一欄，錯誤不再是 unknown

語法講完，回頭看那三個欄位到底解決了什麼。

先看 `E`。原生 `try/catch` 抓到的 `error` 型別是 `unknown`（沒開 strict 的話是 `any`，更慘），想知道是哪一種，只能用 `instanceof` 慢慢猜。

```ts
try {
  await database.findUser(id)
}
catch (error) {
  if (error instanceof UserNotFoundError) {
    return null
  }
  else {
    throw error // 忘記寫這行，其他錯誤就被吃掉了
  }
}
```

漏掉最後那行 `throw`，網路逾時、權限不足這些錯誤就這樣消失了，編譯器不會有意見，因為 `catch` 區塊裡放什麼都合法。%( ´•̥̥̥ ω •̥̥̥` )%

<br/>

Effect 版本用 `catchTag` 指定要處理哪一種，沒指定到的照樣往外傳。

```ts
database.findUser(id).pipe(
  Effect.catchTag('UserNotFound', () => Effect.succeed(null)),
)
```

處理掉的錯誤會從 `E` 那欄消失，剩下沒處理的還留著。

```ts
// 處理前 Effect<User, UserNotFound | NetworkError, Database>
// 處理後 Effect<User | null, NetworkError, Database>
```

想知道呼叫這個函數可能收到什麼錯誤，看型別就好，不用翻進去找 `throw`。%(ゝ∀・)b%

## `R` 那一欄，這個函數需要什麼

接著是 `R`，這欄會直接改變你怎麼寫測試。

先看原生寫法會出什麼事。

<br/>

某天你寫了一個註冊功能，很單純，把使用者存起來就好。

```ts
// register-user.ts
import { database } from './database'

export async function registerUser(user: User): Promise<User> {
  await database.save(user)
  return user
}
```

測試也很單純，把 `database` mock 掉就行了。

```ts
// register-user.test.ts
import { database } from './database'
import { registerUser } from './register-user'

vi.mock('./database')

it('註冊會把使用者存起來', async () => {
  const user = { id: 'u1', name: '鱈魚' }

  await registerUser(user)

  expect(database.save).toHaveBeenCalledWith(user)
})
```

一切美好，測試綠燈。%(´,,•ω•,,)%

<br/>

半年後，有人幫註冊流程加了一行寄歡迎信。

```ts
export async function registerUser(user: User): Promise<User> {
  await database.save(user)
  await emailService.sendWelcomeEmail(user.email) // [!code ++]
  return user
}
```

他改完跑了一次測試，綠燈，直接送出 PR。

沒人記得回去改那份半年前寫的測試，因為它跟這次改動看起來八竿子打不著。%(・∀・)%

<br/>

路人：「等等，`emailService` 沒 mock，測試不是應該壞掉嗎？%(´・ω・`)%」

鱈魚：「它又不影響 `registerUser` 的回傳值，斷言照樣通過啊。%( ˘•ω•˘ )%」

<br/>

於是測試維持綠燈，只是每跑一次，就真的往某個不存在的信箱寄一封歡迎信出去。

某天早上 Slack 跳出一封「歡迎加入」，收件人是 `test@example.com`，你才發現這件事已經持續三個月。%(;´༎ຶД༎ຶ`)%

<br/>

這裡沒有人偷懶。真正的問題是 `registerUser` 用到哪些東西**藏在函數內部**，型別上完全看不出來。

多加一個 import，型別系統一個字都不會抱怨，它本來就不管這件事。

### 換成 Effect

同一份邏輯，依賴改成跟環境拿。

這裡的 `Database` 就是前面「從最小的 Effect 開始長」定義過的那個服務，用 `Effect.Service` 生出來的 class。

```ts
import { Effect } from 'effect'
import { Database } from './database' // 前面用 Effect.Service 定義的那個

export function registerUser(user: User) {
  return Effect.gen(function* () {
    const database = yield* Database

    yield* database.save(user)

    return user
  })
}
// Effect<User, never, Database>
```

請注意 `Database` 是 import 進來的，但 import 的是**服務的名牌**，不是實作。

實作長什麼樣、連哪個資料庫，這個檔案從頭到尾都不知道，它只說「我需要一個叫 `Database` 的東西」。%( ˘•ω•˘ )%

半年後那位同事一樣加了寄信那行。

```ts
const emailService = yield* EmailService // [!code ++]

yield* database.save(user)
yield* emailService.sendWelcomeEmail(user.email) // [!code ++]
```

這兩行一加，`R` 那欄自動變成 `Database | EmailService`。

沒人維護這份清單，全是編譯器算出來的。%( •̀ ω •́ )✧%

### 這件事有個正式名稱

「函數不要自己 import 該用哪個實作，改成由外面塞進去」，這個做法叫做**依賴注入**（Dependency Injection，常縮寫成 DI）。

聽起來很唬人，其實你早就在用了。

```ts
// 自己去拿，這叫相依
function registerUser(user: User) {
  return database.save(user)
}

// 由外面給，這就是依賴注入
function registerUser(user: User, database: Database) {
  return database.save(user)
}
```

第二種寫法讓呼叫端決定要塞哪個 `database` 進去，正式環境塞真的，測試塞假的，函數本身完全不用改。%(´,,•ω•,,)%

<br/>

路人：「那多加一個參數不就好了，幹嘛搞這麼複雜？%(・∀・)%」

鱈魚：「兩三層還行，十層就哭了。%(´_ゝ`)%」

<br/>

參數傳遞最麻煩的部分在於它會**傳染**。

最底層的函數要用 `database`，呼叫它的人也得先拿到才有辦法往下傳，再上一層又是同樣狀況，一路傳到最外面。

中間那些函數根本用不到，卻得在簽章上多掛一個參數，只因為底下有人要用。%( ˘•ω•˘ )%

於是各家框架發明各種容器來代勞，Effect 則是把這份清單收進 `R` 欄位，要用的人自己跟環境拿，中間那些函數一個字都不用改。

### 那 Layer 又是什麼

前面一直說「跟環境拿」，那環境裡的東西是誰放進去的？答案是 **Layer**。

一句話講完，**Layer 就是服務的建造說明書**。%(´,,•ω•,,)%

```ts
// 這是「名牌」，只講有哪些能力，不講怎麼實作
class Database extends Context.Tag('Database')<Database, {
  readonly save: (user: User) => Effect.Effect<void>;
}>() {}

// 這是「說明書」，代表「Database 實際上長這樣」
const DatabaseLive = Layer.succeed(Database, {
  save: (user) => Effect.promise(() => db.insert(user)), // 真的寫進資料庫
})
```

這裡改用 `Context.Tag` 而不是 `Effect.Service`，是為了把名牌跟說明書拆成兩段看。兩者的差別等一下講。

`registerUser` 只認名牌，不認說明書。

執行之前用 `Effect.provide` 把說明書交出去，環境才算齊備。

```ts
registerUser(user).pipe(
  Effect.provide(DatabaseLive), // 把說明書塞進去
)
```

<br/>

之所以要分成兩個東西，是因為同一張名牌可以配好幾份說明書。

| 說明書 | 用在哪 |
|---|---|
| `DatabaseLive` | 正式環境，真的連資料庫 |
| `DatabaseTest` | 測試，回傳假資料 |
| `DatabaseMemory` | 本機開發，存在記憶體 |

`registerUser` 完全不知道自己拿到哪一份，也不需要知道。%( •̀ ω •́ )✧%

<br/>

那前面一直用的 `Effect.Service` 又是什麼？它是**把名牌跟說明書綁在一起**的懶人包，會自動生一份叫 `Default` 的說明書。

```ts
Effect.provide(Database.Default) // Effect.Service 自動生的那份
```

[官方文件](https://effect.website/docs/requirements-management/layers/#effectservice-vs-contexttag)的建議是這樣。

- **應用程式碼、實作只有一種** → 用 `Effect.Service`，少寫樣板
- **函式庫、或沒有哪個實作該當預設** → 用 `Context.Tag`，只發布名牌，讓使用者自己決定

<br/>

Layer 還能互相組合、互相依賴（`Database` 需要 `Config`，`Config` 需要環境變數），這部分展開會太長，先知道「它是說明書」就夠用了。

### 那所有套件都要包成服務嗎？

鱈魚：「來吧，讓我們把 lodash、dayjs、zod 通通包起來！%( •̀ ω •́ )✧%」

路人：「太麻煩了吧！%ლ（´口`ლ）%」

鱈魚：「開玩笑的啦，不用都包起來。%(´,,•ω•,,)%」

<br/>

判斷標準只有一句話，**你會不會想換掉它**。

| | 直接 import | 包成服務 |
|---|---|---|
| 例子 | `date-fns`、`zod`、`remeda` | 資料庫、外部 API、寄信、檔案 |
| 特徵 | 同樣輸入永遠同樣輸出 | 結果隨環境改變 |
| 測試時 | 不會想換掉 | 一定不想真的碰 |

純函數包成服務只是徒增樣板，測試也不會因此變好寫。%( ˘•ω•˘ )%

<br/>

而且要注意，「把資料庫包成服務」指的是包**你自己那層封裝**，不是幫 `drizzle` 寫一層 Layer。

```ts
import { drizzle } from 'drizzle-orm/node-postgres' // 照常 import，沒在客氣

export class Database extends Effect.Service<Database>()('Database', {
  effect: Effect.sync(() => {
    const db = drizzle(process.env.DATABASE_URL!)

    return {
      findUser: (id: string) => Effect.promise(() => db.query.users.findFirst(/* ... */)),
    }
  }),
}) {}
```

套件照常 import，被包起來的是 `findUser` 這個**你定義的介面**。外面只認得介面，不曉得底下是 drizzle、Prisma 還是一包假資料。%( •̀ ω •́ )✧%

<br/>

至於時間、亂數、環境變數這幾個常見的，Effect 已經內建，不用自己動手。

```ts
const now = yield* Clock.currentTimeMillis // 取代 Date.now()
const dice = yield* Random.nextIntBetween(1, 7) // 取代 Math.random()
const apiKey = yield* Config.string('API_KEY') // 取代 process.env
```

測試時搭配 `TestClock` 就能把時間快轉，不用真的等五秒，也就是前面那張守備範圍表裡 `vi.useFakeTimers` 那列。%(ゝ∀・)b%

<br/>

最後提醒一下，包越多 `R` 那欄就越長，每個呼叫端都要跟著 provide。

判斷不出來的時候先直接 import，等到「這裡測試很難寫」再抽出來也不遲。%(´,,•ω•,,)%

### 測試差異，眼見為憑

原生版本得靠 `vi.mock` 把整個模組換掉，前面已經看過會出什麼包。

Effect 版本改成**換一份說明書**，也就是換一顆 Layer。

```ts
// register-user.test.ts
import { expect, it } from '@effect/vitest'
import { Effect, Layer } from 'effect'
import { Database, registerUser } from './register-user'

const DatabaseTest = Layer.succeed(Database, {
  save: () => Effect.void,
})

it.effect('註冊會把使用者存起來', () =>
  Effect.gen(function* () {
    const user = { id: 'u1', name: '鱈魚' }
    const result = yield* registerUser(user)
    expect(result).toEqual(user)
  }).pipe(
    Effect.provide(DatabaseTest),
  ))
```

有人把 `EmailService` 加進 `registerUser` 那天，這段測試不用等執行，**編譯就先紅了**。

```text
Type 'Effect<void, never, EmailService>' is not assignable
to type 'Effect<void, never, TestServices>'.
Type 'EmailService' is not assignable to type 'TestServices'.
```

紅的是 IDE 裡那條波浪線，只要 CI 有跑型別檢查，這種 PR 就過不了。%( •̀ ω •́ )✧%

<br/>

路人：「所以 Effect 靠編譯器抓漏 mock，原生只能靠人記得改測試？%(´・ω・`)%」

鱈魚：「對，這就是最大的差別。原生版本那份清單就算寫進註解也沒人會去對，Effect 搬進型別系統，編譯器每次都幫你對一遍。%(ゝ∀・)b%」

## 回到兩年前

開頭說我棄坑過，看到這裡你應該有感覺了，該來說說當年的理由。

前面出現過的東西，剛好就是當時勸退我的五樣。

**一、型別錯誤訊息長到看不懂**

還記得前面那段「少 provide 一顆 Layer 就編譯失敗」嗎？文章裡我只貼了三行，實戰版通常是一大串巢狀泛型，`Effect` 裡面包 `Effect`，重點藏在第七行的某個角落。

新手看到那種訊息只有一個反應，關掉。%(°ㅂ°)%

**二、API 表面積大到會迷路**

這篇只用到 `Effect`、`Data`、`Layer`、`Context` 而已，實際上還有 `Schedule`、`Stream`、`Scope`、`Queue`、`Fiber`、`STM`、`Schema`⋯⋯每個底下又是幾十上百個函數。

想做一件很簡單的事，光是「該用哪個」就要翻很久。

<br/>

這點官方自己也認了。[Myths 頁面](https://www.effect.website/docs/v3/additional-resources/myths)有一條就叫「Effect is impossible to learn, there are so many functions and modules!」，開頭第一個字是 **True**。%(°ㅂ°)%

> 沒錯，完整的 Effect 生態系相當龐大，有些 module 包含上千個函數。但實際上你不需要全部學會才能開始產出，只要知道 10 到 20 個函數就可以安心開始用，剩下的慢慢認識就好。

後面還附了「常用的 15 個函數」跟「常用的 7 個 module」兩張清單，等於官方直接幫你畫重點。

這個回應很誠實，不過它解的是「要不要全部學會」，沒解到「當下這件事該用哪個函數」。%( ˘•ω•˘ )%

**三、命名來自函數式傳統，猜不到**

`flatMap`、`tap`、`zipRight`、`acquireRelease`、`provide`。知道的人覺得精準，不知道的人根本不曉得要去哪裡找。

前面 `Effect.either` 那招也是，你不會憑直覺想到「把失敗轉成值」要用這個字。

**四、同一件事有好幾種寫法**

`pipe` 還是 `gen`？`Context.Tag` 還是 `Effect.Service`？`Layer.succeed` 還是 `Layer.effect`？選擇障礙直接發作。%(´・ω・`)%

**五、卡住了 Google 不到**

這點最致命。社群還小，Stack Overflow 幾乎沒有答案，遇到問題只能翻文件或去 Discord 問。

對於習慣「卡住就查、查到就繼續」的開發節奏，這等於整條路被切斷。

<br/>

五點加起來就是所謂的心智負擔。概念本身不算難，難的是**每寫一行都要付出額外的查詢成本**，而那個成本高到讓人懷疑人生。%( ´•̥̥̥ ω •̥̥̥` )%

### 這五點在 AI 面前都不太成立了

一條一條對回去看，會發現它們有個共通點，全都是**查資料的成本**。%(ﾉ>ω<)ﾉ%

| 當年的門檻 | 現在怎麼解 |
|---|---|
| 型別訊息看不懂 | 貼給它，直接告訴你少了什麼 |
| 不知道該用哪個函數 | 描述你要做的事，它給你名字 |
| 命名猜不到 | 同上，不用先知道叫什麼才找得到 |
| Google 不到 | 它讀過文件跟原始碼 |
| 選擇障礙 | 把專案慣例講清楚，它會跟著走 |

而查資料剛好是 AI 最擅長的事。

當年那個「用不起」的結論，前提已經不成立了。%( •̀ ω •́ )✧%

### 但 AI 會生出過期的語法

先別急著開心，直接叫 AI 寫 Effect 會踩到一個大雷，**它很容易生出過期的語法**。

原因是 Effect 這幾年改動很大。

- `Effect.gen` 的 adapter 寫法（`function* (_) { yield* _(...) }`）從 2024 年 4 月起就不需要了，但它至今仍然能編譯能執行，所以編譯器不會攔你，而訓練資料裡又到處都是
- 現在 npm 上 `latest` 是 v3，v4 已經進 RC，兩份文件並存
- v4 又把 `Context.Tag`、`Effect.Tag`、`Effect.Service` 通通合併成 `Context.Service`

三個世代的 API 混在一起，AI 想不搞混也難。%(´_ゝ`)%

<br/>

### 官方給的三樣工具

好消息是官方正在處理這件事，有三樣東西可以直接用。

**一、官方 skills**

Effect 官方開了 [skills repo](https://github.com/Effect-TS/skills)，一行指令裝好。

```bash
npx skills add Effect-TS/skills
```

裡面兩個 skill，`effect-ts` 負責日常開發，`effect-v3-to-v4` 專門處理升級。

有趣的是 `effect-ts` 本身**幾乎沒有內容**，它只做一件事，叫 agent 去讀 `node_modules/effect/AGENTS.md`。

**二、套件裡自帶的 AI 文件**

這招很聰明。Effect v4 直接把 `AGENTS.md`（17KB）跟 `ai-docs/`（近 150KB、五十幾個 `.ts` 範例）**包進 npm 套件裡**。

```text
node_modules/effect/
├── AGENTS.md
├── CLAUDE.md
└── ai-docs/
```

文件永遠跟你裝的版本綁在一起，不會出現「文件講 v4、專案跑 v3」的慘案。%( •̀ ω •́ )✧%

要注意 v3 沒有這些檔案，這是 v4 才有的待遇。

**三、`@effect/language-service`**

這個我覺得最實用，它是 TypeScript 的 LSP plugin，專門抓 Effect 的寫法問題。

```bash
npm install -D @effect/language-service
```

裡面幾條規則根本是為 AI 生成的程式碼量身訂做。

| 規則 | 抓什麼 |
|---|---|
| `effectGenUsesAdapter` | 用了 2024 年就淘汰的 adapter 寫法 |
| `missingStarInYieldEffectGen` | 前面講過的，`yield` 忘記加星號 |
| `floatingEffect` | 建立了 Effect 卻沒有人執行它 |
| `outdatedApi` | 用到 v4 已經改名或移除的 API |

還記得前面那個「忘記寫星號，資料就人間蒸發」嗎？`missingStarInYieldEffectGen` 就是專門守這關的。%(ゝ∀・)b%

<br/>

另外官方部落格有篇 [The One Weird Git Trick That Makes Coding Agents More Effect-ive](https://effect.website/blog/the-one-weird-git-trick-that-makes-coding-agents-more-effect-ive/)，主張用 `git subtree` 把 Effect 原始碼放進專案，讓 agent 直接讀原始碼。

文中那句話蠻有意思的，agent 拿到「寫給人看的文件」時，效率明顯比較差。%(´,,•ω•,,)%

<br/>

路人：「所以現在有 AI 就可以無腦上了？%(・∀・)%」

鱈魚：「當然沒這麼好康，有兩件事 AI 幫不了你。%( ˘•ω•˘ )%」

<br/>

**第一，你還是得看得懂它寫了什麼。**

AI 產出的 Effect 程式碼你 review 不了，那就只是把技術債外包出去，出事還是你要扛。

**第二，心智模型還是要自己建立。**

`Effect<A, E, R>` 那三欄代表什麼、為什麼要惰性、Layer 怎麼組合，這些理解不會因為 AI 會寫就自動長進你腦袋裡。

AI 砍掉的是**打字跟查資料的成本**，理解的成本它砍不掉。%( ˘•ω•˘ )%

<br/>

不過話說回來，查資料跟猜 API 的成本一旦消失，當年那個「用不起」的結論就得重算一次。

所以我又回鍋了。%(´,,•ω•,,)%

## 總結 🐟

- `Promise<User>` 只講了成功會拿到什麼，`Effect<A, E, R>` 把「會怎麼失敗」跟「需要什麼」也寫進型別，後兩欄由編譯器算，不會像 JSDoc 那樣過期
- Effect 寫好了不會馬上跑，還沒跑的描述才加得上重試、逾時、併發，它也才管得動錯誤、依賴、資源、測試時鐘一整包
- `yield*` 就是 Effect 版的 `await`，每 `yield*` 一次編譯器就順手更新 `E` 跟 `R`，代價是它只能寫在 generator 本體，`forEach` 的 callback 裡放不了
- 那份依賴清單沒人手動維護，測試也就從「換掉整個模組」變成「換一顆 Layer」，少換一顆直接編譯失敗
- 別把所有套件都包成服務，判斷標準只有「你會不會想換掉它」，純函數直接 import 就好
